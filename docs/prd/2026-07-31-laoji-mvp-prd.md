# 老己 MVP 产品方案冻结稿

- 版本：MVP v0.1
- 状态：被替代，仅保留历史
- 日期：2026-07-31
- 目标读者：产品、设计、开发、测试和后续 agent

> 本文档已被 `docs/prd/laoji-mvp-prototype-prd.md` 替代。UI 和开发应使用新原型 PRD，本文仅用于追溯早期范围收敛过程。

## 1. 一句话定义

老己是一个以聊天为主入口、以统一书架为内容入口的个人自我提升助理。MVP 先验证一条闭环：

```text
微信读书 / 本地书籍
        -> 划线、笔记和来源整理
        -> AI 生成并确认 PPT 大纲
        -> 导出可编辑 PPTX
```

## 2. MVP 目标

### 2.1 必须验证

- 用户能注册并进入产品，不被配置表单阻塞。
- 用户能把微信读书同步书和本地导入书放在一个统一书架中管理。
- 用户能按书名和作者查找已有书籍。
- 用户能区分微信读书同步内容与本地正文阅读能力。
- 用户能保存私有补充、标签和 PPT 备注。
- 用户能选择一本书的章节、划线和笔记生成 PPT 大纲，并在确认后导出可编辑 PPTX。

### 2.2 不在 MVP

- 养生食谱、专注力管理等后续技能；
- 微信登录、手机号登录、邀请码；
- 多人协作、社区、分享、付费和订阅；
- 微信读书全站书目搜索；
- 微信读书全文在老己内阅读；
- 通用的非读书 PPT 创作；
- 拼音搜索、全文搜索和笔记搜索；
- 复杂阅读统计、社交排行和推荐系统。

## 3. 核心用户与入口

首批用户是需要持续学习和输出的职场知识工作者。产品以聊天保留“老己”的助理感，但阅读和 PPT 需要独立工作区承载，不能把正文阅读塞进聊天气泡。

### 3.1 MVP 顶层导航

```text
+----------------+
| 对话           |
| 读书           |
| 设置           |
+----------------+
```

- `对话`：全局入口。MVP 只调度读书和 PPT 能力。
- `读书`：统一书架和书籍工作区。
- `设置`：AI 服务、微信读书连接和账户安全。

PPT 不作为顶层导航。它在书籍工作区中有共同入口，底层能力和作品实体保持独立。

### 3.2 注册后的默认状态

- 注册方式：邮箱 + 密码。
- 注册后直接进入对话首页。
- 不展示 AI 配置卡或微信读书连接卡。
- 顶部可以显示轻量的 `AI 未配置` 状态。
- 第一次执行 AI 操作时就地引导配置并保留上下文。
- 第一次进入 `读书 -> 微信读书同步` 时引导填写微信读书 Skill Key。
- 未配置 AI 不影响阅读、导入、划线和笔记。
- 未连接微信读书不影响本地导入。

## 4. 统一书架

### 4.1 书架内容

微信读书同步书和用户导入的 EPUB/PDF 都展示在一个书架中。每张书籍卡片显示：封面、书名、作者、来源标签和来源对应的进度/状态。

```text
+----------------------------------------------------------+
| [搜索书名或作者...] [全部 v] [排序 v]       [导入书籍]   |
+----------------------------------------------------------+
| [封面]          [封面]          [封面]                  |
| 原子习惯        深度工作        被讨厌的勇气              |
| 微信读书        我的导入        微信读书                  |
| 进度 42%        阅读进度 18%    12 条划线                |
+----------------------------------------------------------+
```

同名书不自动合并。微信读书版本和本地导入版本保留为独立书籍记录。

### 4.2 书架搜索

- 搜索范围：当前书架中的书籍元数据。
- 匹配字段：书名、作者；任意一个字段匹配即可。
- 来源筛选：全部、微信读书、我的导入。
- 无结果：显示清除搜索、导入书籍、连接微信读书等相关动作。
- MVP 不搜索正文、划线、笔记或微信读书全站书目。

### 4.3 书籍工作区

书籍工作区使用统一外壳，但根据来源能力展示不同功能。

```text
统一：书架、书籍详情外壳、笔记、PPT

微信读书：书籍概览、进度、个人同步内容、公开内容、PPT
本地导入：正文、目录、精准划线、个人笔记、PPT、移除
```

微信读书同步书不提供老己站内全文阅读。界面不能展示会让用户误以为存在正文阅读的空按钮。

## 5. 两类来源的内容边界

### 5.1 微信读书同步

通过用户填写的微信读书 Skill Key，由服务端同步：

- 书架和书籍元数据；
- 阅读进度和阅读统计（以接口实际提供字段为准）；
- 用户自己的划线、想法、章节点评和书评；
- 热门划线；
- 他人公开想法；
- 公开书评。

原始同步内容只读，不回写微信读书。同步能力、字段和公开使用边界必须通过阶段 0 真实接口和合规验证。

### 5.2 本地导入

- 支持 EPUB 和文字型 PDF。
- EPUB 支持正文阅读、目录、精准划线和备注。
- 文字型 PDF 必须支持跨页连续选择，并保存稳定位置锚点。
- 扫描版、加密版和文本层损坏 PDF 不承诺精准划线，并明确提示不支持。
- 本地书移除后进入 30 天回收站，图书文件和本地笔记一起删除；已生成 PPT 保留。

## 6. 笔记模型

笔记分为来源内容层和用户笔记层：

```text
来源内容（只读）
  原文 / 划线 / 来源 / 作者 / 位置
          |
          v
用户笔记（私有、可编辑）
  老己补充 / 标签 / PPT 备注 / 加入 PPT
```

### 6.1 挂载层级

- 书籍级：整本书理解、行动计划和复盘；
- 章节级：章节总结和结构化笔记；
- 划线级：附着在原文片段上的解释、联想和行动。

### 6.2 公开内容规则

- 用户自己的划线和想法：默认可用于 AI 整理和 PPT。
- 热门划线、他人公开想法、公开书评：默认只读，不自动进入 AI 或 PPT。
- 用户明确选择公开内容后，作为带来源的参考素材使用。
- 外部内容不得在 PPT 或 AI 输出中伪装成用户原创观点。

## 7. PPT 共同入口与流程

微信读书和本地导入从同一个 PPT 制作器进入。进入时自动带入当前书籍和上下文。

```text
选择一本书
      |
      v
选择素材：当前章节 / 多章节 / 指定划线 / 指定笔记
      |
      v
填写用途、受众、页数倾向和 PPT 备注
      |
      v
生成结构化 PPT 大纲
      |
      v
用户编辑并确认大纲
      |
      v
选择模板和配图策略
      |
      v
HTML 预览与修改
      |
      v
导出可编辑 PPTX
```

MVP 默认一次处理一本书，允许选择多个章节和笔记；暂不支持跨书籍、跨来源混合生成。

大纲至少包含：页面标题、核心观点、来源引用、素材类型、配图意图和用户可编辑文案。具体生成器候选为 `PptxGenJS`，`mav-slide-craft-skill` 只作为版式和视觉规范参考，不直接作为线上 PPTX 引擎。

PPT 作品是独立产物，保留来源引用、生成状态、预览、下载和再次打开能力。书籍只是第一种来源，未来可接入聊天或其他技能输出。

## 8. AI 配置

### 8.1 用户体验

- 用户选择一个供应商：DeepSeek、Kimi 或 GLM。
- 用户只填写一把当前生效的 AI API Key。
- 用户不填写模型名；系统自动检测文本、图片理解和图片生成能力。
- 用户可以跳过配置。
- 设置页始终保留 AI 服务入口。

### 8.2 路由规则

- 文本对话、读书整理和 PPT 大纲：当前供应商的文本模型。
- 图片理解：当前供应商支持时启用。
- PPT 配图：优先当前供应商的图片能力；不支持时使用老己平台统一图片服务。
- 一把 Key 不跨供应商调用。
- 三家供应商的能力必须分别验证，不用一家供应商的结果代表全部。

## 9. 微信读书配置

- 微信读书 Skill Key 与 AI API Key 分开配置。
- 设置页提供独立的微信读书连接、验证、重试和清除凭证入口。
- 注册后不主动展示连接卡。
- 进入微信读书同步书架或点击同步时显示未连接状态和填写入口。
- 不做一键扫码微信登录。
- API Key 只经服务端使用，前端不保存明文。

## 10. MVP 成功标准

阶段 0 通过后，阶段 1 至少满足：

1. 新用户可以注册并进入对话首页，不被 Key 配置阻塞。
2. 用户可以连接微信读书并同步书籍/可用内容，或导入 EPUB/文字型 PDF。
3. 两类书在统一书架展示，可按书名和作者搜索。
4. 用户能在本地文字型 PDF 上完成跨页精准划线；不支持的 PDF 会明确提示。
5. 用户能保存书籍级、章节级和划线级私有笔记。
6. 用户能选择一本书的素材生成 PPT 大纲，编辑确认后导出可编辑 PPTX。
7. AI 未配置、微信读书未连接、同步失败、生成失败和导入失败都有可恢复状态。
8. 核心流程在桌面端和手机端均可完成。

## 11. 阶段 0 硬阻塞

- 微信读书真实接口连通性、字段完整性和商业/合规边界未验证前，不宣称可公开发布。
- PDF 跨页精准选区未通过真实文字型 PDF 样本验证前，不进入完整阅读器开发。
- PPTX 可编辑性未在实际演示软件中验证前，不承诺“可编辑 PPTX”。
- 三家 AI 供应商的能力和权限未逐家验证前，不把三家都标为已支持。

## 12. 明确默认

为避免继续阻塞方案，以下低风险细节由实现阶段按最小实现原则确定：

- 书架默认按最近访问或最近更新排序；
- 搜索先做书名/作者文本匹配，不做拼音和全文索引；
- PPT 默认使用少量固定模板，模板数量后续由视觉方案确定；
- AI 生成任务和微信读书同步任务使用可重试的异步状态；
- 具体数据库、对象存储和生产图片服务在阶段 0 根据 Netlify 和中国大陆访问/合规约束选择。
