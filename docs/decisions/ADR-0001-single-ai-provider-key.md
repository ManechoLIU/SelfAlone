# ADR-0001: 每个用户只配置一个当前生效的 AI 供应商和 API Key

- 状态：已接受
- 日期：2026-07-31
- 范围：AI 配置、模型路由、PPT 配图

## 背景

老己需要调用大模型完成聊天、读书整理和 PPT 生成。首版只支持 DeepSeek、Kimi、GLM 三类国产大模型。让用户同时维护多家供应商的 API Key 会增加上手成本，也不符合首版的使用预期。

“多模态”不能直接等同于“同一个模型同时负责文字和图片生成”：模型可能支持图片理解，却不支持图片输出；图片生成也可能使用独立的模型和接口。

## 决策

1. 用户在老己中选择一个 AI 供应商：DeepSeek、Kimi 或 GLM。
2. 用户只填写一把该供应商的 API Key，作为当前生效配置。
3. 用户不需要填写具体模型名。后端通过供应商适配器验证 Key，并检测文本、图片理解和图片生成能力，自动选择可用模型。
4. 老己内部按能力路由，而不是假设存在一个统一的“文字+生图模型”：
   - 文本对话、读书分析、PPT 大纲使用文本模型。
   - 图片输入理解使用视觉模型（如果当前供应商和 Key 支持）。
   - PPT 配图优先使用当前供应商的图片生成能力。
5. 当前供应商不具备图片生成能力或当前 Key 没有权限时，由老己平台统一提供图片生成兜底服务，用户不需要再填写第二把 Key。
6. 老己不使用一把供应商 Key 跨供应商调用另一家服务。要切换供应商时，用户替换当前配置；首版不维护多套同时生效配置。

## 用户体验

配置入口只展示一个 AI 配置表单：供应商选择、API Key、验证并启用。具体模型名称和路由细节不暴露给普通用户；设置页可以显示当前已启用的能力状态。

用户可以跳过配置。未配置时仍可阅读、导入书籍、划线、添加备注和标签；智能总结、PPT 大纲、PPT 生成等 AI 能力提示配置 Key 后启用。

## 后果

### 正面

- 降低注册后的配置负担。
- 将供应商差异隔离在后端适配器中，后续可以增加供应商而不改变用户的核心流程。
- 用户不必理解模型名称、文本模型与图片模型的关系。

### 代价与风险

- 图片生成兜底服务由老己承担成本、额度和合规责任，需要配额、超时和降级策略。
- 三家供应商的模型、权限和接口能力可能变化，不能只依赖静态配置。
- 开发前必须用真实测试账号验证各供应商的文本、图片理解和图片生成权限，并确认 API Key 的保存、撤销和错误处理流程。

## 不采用的方案

- 同时要求用户填写三家 API Key：配置复杂，超出首版需要。
- 用一把 Key 自动跨 DeepSeek、Kimi、GLM 调用：供应商凭证不通用，技术上不可成立。
- 强行要求一个模型同时输出文字和图片：会把供应商能力差异和图片服务成本隐藏成不可靠的假设。
