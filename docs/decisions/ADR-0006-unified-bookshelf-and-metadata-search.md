# ADR-0006: 统一书架入口，并提供书名/作者元数据搜索

- 状态：已接受
- 日期：2026-07-31
- 范围：读书入口、书籍卡片、书籍来源、书架搜索

## 背景

老己同时管理微信读书同步书和用户导入的 EPUB/PDF。分别建立两个完全独立的书架会割裂用户的查找习惯；但把两类书籍合并成同一个数据来源，又会掩盖全文阅读、同步和划线能力的差异。

用户熟悉微信读书的书架式入口，希望通过书籍封面快速识别和查找内容。书架中的书籍数量增加后，需要按书名和作者搜索。

## 决策

1. `读书`提供一个统一书架，微信读书同步书和本地导入书都在其中展示。
2. 每张书籍卡片只显示封面、书名、作者和必要进度，不以图形、角标或标签区分来源；来源筛选器承担来源区分，书籍详情页以元信息行明确显示“微信读书同步”或“本地导入（EPUB/PDF）”。
3. 同名书不自动合并。微信读书版本和本地导入版本保留为两条独立书籍记录，避免来源数据、权限和笔记错误混合。
4. 点击书籍进入统一的书籍工作区外壳；工作区根据来源能力展示不同的阅读、同步、划线和笔记功能。MVP 不提供本地书移除或回收站。
5. PPT 和笔记是两类来源都可以使用的共同能力，但不因此合并两类书籍的原始数据。
6. 书架提供书名/作者搜索，并支持来源筛选：`全部`、`微信读书`、`我的导入`。
7. MVP 的搜索范围仅为用户已经在书架中的书籍元数据，不搜索微信读书全站书目，不搜索正文、划线或笔记内容。
8. 搜索结果继续使用统一书籍卡片；无结果时提供清除搜索、导入书籍或连接微信读书等与当前状态相关的动作。

## 书架示意

```text
+----------------------------------------------------------+
| [搜索书名或作者...] [全部|微信读书|我的导入] [导入书籍]|
+----------------------------------------------------------+
| [封面]          [封面]          [封面]                  |
| 原子习惯        深度工作        被讨厌的勇气              |
| 进度 42%        18 条笔记       12 条划线                |
+----------------------------------------------------------+
```

## 搜索规则

- 输入同时匹配书名和作者；
- 书名或作者任意一个字段匹配即可展示；
- 搜索作用于当前筛选后的书架集合；
- 搜索框为空时恢复当前来源筛选下的全部书籍；
- 无结果时不自动发起外部书目搜索；
- MVP 不承诺拼音搜索、全文搜索、笔记搜索或推荐排序。

## 能力差异

```text
统一：书架、封面卡片、书籍工作区外壳、笔记、PPT

微信读书：同步书架、进度、我的笔记、书友笔记；不提供老己站内全文阅读
我的导入：全文阅读、目录、精准划线和老己笔记
```

## 设计参考边界

可以借鉴微信读书的书架交互模式、封面网格和信息层级，帮助用户形成熟悉的操作预期；不直接复制其品牌样式、图标、视觉资产或特殊交互细节。

## 后续扩展

如果未来确实需要搜索更多内容，分别增加不同职责的入口：

- 书架搜索：查找已有书籍；
- 内容搜索：查找划线、备注和 PPT 素材；
- 书目搜索：查找并添加外部书籍。

三者不在 MVP 中合并成一个模糊的全局搜索框。
