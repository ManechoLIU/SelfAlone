# 老己领域术语表

本表定义产品方案中的核心术语。后续文档、接口和代码命名应优先遵循这些定义。

| 术语 | 定义 | 边界 |
| --- | --- | --- |
| 老己 | 面向个人学习、生活和娱乐的自我提升助理产品；MVP 以读书工作台为中心。 | 不是首版就覆盖所有生活技能的泛用平台。 |
| MVP | 老己第一版可验证的最小产品范围。 | 重点验证“阅读/笔记 -> AI 整理 -> 可编辑 PPTX”的闭环。 |
| AI 供应商 | 用户选择并提供 API Key 的模型服务方，目前为 DeepSeek、Kimi 或 GLM。 | 一把 Key 只对应一个供应商。 |
| 当前生效 Key | 用户当前启用的唯一一套 AI 供应商凭证。 | 首版不维护多套同时生效的模型凭证。 |
| 能力检测 | 后端验证 API Key，并检测文本、图片理解、图片生成等能力的过程。 | 不是让用户手动填写模型名称。 |
| 微信读书 Skill Key | 用户用于授权老己通过微信读书 Skill/API 获取其微信读书数据的凭证。 | 与 AI API Key 完全不同；只用于微信读书连接和同步。 |
| 微信读书同步书 | 通过微信读书 Skill/API 获取的书籍及其同步数据。 | 与本地导入书籍分开管理；原始同步内容只读，不回写微信读书。 |
| 本地导入书 | 用户上传的 EPUB 或文字型 PDF。 | 不自动与微信读书同步书合并；MVP 暂不支持移除。 |
| 本地书目录 | 本地书阅读器中按章节定位内容的统一导航。 | EPUB 使用书内目录；PDF 优先读取内置大纲，其次自动提取章节标题，无法可靠识别时才降级为页码/缩略页导航。 |
| 统一书架 | 展示微信读书同步书和本地导入书的共同入口。 | 统一的是查找入口和书籍工作区外壳，不代表来源数据或阅读能力合并。 |
| 书架搜索 | 在当前书架集合中按书名或作者查找已有书籍。 | MVP 不搜索全文、笔记或微信读书全站书目。 |
| 划线 | 用户在本地书正文中创建的阅读高亮及其位置锚点。 | 可取消高亮，但不修改本地原文，也不删除已关联的老己笔记；文字型 PDF 必须支持精准跨页划线，扫描版 PDF 不承诺该能力。 |
| 老己笔记 | 用户在老己中新增、可编辑和删除的私有笔记；本地书的同名区域还汇总本地划线和用户笔记。 | 微信读书的“老己笔记”只显示新增笔记；本地书可按“全部 / 划线 / 笔记”过滤。记录有原文引用时显示原文与笔记，没有原文引用时只显示笔记正文。编辑或删除只作用于用户笔记，不修改同步内容、引用原文、本地划线或书籍。 |
| 引用型老己笔记 | 关联一条同步内容、本地原文或本地划线的用户私有笔记。 | 引用原文和来源只读；同一原文可关联多条笔记，用户只编辑或删除自己的笔记正文。 |
| 独立型老己笔记 | 不依赖具体原文的用户私有笔记。 | 界面只显示笔记正文，不要求用户选择书籍级或章节级分类；可编辑和删除。 |
| 来源内容 | 从微信读书同步的数据或本地书籍中读取的原文及其来源信息。 | 原始内容只读，不被老己笔记或本地划线覆盖。 |
| 原文条目 | 微信读书“我的笔记”或“书友笔记”中的一条独立原文、划线、想法或评价。 | 默认只读；激活后可复制或创建引用型老己笔记，一次只激活一条。 |
| 笔记关联元数据 | 系统内部保存的书籍、章节或划线位置，用于定位原文、排序和 PPT 来源追溯。 | 不作为用户可见分类、筛选或填写项；不回写外部来源。 |
| PPT 备注 | 用户对 PPT 结构、重点或表达方式提出的私有要求。 | 是用户笔记层的一部分，不等于来源原文，也不替代 PPT 对话中的范围选择。 |
| 我的笔记 | 微信读书同步的用户自己的划线和想法。 | 原始同步内容只读；可在 PPT 专属对话中按章节、全部笔记或指定笔记范围使用。 |
| 书友笔记 | 微信读书同步的热门划线和高赞书评。 | 首版最多展示各 20 条；默认只读且不进入 PPT，只有在 PPT 专属对话明确“加入书友观点”后才作为带来源参考。 |
| 加入书友观点 | 在微信读书书籍的 PPT 专属对话中，将书友笔记作为范围补充。 | 不是逐条素材勾选；大纲和成品必须保留作者与来源。 |
| PPT 制作意图 | 用户在普通对话中明确提出制作、生成或整理读书 PPT。 | 与书籍页面“制作 PPT”进入同一流程；必须绑定一本书，原消息需要保留。 |
| SlideSpec | 描述 PPT 页面结构、文案、素材、布局和来源引用的结构化中间数据。 | HTML 预览和最终 PPTX 应共同使用它；具体字段仍待方案定稿。 |
| AI 配图兜底 | 当前供应商不能生图或权限不足时，由老己平台提供的统一图片生成服务。 | 用户不需要为此额外填写 API Key；成本和配额由平台承担。 |
