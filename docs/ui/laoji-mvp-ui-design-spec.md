# 老己 MVP UI 设计规范

- 版本：UI Spec v1.1
- 状态：已接受
- 日期：2026-08-04
- 适用端：响应式 Web，覆盖桌面、平板和手机
- 视觉方向：青瓷书斋
- 目标读者：UI 设计师、产品、前端、测试和后续 agent

## 0. 文档职责与优先级

本文件是老己 MVP 的唯一视觉与组件事实来源，负责颜色、字体、布局、尺寸、组件表现、动效和视觉验收。产品能力、页面职责、字段、流程和失败后行为只以 `../prd/laoji-mvp-prototype-prd.md` 为准，本文件不重新定义产品行为。

文档优先级如下：

1. 行为、状态和文案：原型 PRD；
2. 视觉、组件和响应式表现：本 UI 设计规范；
3. 决策背景与取舍：`../decisions/ADR-0010-qingci-study-ui-direction.md`。

发生冲突时按职责归属处理，不在实现中自行折中。调整产品行为先更新 PRD；调整具体视觉参数只更新本文件；改变已接受方向时新增或替代 ADR。

## 1. 设计方向

### 1.1 设计主张

“青瓷书斋”以现代知识工作台为骨架，以克制的东方阅读气质建立识别。界面首先要安静、清晰和适合长时间使用，其次才是装饰表达。

关键词：`清新`、`书卷气`、`克制`、`可信赖`、`工作导向`。

### 1.2 品牌记忆点

- 使用竖向“己”字题签作为主要品牌标记，可出现在侧栏品牌区、加载状态和空状态的低频位置。
- 活字印刷字模网格可作为侧栏或页头暗纹，最大不透明度为 4%，不得覆盖正文或表单。
- 楷体只用于“老己”品牌字和极少量题签，不用于导航、按钮、表单或长正文。
- 宋体用于阅读正文、原文引用和需要书卷感的内容标题；操作界面仍使用现代黑体。
- 不使用大面积水墨、仿古宣纸纹理、云纹边框、金色描边或循环漂浮装饰。
- 不为装饰新增“近读”等无真实分组意义的文字；结构标签必须对应实际内容或状态。

### 1.3 视觉层级原则

1. 当前任务与正文优先；品牌元素退后。
2. 书架以封面和书名为第一层，作者与进度为第二层，来源为第三层。
3. 来源在书架中弱化，在笔记、公开参考和 PPT 引用中强化，保证归属可追溯。
4. AI 配置状态常驻但轻量，不使用大卡片或强制向导。
5. 卡片只包裹书籍、笔记、作品等重复实体；页面结构通过留白和细线组织。

## 2. 设计基础

### 2.1 颜色

| Token | 名称 | 色值 | 用途 |
| --- | --- | --- | --- |
| `color-bg` | 瓷白 | `#F5F8F6` | 页面主背景、阅读器外围 |
| `color-surface` | 雾釉 | `#EDF4F1` | 侧栏、次级面板、选中弱背景 |
| `color-primary` | 青瓷 | `#0D6A57` | 主按钮、当前导航、焦点与品牌题签 |
| `color-ink` | 墨青 | `#21312D` | 主文字、标题 |
| `color-muted` | 竹影灰 | `#71807A` | 作者、进度和说明文字 |
| `color-border` | 釉边 | `#CBD8D3` | 分隔线、输入框和面板边界 |
| `color-warning` | 淡赭 | `#B18B56` | AI 未配置、需要注意但不阻断的状态 |
| `color-danger` | 朱砂 | `#A34F43` | 删除、不可恢复和阻断错误 |

- 大面积背景仅使用瓷白和雾釉；青瓷色的大面积填充只用于主按钮和小型选中区域。
- 来源类型不依赖不同颜色区分，必须同时显示文字或图标。
- 正文、控件和状态文字满足 WCAG AA；任何错误或选择状态不能只靠颜色表达。

### 2.2 字体

| 角色 | 首选 | 回退 | 使用范围 |
| --- | --- | --- | --- |
| UI 黑体 | `Source Han Sans SC` | `PingFang SC`, `Microsoft YaHei`, sans-serif | 导航、按钮、表单、列表和状态 |
| 阅读宋体 | `Source Han Serif SC` | `Songti SC`, `STSong`, serif | EPUB/PDF 文本层、原文引用、长阅读 |
| 品牌楷体 | `Kaiti SC` | `STKaiti`, serif | “老己”品牌字与“己”字题签 |
| 数据与英文 | `Inter` | system-ui, sans-serif | 页码、进度、文件类型和英文辅助信息 |

- UI 正文：14–16px，行高 1.55–1.7。
- 阅读正文：桌面 18px/1.85，手机 17px/1.8；用户可在后续版本增加字号调节，MVP 不预置复杂排版面板。
- 页面标题：24px/1.3；区块标题：18–20px/1.4；控件标签：13–14px。
- 来源与作者不得小于 11px；弱化依赖颜色和位置，不通过不可读的小字号实现。
- 字重只使用 400、500、600；长正文默认 400。

### 2.3 间距、圆角与阴影

- 基础间距单位为 4px；常用间距为 8、12、16、20、24、32、40px。
- 输入框、按钮和分段控件圆角 8–10px；书籍封面上角 4px、下角 8px；抽屉和主要弹窗 16px。
- 页面区块不使用阴影；书籍封面使用单层柔和阴影 `0 8px 18px rgba(28,57,49,0.12)`。
- 弹窗可使用 `0 20px 60px rgba(18,66,55,0.16)`；不叠加多层阴影或发光效果。
- 分隔线统一 1px 釉边色；结构不能同时使用边框、阴影和背景三种手段重复强调。

### 2.4 图标

- 使用统一的 1.5px 线性图标；默认 18px，紧凑工具栏 16px，主导航 20px。
- 图标按钮必须有可访问名称；手机端高频动作优先图标加文字。
- 来源、警告、成功和删除状态同时使用图标与文本，不使用彩色图标单独传达含义。

## 3. 全局布局与响应式

### 3.1 布局区间

| 区间 | 宽度 | 全局导航 | 内容表现 |
| --- | --- | --- | --- |
| 大桌面 | `>= 1440px` | 176px 固定侧栏 | 多栏工作区、书架 7 列 |
| 桌面 | `1200–1439px` | 168px 固定侧栏 | 多栏工作区、书架 6 列 |
| 平板横向 | `1024–1199px` | 72px 收窄侧栏 | 目录/笔记可折叠、书架 5 列 |
| 平板纵向 | `768–1023px` | 64px 收窄侧栏 | 主内容优先、书架 4 列 |
| 手机 | `<= 767px` | 固定底部导航 | 单主视区、书架 2 列 |

- 桌面主内容水平内边距 28–32px；平板 20–24px；手机 16px。
- 手机底部导航避开系统安全区；页面内容不能被固定导航遮挡。
- 阅读器目录与笔记面板在平板可折叠，在手机使用单层抽屉或底部面板。

### 3.2 全局页头与 AI 状态

- 桌面端所有已登录主页面在页头右侧显示 AI 状态弱提示，位于页面标题与主要操作之间。
- 状态文案为：`AI 未配置 · 去配置`、`DeepSeek 已启用`、`Kimi 已启用`、`GLM 已启用` 或 `AI 凭证失效 · 重新配置`。
- 未配置使用淡赭圆点和 12px 文字，使用虚线下划线提示可点击；已启用使用竹影灰，不与主操作竞争；失效使用朱砂文字但不变成大卡片。
- AI 状态弱提示整体可点击并提供明确焦点态；进入 `SET-01` 及返回上下文的行为以原型 PRD 为准。
- 手机端在页面标题栏保留紧凑状态，宽度不足时显示 `AI 未配置` 或供应商名称，完整说明通过点击进入。

## 4. 统一书架

### 4.1 网格密度

- 桌面封面宽度限定在 132–148px，比例固定为 5:7，不因容器变宽而无限放大。
- 大桌面 7 列、桌面 6 列、平板横向 5 列、平板纵向 4 列、手机 2 列。
- 桌面横向间距 16–20px，纵向间距 24–28px；手机横向 12px、纵向 20px。
- 在高度不低于 800px 的常见桌面视口中，书架正常状态首屏至少展示两行书籍；页头与筛选区总高度不得挤压书架只剩一行。
- 结果不足时保持左对齐，不拉伸封面填满整行。

### 4.2 封面清晰度与兜底

- 封面容器使用 5:7 比例；图片使用等比裁切或完整适配，不拉伸、不变形。
- 目标显示宽度为 132–148 CSS px；优先请求宽度不低于 296px 的 2× 图片。
- 可用图片宽度低于 216px 时视为清晰度不足，不放大到标准卡片尺寸，改用文字封面。
- 文字封面根据稳定的书籍标识选择青瓷、竹影、赭石、靛青等低饱和底色；显示书名最多四行、作者一行，不伪造出版社或装饰图片。
- 微信读书真实封面尺寸需在阶段 0 验证；验证结果只影响图片与文字封面的使用比例，不改变网格尺寸。

### 4.3 卡片信息层级

1. 封面；
2. 书名，最多两行；
3. 作者，单行截断；
4. 来源与进度，同一行低对比文字。

- 来源显示为 `微信读书`、`本地 EPUB` 或 `本地 PDF`，不使用实色胶囊标签。
- 来源文字使用 11px 竹影灰的弱化层级；进度可稍深，但不能比作者更抢眼。
- 来源筛选仍使用清晰的分段控件，因为它承担真实过滤功能，不能随卡片来源一起弱化。
- 同名不同来源仍为独立卡片；来源必须在不打开详情时可辨认。

## 5. 组件规范

### 5.1 导航与按钮

- 当前导航使用雾釉加深背景、青瓷文字和图标；不使用高饱和整块侧栏选中状态。
- 一个操作组只有一个青瓷实色主按钮；次按钮使用白色或透明背景加釉边色边框；文字按钮用于取消、返回和弱操作。
- 提交中保持按钮尺寸不变，替换局部图标/文字并禁用重复提交。
- 破坏性按钮默认不使用实色朱砂，只有最终确认弹窗中的主破坏动作使用朱砂实色。

### 5.2 表单与筛选

- 输入框默认高度 44px，边框为釉边色；聚焦使用 2px 青瓷外环，不通过阴影模拟发光。
- 错误在字段下方显示具体原因并保留合法输入；错误边框、图标和文字共同表达。
- 分段控件只用于 2–4 个互斥选项；选中项使用白色表面与轻微单层阴影。
- 搜索框与来源筛选可同排时，搜索占剩余空间；手机端垂直排列。

### 5.3 笔记、来源与引用

- 来源原文使用阅读宋体和左侧 3px 青瓷浅色标线；用户“老己补充”使用 UI 黑体和雾釉背景。
- 公开参考在卡片页头显示作者、来源和“公开参考”文本标识；选中进入 PPT 后增加明确的已选状态。
- 来源信息在笔记和 PPT 大纲中属于必要信息，不沿用书架卡片的极弱层级。
- 删除私有补充与删除来源内容必须使用不同文案和确认范围。

### 5.4 面板、弹窗与反馈

- 桌面笔记优先使用右侧面板，手机使用底部面板；一次只显示一个主要层级。
- 短暂成功使用 3–4 秒 toast；需要用户决定的失败使用就地错误或对话框，不用 toast 承载长说明。
- 空状态包含原因、一个主动作和最多一个次动作；不使用营销插画填充大面积空间。
- 异步长任务显示阶段和已完成数量，不展示未经计算的剩余时间。

### 5.5 缺省、加载与错误模板

- 初次加载使用与最终内容同尺寸的骨架，不能先闪现空状态再加载数据。
- 真实空数据使用居中的短说明、一个主动作和最多一个次动作；没有合理动作的空回收站不强行放按钮。
- 搜索或筛选为空保留搜索词、筛选器和页面结构，缺省说明出现在结果区域，不替换成整页欢迎界面。
- 请求失败使用原内容区域的就地错误；有缓存时保留现有数据并使用非阻塞错误条，无缓存时显示重试。
- 空状态、错误状态和无权限/不支持状态使用不同标题与图标，不共享含糊的“暂无数据”。
- “己”字题签可用于真实空数据的低频品牌点缀，不用于网络错误、权限错误或阻断失败。

## 6. 阅读与 PPT 工作区

### 6.1 阅读器

- EPUB 正文桌面最大行宽 680px；PDF 页面按工具栏可用宽度居中，不让笔记面板覆盖页面。
- 文本选区工具条尺寸稳定，顺序统一为：`划线`、`添加备注`、`加入 PPT`。
- 默认划线使用青瓷色 18% 透明背景，不改变文字颜色；键盘焦点和选中不能混淆。
- 目录与笔记收起后正文平滑扩展，但阅读行宽仍受上限约束。
- PDF 加载、渲染失败、无可渲染页面和可阅读但不可精准划线使用四种独立版式；失败时保留书名、页码区域和返回书架入口。

### 6.2 PPT 流程

- 素材、要求、大纲和预览使用连续的步骤标题，但不添加可跳过“大纲确认”的进度导航。
- 大纲桌面采用页面列表、当前页编辑、来源三栏；手机逐页编辑，来源通过单层面板查看。
- 模板缩略图展示真实内容密度，不以装饰性渐变代替模板差异。
- 生成中只突出一个当前阶段；失败保留大纲、模板和已完成页，重试按钮保持主操作层级。
- 大纲页头使用轻量文字显示“保存中”“已保存”或“保存失败”；保存失败为可操作状态，不能只用 toast。
- 本书无历史作品时使用 PPT 空作品模板；无素材时使用与书籍来源能力匹配的素材准备出口，具体文案和动作以原型 PRD 为准。

## 7. 动效、状态与可访问性

- 控件状态过渡 120–160ms；抽屉、面板和页面内布局变化 200–240ms；统一使用 ease-out。
- 不使用循环环境动画；题签仅可在首次加载时做一次不超过 240ms 的淡入或位移。
- `prefers-reduced-motion` 下取消非必要位移和缩放，仅保留即时状态切换。
- 所有交互提供可见键盘焦点；触控目标不小于 44×44px。
- 正文、状态、错误和禁用态在明暗对比与文字说明上均可辨认。
- 长书名、长作者、长笔记、系统字体回退和 200% 浏览器缩放均纳入验收。
- 加载、空、失败、禁用、成功和连接失效状态不得导致布局跳动或丢失用户输入。

## 8. 设计稿与验收

设计稿页面和状态清单以原型 PRD 第 5 节和第 9.2 节为准。设计文件按以下顺序组织：

1. `00 Foundations`：颜色、字体、间距、图标与题签；
2. `01 Components`：导航、按钮、表单、书籍卡片、笔记、来源、弹窗与任务状态；
3. `02 Desktop`：15 个页面主状态与规定的关键状态；
4. `03 Mobile`：15 个页面主状态与规定的关键状态；
5. `04 Prototype`：注册、导入/同步、阅读笔记、PPT、配置返回上下文五条可点击流程。

每次交付前检查：

- 原型 PRD 的页面、主要出口和失败状态是否全部保留；
- UI 文件中是否出现无产品意义的分组文字或新功能入口；
- 1440×900 和 1200×800 书架是否至少展示两行，封面是否保持清晰；
- 微信读书与本地导入来源是否弱化但仍可辨认；
- 桌面主页面是否都有 AI 状态弱提示；
- 首次无任何数据、真实空书架、来源筛选为空、搜索无结果、无笔记、无素材、无作品和空回收站是否使用了正确且不同的缺省模板；
- 所有列表是否区分初次加载、真实空数据、搜索/筛选为空、请求失败和正常数据；
- APP 最近任务与书籍 PPT 状态是否一致，并能恢复生成中或失败任务；
- 国风元素是否限制在题签、暗纹、色彩和阅读排版，没有遮挡或降低效率；
- 手机触控目标、键盘弹出、长文本和底部安全区是否通过验收；
- 颜色、尺寸和组件状态是否只引用本规范，没有在其他协作文档中维护第二套参数。
