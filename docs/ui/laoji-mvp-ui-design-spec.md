# 老己 MVP UI 设计规范

- 版本：UI Spec v1.6
- 状态：已接受
- 日期：2026-08-09
- 适用端：响应式 Web，覆盖桌面、平板和手机
- 视觉方向：青瓷书斋
- 目标读者：UI 设计师、产品、前端、测试和后续 agent

### 0.1 设计自由度与约束边界

本规范的职责是传达产品体验目标、视觉方向和验收底线，不是替 Open Design 预先画死页面。除明确标注的关键体验底线外，页面布局、信息编排、组件形态、交互手势、图标选择、间距和具体尺寸均由 Open Design 根据主流 Web/移动端习惯自主设计；参考参数可以调整，设计师应以可用性、可读性、响应式适配和视觉品质为判断标准。

必须保留的体验底线只有：

- 微信读书与本地书详情使用同一产品外壳，并按来源显示对应标签和内容区域；
- 微信读书原文条目激活后提供复制、写笔记；本地书选中文字后提供复制、划线、写笔记；工具条贴近当前内容，不固定在页面底部；
- 老己笔记可新建、编辑和删除，引用原文保持只读；
- 微信读书设置存在可发现的配置入口，并覆盖保存、测试、失败重试和清除凭证；
- PDF 优先展示提取出的章节目录，无法可靠识别时才降级为页码或缩略页导航；
- 所有方案满足响应式、键盘可用、触控目标足够大、状态可理解且不丢失用户输入。

下文中的“建议、优先、参考”不是强制实现；只有“必须、不得、底线”用于验收。Open Design 可以提交不同的布局或组件方案，只要不违反上述底线并能说明用户体验收益。

### 0.2 2026-08-07 UI 实现对齐参考

本节覆盖旧设计稿中与当前响应式原型不一致的视觉与组件规则。

**全局视觉与 Shell**

- 已登录页保持青瓷书斋的克制、安静和有层次的整体气质；页面容器、导航形态和区块组织由 Open Design 选择，不把每个页面区块包装成互相嵌套的装饰卡片。
- 品牌标识、头像、导航和次级内容入口应在桌面与手机都容易发现；具体位置、尺寸和承载方式由 Open Design 设计。

**认证页面**

- 登录和注册体现水墨窗景与安静表单的视觉方向，但分栏、卡片或背景处理不作固定要求；手机端必须自然适配单手操作。
- 密码显示、提交、切换和找回密码等功能必须清晰可达，图标和控件样式由 Open Design 选择，并满足键盘焦点与触控可用性。

**对话与上下文**

- 对话需要同时照顾消息阅读、输入和书籍上下文；桌面与手机可以使用侧栏、抽屉、分栏或其他主流模式，但不能让上下文遮挡主要任务。
- 首次状态以真实操作为中心，品牌题签仅作为低频点缀，不使用营销插画。

**书架卡片**

- 卡片不放置底部操作按钮，封面和卡片主体作为统一点击区域。
- MVP 不显示本地书删除按钮，也不设计回收站入口。
- 书架卡片不显示本地或微信读书来源的图形、文字标签或角标；来源筛选器承担区分来源的职责，书籍详情页显示清晰的来源元信息。
- 书架卡片优先保证封面、书名和作者的清晰层级；长文本、封面比例和网格密度由 Open Design 根据真实内容和视口验证。

**个人资料与设置**

- 设置首页使用“个人资料 / 已连接的服务 / 存储、安全与退出”三个完整区段，不在侧栏展开二级设置导航。
- 头像编辑使用大尺寸圆形预览、选择图片和恢复默认两个操作；格式、尺寸限制保持为独立帮助文本行，错误紧邻编辑器。
- 服务状态使用轻量状态文字 + “管理”按钮；退出和删除账户必须在视觉和危险等级上区分。
- “已连接的服务”区段至少包含 AI 服务和微信读书两行；微信读书行显示未配置、已配置、已连接或已失效状态，并提供“管理”入口进入独立配置页。
- 设置首页要让个人资料、已连接服务和危险操作易于扫描；采用分组列表、面板或卡片均可，但不要制造层层嵌套的设置容器。
- 微信读书配置页必须包含标题、用途说明、API Key、状态、保存、测试、最近同步和凭证管理；表单与操作的具体组件组合、排列和响应式换行由 Open Design 决定。
- 删除账户独立为危险区，视觉上与密码、退出登录分开；不出现回收站或本地书删除说明。

**数据状态与反馈**

- 所有列表和工作区统一提供加载骨架、真实空、筛选空、错误和正常内容；连接失效、不支持和权限问题使用独立状态文案。
- 就地错误保留原数据和用户输入；toast 只用于短暂成功，不承载需要决策的失败。
- 长任务进度使用稳定区域和填充进度条；失败状态保留已完成数量和恢复动作，禁止只有空轮廓。

**阅读器、笔记和 PPT**

- 微信读书和本地 EPUB/PDF 必须使用同一套书籍详情外壳：同一页头、封面信息、元信息层级、标签栏和内容容器。微信读书显示“我的笔记 / 书友笔记 / 老己笔记 / 读书 PPT”；本地书显示“阅读 / 老己笔记 / 读书 PPT”。来源只决定区域可见性，不得设计成两种详情页。
- 统一笔记卡片通过字体、背景和来源栏区分来源原文、老己笔记和书友笔记，不用高饱和标签。
- PPT 范围、需求、大纲和预览应让用户感到流程连续；书籍选择、编辑、来源查看和模板选择的组织方式由 Open Design 选择。
- 生成、失败、完成和未确认状态应尽量保持上下文和操作位置稳定，避免页面跳动或丢失输入。

### 0.3 2026-08-08 视觉审查关键底线

- 高级感来自真实内容、文字层级、留白、对齐和直接操控；避免用纯色占位封面、重阴影、巨大标题、装饰性纹样或成片圆角卡片伪造质感。
- 微信读书每条原文默认不显示操作按钮，点击、轻触或键盘激活后才显示贴近该条的 `复制 / 写笔记` 工具条。本地 EPUB/PDF 选中文字后显示 `复制 / 划线 / 写笔记`；两类工具条都不得固定在页面底部，并需避开浏览器边缘和手机安全区。
- 图标应来自成熟图标体系，表达清晰并保持风格一致；具体图标库、笔画和尺寸由 Open Design 选择。
- 手机端必须有清晰可发现的主导航和返回路径，具体采用底部导航、顶部导航或其他主流模式由 Open Design 决定。
- 对话必须支持新建和切换独立会话；桌面与手机的会话入口形态由 Open Design 根据空间和可达性设计。
- 普通对话识别到 PPT 制作意图后，必须保留原消息并进入与书籍按钮相同的 PPT 流程；书籍绑定和任务状态需要让用户容易理解，具体承载方式由 Open Design 决定。

**交互与可访问性**

- 弹窗标题可聚焦，关闭后焦点返回真实触发元素；直接调用弹窗也必须遵循同一规则。
- 标签页和分段控件具有清晰选中态；标签页支持键盘方向键、Home、End，并跳过禁用项。
- 所有图标按钮具有可访问名称；状态变化不能降低文字与背景的对比度。

## 0. 文档职责与优先级

本文件是老己 MVP 的视觉方向、体验原则和关键底线来源；它不限制 Open Design 对页面布局、组件形态和具体交互的发挥。产品能力、页面职责、字段、流程和失败后行为只以 `../prd/laoji-mvp-prototype-prd.md` 为准，本文件不重新定义产品行为。

文档优先级如下：

1. 行为、状态和文案：原型 PRD；
2. 视觉方向、体验原则和关键底线：本 UI 设计规范；具体布局与组件方案以 Open Design 的可用性设计为准；
3. 决策背景与取舍：`../decisions/ADR-0010-qingci-study-ui-direction.md`。

发生冲突时按职责归属处理，不在实现中自行折中。调整产品行为先更新 PRD；调整视觉方向或关键底线更新本文件；具体页面方案无需为了匹配参考参数而牺牲用户体验。

## 1. 设计方向

### 1.1 设计主张

“青瓷书斋”以现代知识工作台为骨架，以克制的东方阅读气质建立识别。界面首先要安静、清晰和适合长时间使用，其次才是装饰表达。

关键词：`清新`、`书卷气`、`克制`、`可信赖`、`工作导向`。

### 1.2 品牌记忆点

- 使用竖向“己”字题签作为主要品牌标记，可出现在侧栏品牌区、加载状态和空状态的低频位置。
- 活字印刷字模网格可作为侧栏或页头暗纹，最大不透明度为 4%，不得覆盖正文或表单。
- 楷体只用于“老己”品牌字和极少量题签，不用于导航、按钮、表单或长正文。
- 宋体用于阅读正文、原文引用和需要书卷感的内容标题；操作界面仍使用现代黑体。
- 不使用大面积水墨、仿古宣纸纹理、云纹边框、金色描边或循环漂浮装饰。
- 不为装饰新增“近读”等无真实分组意义的文字；结构标签必须对应实际内容或状态。

### 1.3 视觉层级原则

1. 当前任务与正文优先；品牌元素退后。
2. 书架以真实封面和书名为第一层，作者与进度为第二层；不为来源增加独立视觉层级。
3. 来源不在书架卡片内重复显示；在书籍详情元信息、笔记和 PPT 引用中明确显示，保证归属可追溯。
4. AI 配置状态常驻但轻量，不使用大卡片或强制向导。
5. 卡片只包裹书籍、笔记、作品等重复实体；页面结构通过留白和细线组织。

## 2. 设计基础

本节参数是青瓷书斋的起始建议，不是页面实现的硬性尺寸表。Open Design 可以根据字体、内容密度、设备和可访问性调整数值，只需保持清晰层级、足够触控区域和整体克制感。

### 2.1 颜色

| Token | 名称 | 色值 | 用途 |
| --- | --- | --- | --- |
| `color-bg` | 瓷白 | `#F5F8F6` | 页面主背景、阅读器外围 |
| `color-surface` | 雾釉 | `#EDF4F1` | 侧栏、次级面板、选中弱背景 |
| `color-primary` | 青瓷 | `#0D6A57` | 主按钮、当前导航、焦点与品牌题签 |
| `color-ink` | 墨青 | `#21312D` | 主文字、标题 |
| `color-muted` | 竹影灰 | `#71807A` | 作者、进度和说明文字 |
| `color-border` | 釉边 | `#CBD8D3` | 分隔线、输入框和面板边界 |
| `color-warning` | 淡赭 | `#B18B56` | AI 未配置、需要注意但不阻断的状态 |
| `color-danger` | 朱砂 | `#A34F43` | 删除、不可恢复和阻断错误 |

- 大面积背景仅使用瓷白和雾釉；青瓷色的大面积填充只用于主按钮和小型选中区域。
- 需要显式显示来源的控件不得只依赖颜色，必须同时使用文字或图标；书架卡片遵循 4.3 节的来源例外规则。
- 正文、控件和状态文字满足 WCAG AA；任何错误或选择状态不能只靠颜色表达。

### 2.2 字体

| 角色 | 首选 | 回退 | 使用范围 |
| --- | --- | --- | --- |
| UI 黑体 | `Source Han Sans SC` | `PingFang SC`, `Microsoft YaHei`, sans-serif | 导航、按钮、表单、列表和状态 |
| 阅读宋体 | `Source Han Serif SC` | `Songti SC`, `STSong`, serif | EPUB/PDF 文本层、原文引用、长阅读 |
| 品牌楷体 | `Kaiti SC` | `STKaiti`, serif | “老己”品牌字与“己”字题签 |
| 数据与英文 | `Inter` | system-ui, sans-serif | 页码、进度、文件类型和英文辅助信息 |

- UI 正文：14–16px，行高 1.55–1.7。
- 阅读正文：桌面 18px/1.85，手机 17px/1.8；用户可在后续版本增加字号调节，MVP 不预置复杂排版面板。
- 页面标题：24px/1.3；区块标题：18–20px/1.4；控件标签：13–14px。
- 来源与作者不得小于 11px；弱化依赖颜色和位置，不通过不可读的小字号实现。
- 字重只使用 400、500、600；长正文默认 400。

### 2.3 间距、圆角与阴影

- 基础间距单位为 4px；常用间距为 8、12、16、20、24、32、40px。
- 圆角、阴影和分隔线以轻量、克制、不堆叠为原则；具体数值由 Open Design 根据组件语义和平台习惯选择。
- 页面区块不要依赖多层阴影或发光制造层级，重复实体可以使用适度边界或背景区分。

### 2.4 图标

- 使用同一套成熟图标体系，保持笔画、光学重量和语义一致；具体图标库与尺寸由 Open Design 选择。
- 图标按钮必须有可访问名称；手机端高频动作应让用户能理解其含义，图标、文字或组合形式由 Open Design 选择。
- 警告、成功和删除状态同时使用图标与文本，不使用彩色图标单独传达含义。

## 3. 全局布局与响应式

### 3.1 布局区间（参考）

| 区间 | 宽度 | 全局导航 | 内容表现 |
| --- | --- | --- | --- |
| 大桌面 | `>= 1440px` | 宽屏导航与多栏工作区 | 适合快速扫描的书架密度 |
| 桌面 | `1200–1439px` | 完整导航与工作区 | 适合比较的书架密度 |
| 平板横向 | `1024–1199px` | 可收窄导航 | 目录/笔记可折叠 |
| 平板纵向 | `768–1023px` | 主内容优先 | 次级内容可切换 |
| 手机 | `<= 767px` | 适合单手操作的导航 | 单主视区 |

- 桌面、平板和手机都要保留合理留白，并确保主要内容不被导航或系统安全区遮挡；具体内边距和导航尺寸由 Open Design 通过真实视口验证。
- 移动端需要有适合单手操作的主导航和次级内容入口；底部导航、顶部导航、抽屉或面板均可采用。
- 阅读器目录与笔记面板应能在小屏幕上收起或切换，避免与正文争夺空间。

### 3.2 全局 AI 状态

- 所有已登录主页面都要提供可发现但不抢占主任务的 AI 状态弱提示；桌面、平板和手机的具体位置及承载方式由 Open Design 决定。
- 状态文案为：`AI 未配置 · 去配置`、`DeepSeek 已启用`、`Kimi 已启用`、`GLM 已启用` 或 `AI 凭证失效 · 重新配置`。
- 未配置、已启用和凭证失效必须有可辨认的文字与状态差异，不能只依赖颜色；具体字体、图标、颜色和点击提示由 Open Design 设计，但不得变成大面积配置卡。
- AI 状态弱提示整体可点击并提供明确焦点态；进入 `SET-01` 及返回上下文的行为以原型 PRD 为准。
- 小屏幕仍需保留可发现的紧凑状态入口；空间不足时可以缩短文案或调整承载方式，但点击后应能查看完整状态并进入设置。

### 3.3 统一书籍详情外壳

- 微信读书和本地书共用同一书籍详情组件：返回书架、封面、书名、作者、来源/进度元信息、主要操作、标签栏和内容容器的层级与体验保持一致，具体摆放和尺寸由 Open Design 决定。
- 来源自适应只改变标签数量和内容：微信读书为“我的笔记 / 书友笔记 / 老己笔记 / 读书 PPT”，本地书为“阅读 / 老己笔记 / 读书 PPT”。不得用不同背景、卡片结构或页面标题制造两个产品。
- 微信读书四个标签始终保留；“书友笔记”没有内容时使用真实空状态，不隐藏标签。微信读书和本地书页头都提供“制作 PPT”主操作，进入同一绑定书籍的 PPT 对话。
- 本地“阅读”内容区嵌入目录、阅读区和当前笔记；本地“老己笔记”内容区同时展示划线和用户笔记，记录有原文引用时显示原文与笔记，没有原文引用时只显示笔记正文，内部过滤为“全部 / 划线 / 笔记”。微信读书“老己笔记”只展示用户新增笔记，不显示同步的我的笔记或书友笔记。
- 微信读书在小屏幕上仍使用完整标签名称，不缩写为“我的/书友/老己/PPT”；横向滚动、折叠或其他溢出方案由 Open Design 决定，但不能降低可发现性。
- 切换标签时应保持用户对当前书籍和返回路径的认知；桌面或手机如何承载页头、标签和内容区由 Open Design 决定，不得让阅读器进入后失去返回详情的路径。

## 4. 统一书架

### 4.1 网格密度（参考）

- 书籍封面保持稳定比例和清晰边界，网格密度以快速扫描和真实内容可读为准；列数、卡片宽度和间距由 Open Design 根据视口验证。
- 书架首屏应优先展示足够内容，同时保留搜索、筛选和主要入口；结果不足时保持自然排列，不拉伸封面填满空白。

### 4.2 封面清晰度与兜底（参考）

- 封面容器使用 5:7 比例；图片使用等比裁切或完整适配，不拉伸、不变形。
- 图片清晰度应与实际显示尺寸匹配，避免低清图片被放大；具体阈值由实现和素材验证决定。
- 文字封面根据稳定的书籍标识选择青瓷、竹影、赭石、靛青等低饱和底色；显示书名最多四行、作者一行，不伪造出版社或装饰图片。
- 高保真设计稿使用真实书封或经过统一排版的文字封面；不得用无文字、无图像信息的纯色矩形代替书封。
- 微信读书真实封面尺寸需在阶段 0 验证；验证结果只影响图片与文字封面的使用比例，不改变网格尺寸。

### 4.3 卡片信息层级

1. 封面；
2. 书名，单行省略；
3. 作者，单行省略；
4. 可选进度信息，低对比显示。

- 进度信息使用低对比的弱化层级，不能比作者更抢眼；字号和颜色由 Open Design 在可读性底线内决定。
- 来源筛选仍使用清晰的分段控件，因为它承担真实过滤功能，不能随卡片来源一起弱化。
- 同名不同来源仍为独立卡片；卡片不以来源差异作视觉装饰。进入详情页后，以元信息行显示“微信读书同步”或“本地导入（EPUB/PDF）”。

## 5. 组件规范

### 5.1 导航与按钮（参考）

- 当前导航需要有克制、明确的选中态；颜色、背景、图标和指示方式由 Open Design 选择，避免高饱和或喧宾夺主。
- 操作组应有清晰的主次层级，主按钮、次按钮和文字操作的具体视觉形式由 Open Design 选择。
- 提交中应禁用重复提交并保持上下文稳定；按钮是否替换为进度图标或文案由设计决定。
- 删除账户等破坏性操作需要明显区分并二次确认，具体危险色和组件形态由 Open Design 选择。

### 5.2 表单与筛选（参考）

- 输入框和筛选控件应有足够触控面积、清晰边界和明确焦点态；高度、边框和焦点表现由 Open Design 选择。
- 错误在字段下方显示具体原因并保留合法输入；错误边框、图标和文字共同表达。
- 分段控件、标签、下拉菜单或其他筛选模式均可使用，选择应符合选项数量和用户预期；桌面与手机的排列由 Open Design 选择。

### 5.3 笔记、来源与引用

- 来源原文与用户“老己笔记”需要通过字体、背景、边界或其他一致手段清晰区分；具体视觉表达由 Open Design 决定。
- 书友笔记在卡片页头显示作者、来源和“书友笔记”文本标识；用户仅能在 PPT 专属会话中明确选择“加入书友观点”，选中后在大纲和作品中保留来源。
- 我的笔记和书友笔记是多条独立原文项；条目默认态只展示内容与来源信息，不在每条底部常驻操作区。激活态只为当前条目显示上下文工具条，其他条目布局保持稳定。
- 点击“写笔记”后打开老己笔记编辑器；如果有引用原文则完整显示且只读，同一原文的多条老己笔记作为独立记录展示。
- “老己笔记”内容区页头提供“新建笔记”；新建入口打开不带原文引用的独立笔记编辑器，保存后只显示笔记正文。引用原文、来源和位置由系统保留但不让用户选择或管理书籍级、章节级、划线级分类。
- 本地书“老己笔记”是统一详情内的全书汇总区，使用“全部 / 划线 / 笔记”查看内容。筛选方式由 Open Design 选择，但不代表用户需要维护书籍级、章节级或划线级笔记分类；阅读器内只需提供当前选区或当前位置相关内容，不承担全书汇总。
- 划线列表按章节和原文位置排列；老己笔记列表按最近更新排列。列表项提供“回到原文”，定位后短暂强调目标，不改变用户保存的划线样式。
- 每条用户创建的老己笔记都提供“编辑”和“删除”。操作入口应在桌面和手机都容易发现，并不得挤压笔记正文或引用原文；悬停、聚焦、更多菜单或其他主流承载方式由 Open Design 选择。
- 编辑使用与新建一致的笔记面板，只允许修改用户笔记内容；引用原文、来源、作者和位置保持只读。保存失败时保留未提交内容，并提供重试。
- 删除使用明确标题“删除这条老己笔记？”和说明“引用原文、划线和书籍不会被删除”；确认后只移除当前用户笔记。删除失败时条目保持原位并显示就地重试。
- 来源信息在笔记和 PPT 大纲中属于必要信息，不沿用书架卡片的极弱层级。
- 微信读书同步内容和本地原文不显示编辑或删除入口。本地划线不显示“编辑/删除笔记”，但可通过阅读操作“取消划线”移除高亮；取消划线不删除已关联的老己笔记，也不与“删除老己笔记”混用。

### 5.4 面板、弹窗与反馈

- 笔记编辑和上下文内容应使用用户熟悉的面板、弹窗或内联编辑方式；一次不要堆叠多个主要层级。
- 短暂成功可以使用 toast 或就地反馈；需要用户决定的失败使用就地错误或对话框，不用短暂提示承载长说明。
- 空状态包含原因、一个主动作和最多一个次动作；不使用营销插画填充大面积空间。
- 异步长任务显示阶段和已完成数量，不展示未经计算的剩余时间。

### 5.5 阅读选区工具条

- 微信读书原文条目激活后必须提供 `复制`、`写笔记`；本地 EPUB/PDF 文本选区后必须提供 `复制`、`划线`、`写笔记`。操作顺序和具体控件形态由 Open Design 选择。
- 工具条锚定当前原文项、文本选区或已有划线，优先显示在内容上方；空间不足、靠近页头或会遮挡系统区域时翻转到下方。它不是常驻底栏，也不应被内容滚动后留在旧位置。
- 点击或轻触本地已有划线时，工具条显示 `复制`、`写笔记`；`取消划线`放入次级菜单并要求明确操作目标。
- 工具条应紧凑、不遮挡内容并满足触控可用性；点击“写笔记”后进入清晰的笔记编辑状态，具体使用底部面板、侧栏、弹窗或内联编辑由 Open Design 选择。
- 同一页面一次只显示一个上下文工具条；点击外部、滚动到锚点不可见、按 `Esc` 或切换标签页时收起。键盘用户可聚焦原文项并用 `Enter`/`Space` 打开工具条。
- 工具条出现和收起应短促、可打断并尊重减少动效设置；具体时长和过渡形式由 Open Design 选择，避免弹跳、重阴影或全屏遮罩干扰阅读。

### 5.6 设置分组与危险操作（参考）

- 设置页应便于扫描和区分普通操作与危险操作；分组列表、面板或卡片均可，只要避免层层嵌套和视觉噪音。
- 标题、说明和操作的层级应适合当前视口，避免手机端出现桌面级大标题或过多空白。
- 修改密码、退出登录和删除账户应有清晰的风险层级与确认反馈，具体承载方式由 Open Design 选择。

### 5.7 缺省、加载与错误模板

- 初次加载使用与最终内容同尺寸的骨架，不能先闪现空状态再加载数据。
- 真实空数据使用居中的短说明、一个主动作和最多一个次动作；没有合理动作时不强行放按钮。
- 搜索或筛选为空保留搜索词、筛选器和页面结构，缺省说明出现在结果区域，不替换成整页欢迎界面。
- 请求失败使用原内容区域的就地错误；有缓存时保留现有数据并使用非阻塞错误条，无缓存时显示重试。
- 空状态、错误状态和无权限/不支持状态使用不同标题与图标，不共享含糊的“暂无数据”。
- “己”字题签可用于真实空数据的低频品牌点缀，不用于网络错误、权限错误或阻断失败。

## 6. 阅读与 PPT 工作区

### 6.1 阅读器

- EPUB/PDF 的“阅读”区域共用目录、阅读区、笔记和选区能力，并嵌入统一书籍详情外壳；具体区域比例和布局由 Open Design 设计。
- 本地书标签“阅读 / 老己笔记 / 读书 PPT”在桌面和手机保持同一命名；手机可使用等宽标签或可横向滚动标签栏，但不得缩写成含义不明的单字。
- EPUB 正文和 PDF 页面都应保持舒适阅读宽度，笔记面板不得遮挡正文；页码和缩放应容易发现，具体位置不作固定要求。
- 本地书章节导航统一命名为“目录”，不得把 PDF 默认设计为独立的“缩略页栏”。PDF 目录优先显示文件内置书签或自动提取的章节标题，并使用与 EPUB 相同的层级、选中和定位体验；目录位置由 Open Design 决定。
- PDF 未识别到可靠章节时，在目录面板内显示简短说明并切换为页码/缩略页导航；缩略页是降级导航，不是 PDF 阅读器的默认视觉特征。
- 文本选区和已有划线工具条遵循 5.5 节，贴近当前内容浮动；不得固定在页面底部。
- 默认划线应与正文、键盘焦点和当前选区清晰区分；颜色和透明度由 Open Design 选择。
- 目录与笔记收起后正文应自然扩展，同时保持舒适阅读宽度。
- PDF 加载、渲染失败、无可渲染页面和可阅读但不可精准划线使用四种独立版式；失败时保留书名、页码区域和返回书架入口。

### 6.2 PPT 流程

- 范围、需求、大纲和预览应让用户理解当前进度并能回退修改；是否使用步骤标题、进度导航或对话式状态由 Open Design 选择，不得跳过产品要求的确认环节。
- PPT 需求卡至少包含主题/标题、用途、分享对象和页数；主题/标题允许用户直接修改，范围组件按书籍来源能力显示章节、笔记类型和书友观点选项。
- 大纲需要同时支持页面内容编辑和来源追溯；桌面与手机的分栏、列表、面板或逐页编辑方式由 Open Design 选择。
- 模板缩略图展示真实内容密度，不以装饰性渐变代替模板差异。
- 生成中只突出一个当前阶段；失败保留大纲、模板和已完成页，重试按钮保持主操作层级。
- 大纲页头使用轻量文字显示“保存中”“已保存”或“保存失败”；保存失败为可操作状态，不能只用 toast。
- 本书无历史作品时使用 PPT 空作品模板；无素材时使用与书籍来源能力匹配的素材准备出口，具体文案和动作以原型 PRD 为准。

## 7. 动效、状态与可访问性

- 动效应短促、克制、可打断，并服务于状态反馈和空间关系；具体时长、缓动和是否使用动效由 Open Design 选择。
- 不使用循环环境动画或会干扰阅读的装饰动画；`prefers-reduced-motion` 下取消非必要动效。
- 所有交互提供可见键盘焦点；触控目标不小于 44×44px。
- 正文、状态、错误和禁用态在明暗对比与文字说明上均可辨认。
- 长书名、长作者、长笔记、系统字体回退和 200% 浏览器缩放均纳入验收。
- 加载、空、失败、禁用、成功和连接失效状态不得导致布局跳动或丢失用户输入。

## 8. 设计稿与验收

设计稿页面和状态清单以原型 PRD 第 5 节和第 9.2 节为准。设计文件按以下顺序组织：

1. `00 Foundations`：颜色、字体、间距、图标与题签；
2. `01 Components`：导航、按钮、表单、书籍卡片、笔记、来源、弹窗与任务状态；
3. `02 Desktop`：15 个页面主状态与规定的关键状态；
4. `03 Mobile`：15 个页面主状态与规定的关键状态；
5. `04 Prototype`：注册、导入/同步、阅读笔记、PPT、配置返回上下文五条可点击流程。

每次交付前检查：

- 原型 PRD 的页面、主要出口和失败状态是否全部保留；
- UI 文件中是否出现无产品意义的分组文字或新功能入口；
- 1440×900 和 1200×800 书架是否至少展示两行，封面是否保持清晰；
- 书架是否只保留封面、书名、作者和必要进度，来源是否仅由筛选器和书籍详情元信息呈现；
- 桌面主页面是否都有 AI 状态弱提示；
- 首次无任何数据、真实空书架、来源筛选为空、搜索无结果、无老己笔记、书友笔记获取失败和无读书 PPT 是否使用了正确且不同的缺省模板；
- 所有列表是否区分初次加载、真实空数据、搜索/筛选为空、请求失败和正常数据；
- APP 最近任务与书籍 PPT 状态是否一致，并能恢复生成中或失败任务；
- 普通对话提出制作 PPT 时是否保留原消息、就地选择或继承一本书，并进入与书籍按钮相同的 PPT 流程；
- 国风元素是否限制在题签、暗纹、色彩和阅读排版，没有遮挡或降低效率；
- 手机触控目标、键盘弹出、长文本和底部安全区是否通过验收；
- 微信读书多条原文是否默认隐藏操作、单条激活后才显示复制/写笔记；EPUB/PDF 选区与已有划线工具条是否贴近内容、能上下避让且不固定在底部；写笔记后是否进入清晰、可返回且不丢失内容的编辑状态；
- 微信读书与本地书详情是否共用同一页头、标签栏和内容容器，仅按来源显示区域；本地“老己笔记”是否同时包含划线和用户笔记，并按是否有原文显示内容，支持全部/划线/笔记过滤与回到原文；微信读书老己笔记是否只显示新增笔记；
- 用户创建的老己笔记是否可编辑和删除；编辑时引用原文是否保持只读；删除是否只影响当前笔记，并在失败时保留条目与重试入口；
- EPUB/PDF 是否使用同一套本地书阅读器外壳；PDF 是否优先展示章节目录，仅在无法可靠识别章节时降级到页码/缩略页导航；
- 设置页是否便于扫描并区分危险操作，手机主导航是否清晰可发现且不遮挡内容；
- 设置首页是否有微信读书服务行并能进入 `SET-02`；配置卡是否完整覆盖 API Key、未配置/已配置/测试中/已连接/失效、保存、测试、失败重试和清除凭证；
- 颜色、尺寸和组件状态是否形成一致的视觉系统，并且没有为了套用参考参数而牺牲可用性；
