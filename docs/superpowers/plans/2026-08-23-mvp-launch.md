## 1. 目标与边界

用最短关键路径完成可在中国邀请测试的产品闭环：

`登录 → 导入 / 同步一本书 → 阅读与笔记 → 确认 PPT 范围、大纲和模板 → 生成 → 预览并下载 PPTX`

本方案主动删除不影响首发闭环的建设：不做微服务、Kubernetes、Redis、通用任务平台、插件系统、管理后台、向量数据库、OCR、在线 PPT 编辑和多模型高级参数。

首发固定约束：

- 客户端是桌面 Web 与微信小程序；先用桌面 Web 固定共享契约，再接同一后端的小程序核心页。
- 数据库使用 PostgreSQL；后台任务先使用数据库任务表与独立 Worker，不再增加 Redis。
- PPT 复用 Presenton；项目只维护业务状态、模板映射、权限和下载。确定性本地 PPTX 只用于开发闭环，不冒充真实模型完成。
- 用户自有文本模型只支持 DeepSeek、Kimi、GLM、通义千问四家固定供应商；不开放任意 Base URL 和模型参数。
- 微信读书使用腾讯官方 `wrk-...` API Key 与官方 Agent API Gateway，不使用 Cookie 抓取。
- 未提供凭证或未授权的真实微信、模型和微信读书调用停在 H4 门前，不阻塞本地实现。

## 2. 四个纵向里程碑

### M0：可连续点击的桌面闭环

**结果：** 在真实浏览器中从开发入口进入一本种子书，填写需求、确认大纲、选择模板、观察逐页进度并下载可打开的 PPTX。

**只做：**

- 最小 TypeScript workspace：`apps/web`、`apps/server`、`packages/contracts`、`packages/domain`、`packages/presentation-adapter`。
- `GET /api/v1/health/live`、`GET /api/v1/health/ready`。
- PostgreSQL 中最小的 `books / conversations / ppt_drafts / ppt_tasks / ppt_pages / ppt_artifacts`。
- 确定性本地 PPT 适配器，所有页面和接口明确标记“开发数据”。
- 桌面共享外壳与 PPT 四阶段，不实现设置、真实认证、微信读书和完整阅读器。

**证据：** H0/H1、API 与 PostgreSQL H2、`1440×1024` 真实浏览器 H3、下载文件包含 `16:9` 页面与可编辑文字对象。

**停止条件：** 刷新后任务和下载记录仍在；下载文件不是截图拼装；生产构建不能默认启用开发适配器。

### M1：真实桌面内测闭环

**结果：** 邮箱登录、导入一本真实 EPUB/TXT、阅读与笔记、配置四家中的任一家真实模型、通过 Presenton 生成可编辑 PPTX。

**只做：**

- 邮箱注册 / 登录 / 找回密码与服务端会话。
- EPUB、TXT 和 PDF 使用统一导入与界面；PDF 有文本时读取文本，无文本但页面可渲染时显示页面图，全部不可渲染时明确失败；不引入 OCR。
- 阅读位置、划线、想法和老己笔记的最小 CRUD。
- 四家固定模型适配器与供应商下拉；凭证加密、检测成功后替换旧配置。
- Presenton 固定版本 API 适配、三套内置模板、任务停止 / 失败 / 恢复。
- 免费体验只实现 `¥5` 事务硬上限和平台调用成本账本，不建设券或充值系统。

**证据：** 真实文件导入 H2、登录至下载 H3；经用户授权后分别执行真实模型 H4 和 PowerPoint/WPS 打开重存验收。

**停止条件：** 一位邀请用户可在桌面独立完成闭环；失败和刷新不丢输入、笔记、草稿和已完成页面。

### M2：国内双端候选

**结果：** 微信登录、微信读书同步和微信小程序复用同一账户与后端闭环。

**只做：**

- Web 微信扫码与小程序 `wx.login()` 服务端交换；不做含数据账户合并。
- 微信读书官方书架、进度、个人划线与想法同步；不提供整本正文。
- 小程序登录、会话、书架、阅读 / 笔记、设置和 PPT 四阶段；不复制桌面组件。
- 同一账户的草稿、任务与作品跨端恢复。

**证据：** 开发者工具 H3、至少一台 iOS 和一台 Android 真机核心路径；经授权执行微信登录与微信读书 H4。

**停止条件：** 两端共享同一任务和产物，换号不静默合并，后台返回后任务可恢复。

### M3：邀请制上线

**结果：** 国内服务器上的 Web 与 API 可访问，小程序通过审核并向受邀用户开放。

**只做：**

- 单一生产镜像中的 `server / worker` 两种启动方式；Presenton 为服务器侧独立生成服务。
- PostgreSQL、S3 兼容对象存储、HTTPS、迁移、备份恢复、日志脱敏、费用和任务告警。
- 模型备案目录与产品详情公示；应用登记、隐私政策、小程序域名和审核材料。
- Staging 冒烟、生产部署与回滚。

**证据：** H5 当前候选快照、备份恢复、回滚、生产核心路径与审核结果。

**停止条件：** 邀请账户能完成一次真实闭环，错误和成本处于阈值内，并能回滚到前一兼容版本。

## 3. 当前执行入口：M1

M0 已完成并形成可恢复基线；当前不按整块 M1 直接开发，而由 [`TASK_LEDGER.md`](../../../TASK_LEDGER.md) 维护唯一工作包顺序、粒度、证据和阻塞。M1 先执行账户归属与 M0 数据迁移对账，再按认证、真实文件与阅读笔记、模型、免费体验、Presenton 和完整业务 Case 收口。

每个工作包独立完成开发、相关回归、与风险相称的真实业务 Case、修复复验、diff 审查和本地提交。用户可见路径使用真实浏览器或 Computer Use；外部调用、远端 push、合并、PR、发布和部署仍遵循授权门。本文只保留里程碑范围，不复制当前台账细节。

## 4. 风险与授权门

| 边界 | 当前动作 | 进入真实验证的条件 |
| --- | --- | --- |
| 文本模型 | 实现四家固定契约与假服务 | 用户指定供应商、提供 Key，并确认调用次数与预算 |
| 微信读书 | 实现官方 Gateway 契约和假响应 | 用户提供 `wrk-...` Key，并授权首同步 / 增量 / 无效 Key / 换号验证 |
| 微信登录 | 实现假 adapter 与回调契约 | 提供 Web 与小程序 AppID/AppSecret、合法回调域名 |
| Presenton | 已验证中文 PPTX 生成和 WPS 重存；继续本地 API 适配 | 固定镜像版本，完成模板、停止、重启和 PowerPoint/WPS 验收 |
| 上线 | 只准备代码和部署清单 | 用户明确授权部署，并提供域名、服务器、主体和平台账号 |

## 5. 时间目标

| 里程碑 | Codex 实际工作目标 | 人类日历目标 |
| --- | --- | --- |
| M0 | `3–5h` | 当天 |
| M1 | 再 `6–10h` | `1–2` 个工作日 |
| M2 | 再 `8–12h` | `1–3` 个工作日，另加微信外部门等待 |
| M3 | 再 `4–8h` | `1–2` 个工作日，另加备案 / 审核等待 |
| 合计 | `21–35h` | `4–8` 个工作日，外部等待另计 |

这是快速邀请制 MVP 目标，不包含大规模公开运营、付费、SLA 和完整管理后台。若外部审核、备案或真实接口行为与当前官方资料不一致，日历时间会增加，但不扩大本地代码范围来掩盖外部阻塞。

## 6. 质量门

- 每个里程碑只运行能证明当前风险的最小测试，不以测试数量代替用户路径。
- M0 允许明确标记的开发数据；M1 起，账户、文件、模型和 PPTX 必须从真实入口验收。
- 认证、凭证、成本、持久化、取消和外部调用必须覆盖成功、失败、超时、恢复和旧请求拒绝。
- 任何真实外部调用前先确认服务、模型、次数、范围和预算；任何发布前单独取得部署授权。
- 达到停止条件即提交当前纵向切片，不夹带下一里程碑基础设施。
