# 老己 UI 视觉规范

- 状态：v2 当前视觉事实源
- 适用端：响应式 Web

## 1. 边界与原则

本文只定义通用视觉语言、设计 Token、组件形态、响应式规则和视觉验收。产品功能、流程、字段、业务文案和状态转换以 `SPEC.md` 为准。

`assets/image2/` 仅用于提取风格，不是逐像素页面合同；其中的功能、文案、面板数量和固定尺寸不得直接继承。

视觉原则：

- 安静、清晰、克制的现代知识工具，带少量编辑出版物气质；
- 内容优先，主要依靠字体层级、留白、对齐和细分隔线组织界面；
- 每个操作组只有一个高强调主操作；
- 两端共享视觉语言，但手机按单任务重新组织布局；
- 不使用大面积高对比水墨、高饱和或多色渐变、玻璃拟态、重阴影、巨大标题、密集装饰纹样或卡片套卡片；允许同色系浅绿在大面积背景中缓慢混合，形成克制层次。

## 2. 视觉基础

### 2.1 色彩

| Token | 色值 | 用途 |
| --- | --- | --- |
| `bg` | `#EAF1EC` | 有明确绿意的应用底色 |
| `nav-surface` | `#CFE1D7` | 最左导航轨，比其他大面积背景稍绿但不做深色块 |
| `list-surface` | `#E0EBE5` | 会话列表与辅助侧栏 |
| `workspace-surface` | `#D8E7DF` | 上下文工作区底色，用于衬托关键内容 |
| `surface` | `#F8FAF6` | 对话主内容面和输入面 |
| `surface-raised` | `#FFFFFF` | 浮层、关键预览和最高层内容面 |
| `surface-subtle` | `#D4E5DC` | 选中、弱强调和占位 |
| `text-primary` | `#21312D` | 标题、正文和主要图标 |
| `text-secondary` | `#5F6F69` | 辅助说明和元信息 |
| `border` | `#B8CBC3` | 边框和分隔线 |
| `accent-strong` | `#174C3F` | 标题、图标和高层级文字锚点，不作为整栏底色 |
| `accent` | `#0D6A57` | 主操作、当前阶段和关键链接 |
| `accent-mid` | `#3F8B75` | 进度、辅助选中和次级强调 |
| `accent-hover` | `#0A594A` | 桌面悬停 |
| `accent-soft` | `#D9EAE3` | 选中背景和浅层强调 |
| `accent-faint` | `#EFF5F2` | 大面积弱分区背景 |
| `warning` | `#8A5A00` | 警告 |
| `error` | `#B44432` | 错误和破坏性后果 |

- 绿色是唯一品牌主色，通过墨绿文字、深青瓷绿操作、中青绿状态、浅玉绿分区和雾绿底色建立层级；不得再用同一个近白绿色铺满导航、列表、对话和工作区。
- 最左导航轨只比其他大面积绿色稍深、稍饱和，不使用整栏深墨绿。列表、主画布和上下文工作区使用可辨认但相邻的不同绿阶，白色仅用于输入、浮层和关键内容等需要突出的位置。
- 大面积背景可使用两到三个相邻浅绿的缓慢线性或径向混合，色差来自明度和饱和度而不是新增色相；渐变不得出现明显光带、霓虹感或多个焦点。
- 单个操作组最多同时出现三个绿色层级，避免同色系仍显杂乱；非绿色只用于语义必须的警告和错误，不把珊瑚、黄色或蓝色当作日常装饰色。
- 正文只使用 `text-primary` 或 `text-secondary`；更浅颜色不得承载关键内容。
- 状态必须同时使用文字、图标或形状，不能只靠颜色。
- 高饱和色只属于内容图片或语义状态，不扩散到界面框架。

### 2.2 背景材质

- 主体背景可以在混合绿底色上使用低对比度宣纸纤维、书页压纹、藏书票轮廓或淡远山线稿，复古感来自材质和局部构图，不依赖新增色相。
- 背景纹理只出现在应用底色与大块空白边缘，不进入输入框、正文阅读区或内容预览内部；不得降低文字、焦点和分隔线对比度。
- 单屏只使用一种主纹理和一种局部轮廓，透明度保持克制；不能形成连续墙纸、明显噪点、仿旧污渍或抢夺视线的水墨画。

### 2.3 字体

- UI 使用系统无衬线字体：`PingFang SC`, `Microsoft YaHei`, `Noto Sans CJK SC`, sans-serif。
- 长篇阅读或引文可使用：`Songti SC`, `STSong`, `Noto Serif CJK SC`, serif。
- 品牌字可有轻微书写感，但按钮、导航和正文不使用书法字体。

| 层级 | 桌面 | 手机 | 字重 |
| --- | --- | --- | --- |
| H1 | `28/36` | `24/32` | 600 |
| H2 | `22/30` | `20/28` | 600 |
| H3 | `18/26` | `18/26` | 600 |
| Body | `16/28` | `16/28` | 400 |
| UI | `14/22` | `14/22` | 400/500 |
| Meta | `12/18` | `12/18` | 400/500 |

长文本限制行宽，标题和正文优先换行；不得通过截断隐藏关键状态或错误原因。

### 2.4 间距与几何

- 使用 4px 网格：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64`。
- 页面留白：桌面 `24–40px`，手机 `16–20px`。
- 圆角：小控件 `4px`、常规控件 `8px`、浮层 `12px`、独立模态 `16px`。
- 常规边框：`1px solid #CBD8D3`；不普遍使用胶囊形。
- 普通内容面不使用阴影；浮层最多使用 `0 8px 24px rgba(33,49,45,.10)`。

### 2.5 品牌资产与角色视觉

- 账户入口使用“复古印刷铺”视觉：暖白纸色、青瓷绿细框、克制的宋体标题和少量珊瑚粉点睛；应用内部回到本规范的现代知识工具视觉语言。
- 产品内左上角直接使用 `assets/avatar/laoji-avatar-conversation-approved-v1.png` 作为老己 Logo 头像；宽导航在头像后显示“老己”字标，窄导航只保留圆形头像，不再使用书页或印章图标替代。
- 老己的对话消息头像也必须使用同一个 `assets/avatar/laoji-avatar-conversation-approved-v1.png`。左上 Logo 保留完整圆形构图，对话头像可在圆形内更紧地裁切脸部与上半身，以尺寸和裁切区分用途；不得重新绘制、改色、换表情或以文字圆标替代。
- 老己角色以 `assets/mascot/laoji-character-master-v1.png` 为标准素材。固定粉色双云髻、圆眼镜、Q 版脸型和青瓷绿古装；姿势、表情、道具与裁切可按场景变化。
- 全身桌宠应以透明背景融入当前布局；Logo 与消息头像可以保留指定头像原图的圆形月洞、山水和纸张背景，但这些背景不得扩展出头像边界或成为页面装饰。
- 对话页的桌宠坐在输入框上沿，并避开输入、附件和发送操作。
- 桌宠关闭后的召回入口保持低存在感；桌宠和召回入口不得长期遮挡内容。
- 账户入口的复古感来自印刷分栏、字体层级、细框和角色构图，不使用仿旧噪点、邮票拼贴、装饰花纹或降低表单可读性的复杂背景。
- 桌面可并列品牌海报区与表单区；手机改为紧凑角色横幅和单列表单，不保留占据半屏的桌面海报栏。

## 3. 布局与响应式

### 3.1 通用布局原语

- **应用外壳**：容纳全局导航和工作上下文，切换内容时保持稳定。
- **导航轨**：窄而稳定，底色使用比相邻侧栏更饱和的浅玉绿，选中项再通过深绿图标、轮廓和略深背景共同表达。
- **辅助侧栏**：承载列表、目录或局部导航，以细分隔线连接主画布。
- **主画布**：承载当前主要任务，拥有最高视觉层级。
- **上下文面板**：宽屏并行展示相关内容；空间不足时进入次级视图或浮层。
- **内容列与网格**：正文限制行宽，网格根据最小项目宽度自适应列数。
- **浮动工具面**：只在与当前内容直接相关时出现，不长期遮挡正文。

优先使用“分组、对齐、留白、分隔线、浅背景”，最后才使用卡片和阴影。

桌面导航轨允许通过边缘左右拖动在两档状态间吸附：窄态只显示图标，宽态显示图标与文字。默认不设置常驻收起按钮；分隔线悬停时显露拖拽反馈，双击可切换两档，键盘聚焦后可用方向键调整并用 Enter 切换。具体宽度和吸附阈值由实现按内容与视口确定。

### 3.2 主画布与上下文工作区

- 没有可并行操作的上下文时，主画布不为空面板预留宽度。
- 宽屏最多在主画布旁展示一个与当前内容直接相关的上下文工作区，不按能力继续增加固定列。
- 仅主画布与当前上下文工作区之间提供宽度调整。分隔线默认保持安静，悬停时扩大热区并显示拖拽反馈；双击在收起和上次使用宽度之间切换。
- 工作区拖到最小安全宽度以下时吸附为标明上下文类型和当前阶段的窄条；向外拖动或双击可恢复，并记住上次使用宽度。
- 不设置常驻收起按钮。分隔线可获得键盘焦点，方向键调整宽度，Enter 收起或恢复；状态变化不能只依赖颜色。
- 空间不足或操作会被遮挡时，桌宠可以暂时弱化或缩回召回入口，但不得擅自关闭用户正在编辑的工作区。

### 3.3 断点与跨端规则

| 模式 | 宽度 | 规则 |
| --- | --- | --- |
| Compact | `≤767px` | 单任务、单主列、触控优先 |
| Medium | `768–1199px` | 主画布常驻，辅助区域按空间折叠 |
| Wide | `≥1200px` | 允许相关上下文并行展示 |

| 维度 | Wide / Medium | Compact |
| --- | --- | --- |
| 主导航 | 常驻导航轨或侧栏 | 紧凑页头、底部导航或次级视图 |
| 内容组织 | 可并列相关面板 | 一次只显示一个主要任务 |
| 局部导航 | 可常驻辅助侧栏 | 全屏次级视图、抽屉或底部面板 |
| 操作密度 | 鼠标、键盘的紧凑布局 | 44px 触控目标和更大间隔 |
| 浮层 | 定位弹层、模态或侧面板 | 优先底部面板或全屏层 |

手机必须使用 `100dvh` 和安全区；键盘弹出后输入与主要操作仍可见。桌面侧栏不得简单堆叠到手机内容顶部，吸底操作区必须为滚动内容预留空间。

## 4. 通用组件

### 4.1 图标与操作

- 使用统一的成熟线性图标或本地 SVG，常规 `20px`，主导航 `22–24px`，描边约 `1.75–2px`。
- 不使用字符、Emoji、CSS 线框或圆点冒充正式图标；图标按钮必须有可访问名称。
- 按钮高度：桌面至少 `40px`，手机至少 `44px`；图标按钮触控区域至少 `44×44px`。
- 主按钮使用深绿实心和白字；次按钮使用白底、深色文字和细边框；破坏性操作使用错误色和明确文字。

### 4.2 表单与导航

- 输入框和选择器使用白底、8px 圆角和 1px 边框；手机高度至少 `44px`。
- 聚焦态使用 2px 强调色轮廓；错误信息靠近字段显示并保留原输入；占位符不能代替标签。
- 当前导航项同时改变背景或轮廓与图标颜色；不依赖悬停或单一颜色表达选中。
- 标签栏最小高度 `44px`；窄屏可横向滚动并自动显示当前项。

### 4.3 列表、卡片与媒体

- 结构化列表优先使用行、分组标题和分隔线；卡片只用于独立选择、拖动、状态或预览对象。
- 选中卡片至少同时使用边框、浅背景和图标中的两种信号。
- 对话类列表行使用统一图标、标题和摘要，不预留固定封面位，也不因当前任务改变基础结构。必要状态和产物数量放在摘要或元信息位置。
- 竖向封面优先保持 `5:7` 或原始比例，宽屏内容优先保持真实 `16:9`。
- 图片不得拉伸或放大失真；加载前保留稳定比例，避免布局跳动。
- 生成图片中的错字、伪 Logo 和不一致图标不得作为正式 UI 素材复用。

### 4.4 对话与异步运行态

- 当前会话的 AI 回答运行时，消息区在老己头像旁显示“老己正在思考…”或流式内容，发送按钮原位变为带可访问名称的“停止回答”控件；输入可保留草稿，但发送和附件提交不可用。
- 异步任务运行时，对话区使用一条稳定位置的原位状态，输入区附近显示可理解的锁定原因，发送按钮原位切换为明确的停止操作。
- 运行态不靠大面积置灰表达；状态文字、图标或形状与停止操作至少同时出现两种。
- “正在思考”使用低频的三点呼吸或小幅书页翻动反馈；减少动态效果时改为静态状态文字，不使用无限旋转的大型加载器。

### 4.5 对话内结构化选择

- 结构化选择控件直接附在对应消息下方，使问题、选项和结果保持同一上下文；不为每个简单选择弹出模态框。
- 待选择时，问题文案保留在老己消息气泡内，选项区在正文下方间隔 `12px` 直接展开；不再包一层外部重卡片，也不把选择器脱离问题单独放到页面其他位置。
- `2–6` 个清晰选项优先使用按钮组、单选或多选；短文案的 `2–3` 项可同行排列，`4–6` 项或较长文案使用两列或单列，手机统一改为单列。每组提供可理解的问题标题，必要时提供“其他”或直接输入出口，不把下拉框作为所有场景的默认形态。
- 单个选项使用白底、`1px` `border` 边框、`8px` 圆角和至少 `44px` 高度；选项内容左对齐，文案前可使用单选、复选或语义图标，不使用一排无差别胶囊。
- 需要确认或自由输入时，在原选项组下方显示紧凑主操作或行内输入，不另开模态框。
- 动态选择的可视状态遵循下表：

| 状态 | 视觉与反馈 |
| --- | --- |
| 默认 | 白底、`border` 边框、`text-primary` 文字，不用颜色预先暗示答案。 |
| 悬停 / 按下 | 底色切换为 `accent-faint`，边框使用 `accent-mid`；按下仅做轻微明度变化，不做明显缩放。 |
| 键盘聚焦 | 控件外显示 `2px` `accent` 焦点轮廓，不与选中状态混淆。 |
| 已选中 | `accent-soft` 底色、`accent` 边框和对勾或单选点同时出现，不只改文字颜色。 |
| 提交中 | 保留已选内容，禁止重复点击，原位显示“正在提交…”与低频动效；减少动态效果时只保留文字。 |
| 已确认 | 整组选项折叠为一行“已选择：…”，附对勾与“已确认”文字，不保留可点击的旧选项。 |
| 已更新 / 已失效 | 使用次要文字和“已更新”或“此选择已失效”明示，不再接受交互，也不仅靠置灰表达。 |

- 层级、多选、需要预览或较长说明的复杂选择进入当前任务工作区；手机优先使用全屏次级视图或底部面板，不强行把复杂内容塞进消息气泡。
- 工作区需要回看当前值时，使用标题、文本和值的轻量分组，不新增独立重卡片或重复边框。
- 选择控件必须支持键盘操作、可访问名称、清晰焦点和至少 `44×44px` 的触控目标。

### 4.6 层级大纲编辑器

- 大纲优先使用行式分层结构：每页为一级行，页标题直接编辑，要点在行内展开编辑；以细分隔线组织，不将每页做成独立重卡片。
- 页面之间在悬停或键盘聚焦时显示“插入一页”，列表末尾保留“新增一页”；展开页面后可添加要点。
- 结构操作的保存、失败和重试反馈使用原位置，避免打断编辑视线。
- 插入控件必须可键盘访问并具备可访问名称，不把悬停作为唯一入口。

### 4.7 生成页面瀑布流

- 生成中、失败和完成态复用同一个单列大图瀑布流；页型内容保持真实比例，当前 PPT 页为 `16:9`，并尽量使用工作区可用宽度。
- 生成中只展示已经完成的完整页面与末尾一个同尺寸当前页骨架；尚未开始的页面不提前铺设空骨架，页数和当前进度固定在工作区顶部说明。
- 新完成页面原位替换当前页骨架，下一页骨架追加到瀑布流末尾，避免内容跳动。
- 失败提示覆盖或嵌入失败页的完整比例区域，已完成页面保持可见；恢复生成后从失败页原位继续，不清空或缩回为任务列表。
- 完成态连续展示全部大图页面，滚动即预览，不额外显示缩略图列表、轮播或分页器。
- 瀑布流背景使用 `surface` 或 `accent-faint` 与页面白底拉开层级；页码、生成状态和当前页轮廓使用深浅不同的绿色，不依赖阴影堆叠。

### 4.8 浮层与反馈

- 小范围操作使用定位弹层，集中输入使用模态，手机复杂任务使用全屏层。
- 底部面板必须有标题和明确关闭方式；拖拽指示不能成为唯一出口。
- Toast 只反馈短结果；需要阅读或操作的错误在原位置呈现。
- 进度、加载和失败占用稳定区域，已有内容不得因后续失败消失。

## 5. 状态、动效与无障碍

### 5.1 状态

所有数据区域区分初次加载、真实空数据、搜索或筛选为空、请求失败和正常内容，并保持相同内容骨架。加载和失败不得先闪现为空数据。

组件必须覆盖默认、悬停、聚焦、按下、选中、禁用、加载、成功和错误状态；手机不需要悬停，但必须有按下反馈。

### 5.2 动效

- 即时反馈 `120–180ms`，面板与视图切换 `180–240ms`。
- 推荐缓动：`cubic-bezier(.2,.8,.2,1)`。
- 动效只解释层级、来源和状态变化，不做持续装饰运动。
- 桌宠仅使用低频眨眼、呼吸、轻摆和点击回应；对话页不通过提示气泡宣称不存在的导航功能。
- 尊重 `prefers-reduced-motion`；减少动态效果时取消位移和缩放。

### 5.3 无障碍

- 正文和关键控件对比度至少 `4.5:1`，大号文字至少 `3:1`。
- 键盘焦点始终可见，焦点顺序与视觉顺序一致。
- 触控目标不小于 `44×44px`，状态不只靠颜色表达。
- 200% 文本缩放、长标题和系统字体放大时仍能完成主要操作。
- 不使用固定高度裁切动态文字；多栏内容在窄屏重新组织，而不是整体缩小。

## 6. 参考边界与验收

实现只以本文的当前规则为视觉事实源，不从旧版或生成图自行推断缺失规则。已确认参考图的索引位于 `output/ui-design-preview/README.md`；该索引只记录稿件状态，不形成平行规范。

至少在 `360 / 390 / 430 / 768 / 1024 / 1200 / 1440px` 检查：

- 无横向溢出、内容裁切、控件重叠、键盘或安全区遮挡；
- 手机不是桌面多栏的缩小版；
- 一个操作组只有一个明确主操作；
- 五类数据状态清晰且结构稳定；
- 对话内结构化选择在待选、选中、提交、已确认和已失效状态下均有明确视觉反馈；提交后不残留可操作的旧选项；
- 焦点、触控目标、对比度、长文本和 200% 缩放符合要求；
- 无高饱和或多色渐变、重阴影、高对比装饰水墨、卡片套卡片或无意义分组；同色系混合绿和低对比背景纹理形成层次但不影响内容识别。
