# 老己 UI 共享视觉规范

- 状态：v2 当前视觉总入口与共享事实源
- 适用端：桌面 Web 与微信小程序

## 1. 文档职责与读取顺序

本文只定义两端共同使用的品牌、视觉基础、共享组件状态、动效、无障碍和参考图治理。产品目标、功能、流程、字段和业务状态以 [`SPEC.md`](SPEC.md) 为准；具体页面布局与端侧交互分别由以下文件定义：

- 桌面 Web：[`DESIGN-WEB.md`](DESIGN-WEB.md)
- 微信小程序：[`DESIGN-MINIAPP.md`](DESIGN-MINIAPP.md)
- 参考图确认层级、适用范围与原稿：[`design-reference/README.md`](design-reference/README.md)

所有视觉任务先读本文，再读且只读当前目标对应的端侧规范。共享规则只写在本文；桌面 Web 和微信小程序的专属规则只写在各自文件，不在三份文档中复制。

`assets/image2/` 仅用于提取风格，不是逐像素页面合同；其中的功能、文案、面板数量和固定尺寸不得直接继承。

## 2. 共享视觉原则

- 安静、清晰、克制的现代知识工具，使用稳定的青瓷复古书卷气质。
- 内容优先，主要依靠字体层级、留白、对齐和细分隔线组织界面。
- 每个操作组只有一个高强调主操作。
- 两端共享品牌身份和业务状态，但按各自平台重新组织布局与交互，不从另一端机械缩放或放大。
- 不使用大面积高对比水墨、高饱和或多色渐变、玻璃拟态、重阴影、巨大标题、密集装饰纹样或卡片套卡片。
- 同色系浅绿可以在大面积背景中缓慢混合，但不得出现明显光带、霓虹感或多个焦点。

- 绿色是唯一品牌主色，通过墨绿文字、深青瓷绿操作、中青绿状态、浅玉绿分区和雾绿底色建立层级。
- 单个操作组最多同时出现三个绿色层级；非绿色只用于语义必须的警告和错误。
- 正文只使用 `text-primary` 或 `text-secondary`；更浅颜色不得承载关键内容。
- 状态同时使用文字、图标或形状，不能只靠颜色。
- 高饱和色只属于内容图片或语义状态，不扩散到界面框架。

### 3.2 字体

- UI 使用系统无衬线字体：`PingFang SC`, `Microsoft YaHei`, `Noto Sans CJK SC`, sans-serif。
- 长篇阅读或引文可使用：`Songti SC`, `STSong`, `Noto Serif CJK SC`, serif。
- 品牌字可有轻微书写感，但按钮、导航和正文不使用书法字体。

| 层级 | 桌面 Web | 微信小程序 | 字重 |
| --- | --- | --- | --- |
| H1 | `28/36` | `24/32` | 600 |
| H2 | `22/30` | `20/28` | 600 |
| H3 | `18/26` | `18/26` | 600 |
| Body | `16/28` | `16/28` | 400 |
| UI | `14/22` | `14/22` | 400/500 |
| Meta | `12/18` | `12/18` | 400/500 |

长文本限制行宽并优先换行；不得通过截断隐藏关键状态或错误原因。

### 3.3 间距、边框与表面

- 使用 4px 网格：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64`。
- 常规边框为 `1px solid #CBD8D3`。
- 普通内容面不使用阴影；浮层最多使用 `0 8px 24px rgba(33,49,45,.10)`。
- 圆角、页面留白、控件尺寸和平台表面形态由对应端侧规范定义。

### 3.4 背景材质

- 复古感来自冷调纸面、极淡青瓷雾感、宣纸纤维、书页压纹和低对比远山线稿，不依赖新增色相。
- 背景纹理主要位于应用底色与大块空白边缘，中心内容区弱于边缘，不得降低文字、焦点和分隔线对比度。
- 单屏只使用一种主纹理和一种局部轮廓，不形成连续墙纸、明显噪点、仿旧污渍或抢夺视线的水墨画。
- 书籍详情使用 `app-paper`；真正的阅读正文才使用阅读背景预设。

## 4. 品牌资产与角色

- 桌面 Web 与微信小程序登录页统一使用标语“遇见自己，爱你老己”；该标语只约束登录页，不作为应用内页面的常驻文案。
- 产品 Logo 和老己消息头像必须直接使用 `assets/avatar/laoji-avatar-qingci-chibi-v2.png`，不得重绘、改色、换表情或以文字圆标替代。
- 老己角色身份以 `assets/mascot/laoji-character-master-v1.png`、已确认桌宠参考和正式透明资产为准；默认道具为书，其他道具只由明确任务语义短暂触发。
- 坐姿持书与趴卧扶书造型分别以 `assets/mascot/laoji-mascot-seated-reading-approved-v1.png`、`assets/mascot/laoji-mascot-prone-reading-approved-v1.png` 为确认源图；两图没有 Alpha 且棋盘格已写入像素，只用于造型溯源。运行时分别使用 `assets/mascot/laoji-mascot-seated-reading-transparent-v1.png`、`assets/mascot/laoji-mascot-prone-reading-transparent-v1.png`，不得重新生成或改画角色。
- `design-reference/12-mobile-composer-prone-mascot.png` 只确认趴卧姿态、构图与表情，因棋盘格已经写入像素且没有透明通道，不是运行时资产。
- 桌宠在固定、底部对齐的槽位内变化，不得推动周围内容、遮挡主要任务或把人物本身伪装成按钮。
- 端侧姿态、召回方式、角色尺寸和对话快捷入口分别由桌面 Web 与微信小程序规范定义。

## 5. 共享组件与状态

### 5.1 图标、表单与操作

- 使用统一的成熟线性图标或本地 SVG；不使用字符、Emoji、CSS 线框或圆点冒充正式图标。
- 图标按钮必须有可访问名称；主要触控目标不小于 `44×44px`。
- 操作固定分为主操作、次操作、文字操作和危险操作：主操作使用品牌强调色，次操作使用低强调描边或文字，危险样式只用于破坏性后果；每个操作组只保留一个高强调操作。
- 相同语义必须复用同一组件及状态，不得仅因页面不同重新发明颜色、圆角、图标或交互方式。
- 输入框与选择器使用清晰标签、稳定边框和可见焦点；占位符不能代替标签。
- 错误信息靠近字段显示并保留原输入。
- `API Key` 等凭证输入默认使用密文，显隐操作具有可访问名称且不改变字段宽度；“检测并保存”是配置页唯一主操作，失焦、关闭或返回不触发检测、保存或清空。

### 5.2 列表、卡片与媒体

- 结构化内容优先使用行、分组标题、留白和分隔线；卡片只用于独立选择、拖动、状态或预览对象。
- 选中项至少同时使用边框、浅背景、对勾或状态文字中的两种信号。
- 图片不得拉伸或放大失真；加载前保留稳定比例。
- PPT 页面和模板预览统一保持真实 `16:9`；竖向书籍封面保持原始比例，无法取得时优先使用 `5:7`。
- 生成图片中的错字、伪 Logo 和不一致图标不得作为正式 UI 素材复用。
- 未连接外部服务的引导使用内容流内低强调服务行，优先置于相关搜索控件之后、内容网格之前；连接成功后不保留空占位。
- 新账户尚未领取时只使用一条内容流内轻提示“免费体验额度”，后接“领取”文字按钮；不使用卡片、积分徽章、倒计时、规则列表、券包入口或高饱和营销装饰。领取成功后短暂反馈并移除整条提示，不保留空占位。

### 5.3 数据与异步状态

- 所有数据区域区分初次加载、真实空数据、搜索或筛选为空、请求失败和正常内容，并保持相同内容骨架。
- 组件覆盖默认、悬停或按下、聚焦、选中、禁用、加载、成功和错误状态；微信小程序不要求悬停，但必须有按下反馈。
- AI 回答或任务运行时使用单条稳定状态原位更新；停止、失败和重试保留输入、上下文与已完成结果。
- 进度、加载和失败占用稳定区域，已有内容不得因后续失败消失。
- Toast 只反馈短结果；需要阅读或操作的错误在原位置呈现。

### 5.4 对话内结构化选择

- 问题、选项和结果保持在同一消息上下文；简单选择不弹出独立模态。
- 选中状态同时使用背景、边框和对勾或单选点；键盘焦点与选中状态不得混淆。
- 提交后折叠为只读“已选择”结果；已更新或失效的选择明确标注且不再接受交互。
- 复杂层级、多选、预览或长说明进入当前任务工作区或微信小程序的次级界面。

### 5.5 PPT 共享视觉语义

- PPT 固定为“范围与需求 / 大纲 / 模板 / 生成”四个阶段；两个平台使用各自的阶段导航表现。
- 大纲使用连续分层文本；页面、要点和说明由段落层级判定，一级段落自动计页，编辑失败不丢内容和焦点。
- 模板选择同时显示真实 `16:9` 预览、名称和非颜色单一的选中反馈；是否显示说明、列数和操作位置由端侧规范定义。
- 生成中、失败和完成复用同一个单列大图瀑布流：已完成页面保持可见，当前页使用同尺寸骨架或原位失败区，尚未开始的页面不提前占位。
- 生成失败页保留“重新生成”和“修改大纲”主路径；右上角低频菜单的“删除任务”须二次确认，只清理当前失败任务及其临时已完成页面，不影响会话、书籍或历史作品，删除后不可重试。
- 完成态连续展示全部页面并支持下载；重新生成创建独立作品，不覆盖已有作品。
- 下载操作附近只用一行次要文字说明“文字与形状可编辑，图片不可编辑”，不展开文件格式规则或技术实现说明。

### 5.6 阅读与引用内容

- 阅读正文使用舒适行宽、清晰层级和低对比纸纹；正文选择、划线、想法和焦点不能只靠颜色表达。
- 阅读背景切换覆盖完整阅读工作区，不改变跨模块共享外壳。
- 划线与想法、老己笔记都使用单列全宽内容流和细分隔线，不设置独立标题字段，也不把正文第一行标题化。
- 引用原文只读；只有存在可靠定位时才显示位置，无法识别时不保留空占位。

### 5.7 参考图未覆盖的界面

- 先从 `SPEC.md` 确定行为，再从目标端侧规范确定页面骨架；参考图只提供风格和已确认组件范例。
- 按语义优先复用已有组件；只使用本文已有的颜色、字体、间距、表面、圆角和阴影规则，不新增另一套视觉语言。
- 默认用层级、留白、开放式列表和细分隔线组织内容；只有独立选择、预览、拖动或明确状态对象才使用卡片。
- 现有模式无法承载时，从最接近的已确认组件派生最小变体；只有变体会重复使用时才补回对应端侧规范，验收同时对照最近的认可参考和本文状态规则。

## 6. 动效与无障碍

- 即时反馈 `120–180ms`，面板与视图切换 `180–240ms`；推荐缓动 `cubic-bezier(.2,.8,.2,1)`。
- 动效只解释层级、来源和状态变化，不做持续装饰运动。
- 尊重减少动态效果设置；取消位移、缩放和曲线路径后，使用约 `140ms` 的淡入淡出。
- 正文和关键控件对比度至少 `4.5:1`，大号文字至少 `3:1`。
- 键盘焦点始终可见，焦点顺序与视觉顺序一致。
- 状态不只靠颜色；触控目标不小于 `44×44px`。
- 200% 文本缩放、长标题和系统字体放大时仍能完成主要操作，不使用固定高度裁切动态文字。

## 7. 参考边界与验收

实现只以本文、目标端侧规范和当前产品规格为事实源，不从旧版、聊天记录、文件名或生成日期推断缺失规则。

参考图按“完整视觉定稿”“已认可页面参考”“已认可视觉元素”和“已确认流程 / 结构”分级，唯一索引位于 [`design-reference/README.md`](design-reference/README.md)。参考图中的示例数据、错字、生成文字、伪图标和与事实源冲突的细节不得照搬。

验收至少检查：无内容裁切、控件重叠和横向溢出；一个操作组只有一个主操作；五类数据状态结构稳定；真实媒体比例不失真；焦点、触控目标、对比度、长文本和系统字体放大符合要求。
