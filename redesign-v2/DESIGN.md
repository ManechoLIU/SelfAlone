# 老己 UI 视觉规范

- 状态：v2 当前视觉事实源
- 适用端：桌面 Web 与微信小程序

## 1. 边界与原则

本文只定义通用视觉语言、设计 Token、组件形态、响应式规则和视觉验收。产品功能、流程、字段、业务文案和状态转换以 `SPEC.md` 为准。

`assets/image2/` 仅用于提取风格，不是逐像素页面合同；其中的功能、文案、面板数量和固定尺寸不得直接继承。

视觉原则：

- 安静、清晰、克制的现代知识工具，使用稳定的青瓷复古书卷外壳，而不是在不同模块间切换成无装饰的通用工具界面；
- 内容优先，主要依靠字体层级、留白、对齐和细分隔线组织界面；
- 每个操作组只有一个高强调主操作；
- 两端共享视觉语言，但手机按单任务重新组织布局；
- 不使用大面积高对比水墨、高饱和或多色渐变、玻璃拟态、重阴影、巨大标题、密集装饰纹样或卡片套卡片；允许同色系浅绿在大面积背景中缓慢混合，形成克制层次。

## 2. 视觉基础

- 绿色是唯一品牌主色，通过墨绿文字、深青瓷绿操作、中青绿状态、浅玉绿分区和雾绿底色建立层级；不得再用同一个近白绿色铺满导航、列表、对话和工作区。
- 最左导航轨只比其他大面积绿色稍深、稍饱和，不使用整栏深墨绿。列表、主画布和上下文工作区使用可辨认但相邻的不同绿阶，白色仅用于输入、浮层和关键内容等需要突出的位置。
- 大面积背景可使用两到三个相邻浅绿的缓慢线性或径向混合，色差来自明度和饱和度而不是新增色相；渐变不得出现明显光带、霓虹感或多个焦点。
- 单个操作组最多同时出现三个绿色层级，避免同色系仍显杂乱；非绿色只用于语义必须的警告和错误，不把珊瑚、黄色或蓝色当作日常装饰色。
- 正文只使用 `text-primary` 或 `text-secondary`；更浅颜色不得承载关键内容。
- 状态必须同时使用文字、图标或形状，不能只靠颜色。
- 高饱和色只属于内容图片或语义状态，不扩散到界面框架。

### 2.2 背景材质

- 读书详情的主体背景以低饱和浅青灰 `app-paper` 为基底，在边缘叠加极淡青瓷雾感、宣纸纤维、书页压纹、藏书票轮廓或淡远山线稿；复古感来自材质和局部构图，不依赖新增色相，也不得被简化为纯色空白外壳。该区域保持克制的青绿色感，不得漂成米黄、暖灰或粉红；真正的阅读正文才使用阅读背景预设。
- 背景纹理主要出现在应用底色与大块空白边缘；Compact 正文允许覆盖全页但必须极淡、细密且近似真实纸纤维，中心区弱于边缘，不得形成可辨认花纹，也不得降低文字、焦点和分隔线对比度。纹理不进入输入框或内容预览内部。
- Wide / Medium 应用内左侧主导航必须保留同一组低对比、低饱和的复古远山、树木与亭子背景，场景贴底锚定；在约 `1024px` 高的桌面画布中，水墨近景和亭子主要收在导航底部约三分之一，向上只保留非常浅的远山与雾气。不得因模块切换而删除这些元素，也不得把场景上移成抢占导航项的半栏主插画、加深笔触、增加山峰密度或提高对比度。
- 对话与“范围与需求”的共享桌面外壳以 `design-reference/02-conversation-and-scope.png` 为完整视觉基准；书架和设置稿用于补充较宽导航下的裁切与密度。PPT 大纲、模板和生成中图片只提供流程与内容结构，缺失的远山亭子、头像、会话列表和绿色层次必须回到该共享外壳，不得照抄为新的页面风格。
- 单屏只使用一种主纹理和一种局部轮廓，透明度保持克制；不能形成连续墙纸、明显噪点、仿旧污渍或抢夺视线的水墨画。

### 2.3 字体

- UI 使用系统无衬线字体：`PingFang SC`, `Microsoft YaHei`, `Noto Sans CJK SC`, sans-serif。
- 长篇阅读或引文可使用：`Songti SC`, `STSong`, `Noto Serif CJK SC`, serif。
- 品牌字可有轻微书写感，但按钮、导航和正文不使用书法字体。

| 层级 | 桌面 | 手机 | 字重 |
| --- | --- | --- | --- |
| H1 | `28/36` | `24/32` | 600 |
| H2 | `22/30` | `20/28` | 600 |
| H3 | `18/26` | `18/26` | 600 |
| Body | `16/28` | `16/28` | 400 |
| UI | `14/22` | `14/22` | 400/500 |
| Meta | `12/18` | `12/18` | 400/500 |

长文本限制行宽，标题和正文优先换行；不得通过截断隐藏关键状态或错误原因。

### 2.4 间距与几何

- 使用 4px 网格：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64`。
- 页面留白：桌面 `24–40px`，手机 `16–20px`。
- 圆角按端区分：Wide / Medium 使用小控件 `4px`、常规控件 `8px`、浮层 `12px`、独立模态 `16px`；Compact 使用小控件 `10–12px`、输入与主要操作面 `16–20px`、抽屉与底部面板 `24–32px`。手机不把所有控件做成胶囊，连续内容行也不因增大圆角而变成独立卡片。
- 常规边框：`1px solid #CBD8D3`；不普遍使用胶囊形。
- 普通内容面不使用阴影；浮层最多使用 `0 8px 24px rgba(33,49,45,.10)`。

### 2.5 品牌资产与角色视觉

- 桌面 Web 账户入口使用低对比水墨书页视觉：暖白纸色、青瓷绿、克制的宋体标题和少量珊瑚红印章点睛；进入应用后延续青瓷绿、远山、树木、亭子和书页材质构成的复古书卷外壳，内容区仍保持现代知识工具的清晰结构。
- 产品内左上角直接以原始位图使用 `assets/avatar/laoji-avatar-qingci-chibi-v2.png` 作为老己 Logo 头像；宽导航在头像后显示“老己”字标，窄导航只保留圆形头像，不再使用书页或印章图标替代。视觉稿和实现都不得让图像模型重绘、近似复刻或重新生成该头像。
- 老己的对话消息头像也必须使用同一个 `assets/avatar/laoji-avatar-qingci-chibi-v2.png`。左上 Logo 保留完整圆形构图，对话头像可在圆形内更紧地裁切脸部与上半身，以尺寸和裁切区分用途；不得重新绘制、改色、换表情或以文字圆标替代。
- 老己角色身份以 `assets/mascot/laoji-character-master-v1.png`、完整视觉定稿中的坐姿持书桌宠和 `design-reference/12-mobile-composer-prone-mascot.png` 的 Compact 趴卧造型为准。运行时必须直接复用另行确认的透明原始位图，不得让图像模型重新解释身份、改色或增加脏污纹理；其中 12 只确认姿态、构图与表情，因原图没有透明通道，不是运行时资产。默认道具固定为书，姿势、表情与裁切只使用已确认素材或参考。其他道具不得随机出现，只能由明确任务语义短暂触发，例如生成 PPT 时拿页面稿、完成时盖印章，状态结束后恢复持书。
- 全身桌宠应以透明背景融入当前布局，并在固定、底部对齐的桌宠槽位内变化；站立、坐下或躺下不得推动周围内容或造成布局跳动。Logo 与消息头像可以保留指定头像原图的圆形月洞、山水和纸张背景，但这些背景不得扩展出头像边界或成为页面装饰。
- 对话页的桌宠依附输入框上沿，并避开输入、附件和发送操作。Wide / Medium 可使用坐姿持书造型；Compact 默认采用 `design-reference/12-mobile-composer-prone-mascot.png` 的探头式趴卧造型：头部微歪，双臂自然趴靠上沿，双手扶住一本小书，只露出头部与少量上半身。角色趴在输入框左上角，宽度约为输入框的 `20–24%`，不得居中或放大成页面视觉中心。它是输入区的低存在感陪伴层，不形成新按钮，也不覆盖消息、输入文字或触控目标。Compact 在键盘弹出、输入框扩展或内容空间不足时沿输入框后方下沉，最终只在输入框左上沿露出一个小发髻作为召回提示；发髻不额外占用布局，透明触控区仍不小于 `44×44px`，点击后沿原路径重新探头。
- 设置总览默认使用小尺寸坐姿读书桌宠，完整露出身体、裙摆与书本；在约 `1440×1024px` 桌面画布中角色高度建议为 `96–120px`，保持低存在感，不因空白区域放大角色。
- 桌宠在角色组中位于前景；Wide / Medium 的读书、设置等非对话页面中，进入对话的快捷入口使用 `44px` 的墨绿色实心圆形气泡按钮，固定在桌宠右侧并保持约 `6–8px` 间距，使两者读作紧凑的同一角色组；不得放到人物左侧、人物后方或覆盖人物，也不常驻显示“找老己聊聊”等长文案，桌面悬停或键盘聚焦时才显示简短提示。关闭控件具有明确可访问名称和不小于 `44×44px` 的命中区域，桌面默认隐藏，在桌宠区域悬停或键盘聚焦时淡入；触屏点击桌宠后显示控制。关闭后桌宠与气泡入口一同收回左上角老己头像，头像通过轻微回应提示可召回，点击或键盘激活头像时原路径返回。桌宠、气泡和召回入口不得长期遮挡内容。
- 账户入口的复古感来自大面积留白、字体层级、山水构图和角色比例，不使用仿旧噪点、邮票拼贴、装饰花纹或降低表单可读性的复杂背景。
- Wide 桌面 Web 将品牌场景与账户面板分为约等宽两区：左侧以大圆弧纸面收住低对比山水，品牌位于左上，角色在左下且高度约为视口的 `18–22%`；右侧账户内容宽度不超过约 `440px`，整体垂直居中。山水、角色和圆弧不得越界进入账户区。微信登录是主入口，邮箱登录作为清晰但低一层级的备选；邮箱注册与找回密码只在邮箱路径中出现，不增加手机号入口。
- 微信小程序登录页以 `design-reference/21-mobile-auth-login.png` 作为认可页面参考，使用紧凑单列登录面，不照搬桌面左右分区。首屏只保留一个高强调操作：较矮的深青瓷绿“微信登录”按钮；邮箱登录以无边框的线性邮件图标与文字入口置于其下，清晰可见但不使用描边按钮、底色容器或说明文字与微信争夺层级。趴卧老己只出现一次，依附微信按钮上沿，不在品牌区重复头像或角色。
- Compact 登录页使用中性偏冷的象牙纸白作为主背景，粉色只用于老己角色；水墨采用低饱和青灰绿，并严格分为上方一段远山与亭子、中央大面积纸白留白、底部协议下方一段极淡远山，三段不连续铺满。不得把背景调成米黄、暖粉或偏红，不得纵向扩写成从上到下的满幅山景，也不使用独立水纹、强路径或高对比近景填补留白。
- Compact 登录页品牌字位于上部留白，标语固定为“亲爱的老己，爱你哟~”；标语使用低饱和青瓷灰绿，“邮箱登录”使用略深但仍去饱和的青灰绿，均不得使用鲜亮纯绿。协议置于登录区下方并保持可读，不增加“登录后同步”等解释文案。按钮视觉高度遵循参考图的紧凑比例，但实际触控命中区仍不得小于 `44px`。
- 微信身份尚未关联账户时，“绑定已有邮箱账户”和“暂不绑定”在微信登录后的关联流程中出现，二者层级清楚且均可继续流程，不得把绑定伪装成必选授权。

## 3. 布局与响应式

### 3.1 通用布局原语

- **应用外壳**：容纳全局导航和工作上下文，切换内容时保持稳定。
- **导航轨**：窄而稳定，底色使用比相邻侧栏更饱和的浅玉绿，并保留贴底的复古远山、树木与亭子背景；选中项再通过深绿图标、轮廓和略深背景共同表达。
- **辅助侧栏**：承载列表、目录或局部导航，以细分隔线连接主画布。
- **主画布**：承载当前主要任务，拥有最高视觉层级。
- **上下文面板**：宽屏并行展示相关内容；空间不足时进入次级视图或浮层。
- **内容列与网格**：正文限制行宽，网格根据最小项目宽度自适应列数。
- **浮动工具面**：只在与当前内容直接相关时出现，不长期遮挡正文。

优先使用“分组、对齐、留白、分隔线、浅背景”，最后才使用卡片和阴影。

宽屏已有常驻导航明确表达当前页面时，主画布可省略同名页面标题，直接从首个内容分组开始，并同步回收原页头占用的高度，不得留下明显空带；首个内容分组标题的文字基线应与宽导航中的“老己”字标基线对齐，允许约 `8px` 的视觉修正，不再使用独立页头高度占位。Compact 模式仍保留可理解的紧凑页头。

桌面导航轨允许通过边缘左右拖动在两档状态间吸附：窄态只显示图标，宽态显示图标与文字。默认不设置常驻收起按钮；分隔线悬停时显露拖拽反馈，双击可切换两档，键盘聚焦后可用方向键调整并用 Enter 切换。具体宽度和吸附阈值由实现按内容与视口确定。

### 3.2 主画布与上下文工作区

- 没有可并行操作的上下文时，主画布不为空面板预留宽度。
- 宽屏最多在主画布旁展示一个与当前内容直接相关的上下文工作区，不按能力继续增加固定列。
- 仅主画布与当前上下文工作区之间提供宽度调整。分隔线默认保持安静，悬停时扩大热区并显示拖拽反馈；双击在收起和上次使用宽度之间切换。
- 工作区拖到最小安全宽度以下时吸附为标明上下文类型和当前阶段的窄条；向外拖动或双击可恢复，并记住上次使用宽度。
- 不设置常驻收起按钮。分隔线可获得键盘焦点，方向键调整宽度，Enter 收起或恢复；状态变化不能只依赖颜色。
- 空间不足或操作会被遮挡时，桌宠可以暂时弱化或缩回对应端的召回入口：Wide / Medium 收回左上角头像，Compact 对话页沉入输入框并只露一个小发髻；不得擅自关闭用户正在编辑的工作区。

### 3.3 断点与跨端规则

| 模式 | 宽度 | 规则 |
| --- | --- | --- |
| Compact | `≤767px` | 单任务、单主列、触控优先 |
| Medium | `768–1199px` | 主画布常驻，辅助区域按空间折叠 |
| Wide | `≥1200px` | 允许相关上下文并行展示 |

| 维度 | Wide / Medium | Compact |
| --- | --- | --- |
| 主导航 | 常驻导航轨或侧栏 | 紧凑页头、底部导航或次级视图 |
| 内容组织 | 可并列相关面板 | 一次只显示一个主要任务 |
| 局部导航 | 可常驻辅助侧栏 | 全屏次级视图、抽屉或底部面板 |
| 操作密度 | 鼠标、键盘的紧凑布局 | 44px 触控目标和更大间隔 |
| 浮层 | 定位弹层、模态或侧面板 | 优先底部面板或全屏层 |

手机必须使用 `100dvh` 和安全区；键盘弹出后输入与主要操作仍可见。桌面侧栏不得简单堆叠到手机内容顶部，吸底操作区必须为滚动内容预留空间。

Compact 对话页打开会话导航时，以 `design-reference/11-mobile-conversation-drawer.png` 作为认可页面参考：抽屉从左侧覆盖主画布约 `84–88vw`，右侧保留少量被遮罩的上下文，抽屉右上与右下使用 `28–32px` 大圆角；顶部依次为紧凑品牌行、新建对话和搜索，最近会话作为单列连续内容流滚动，读书与设置固定在独立底部导航区。抽屉下部使用贴底的低对比远山、树木与亭子作为背景层，向上自然消隐，不占用内容高度、不进入可点击层，也不得遮挡会话文字、焦点轮廓或触控目标。

Compact 对话主画面以 `design-reference/13-mobile-conversation-shell.png` 作为认可页面参考：页头中央只显示一行通用会话名称，左侧保留会话导航入口，右侧不设置含义重复的新建或修改图标；书名、任务名、范围和阶段都不是固定页头结构。普通对话不显示任务阶段，只有进入明确的结构化任务时，才在对应消息上下文内呈现阶段与进度。消息、选择项、确认操作和吸底输入区保持清晰的单列层级，选择项、主操作与输入框使用更符合触屏的饱满圆角和留白；输入框左上角使用低存在感趴卧桌宠。主画面下部未被内容占用时可出现极低对比、贴底并向上消隐的远山与亭子，但不得置于正文、消息、按钮或触控目标背后。

Compact 统一书架以 `design-reference/14-mobile-reading-library.png` 作为认可页面参考：页头左侧保留会话导航入口，中央只显示“读书”，右侧使用图标与“导入”文字组成的明确操作；其下只保留一个全宽大圆角搜索框，不增加筛选、来源切换、同步时间或重复的书架标题。微信读书与本地书籍在连续双列封面网格中混排，阅读进度收在封面底部，书名保持一行，来源只用无底色小图标表达；页面不设置最近阅读大卡片、底部导航或浮动桌宠。正常内容态不在书籍背后铺设山亭，远山亭子只可在空状态或滚动末端的未占用空间中低对比出现。

Compact 设置总览以 `design-reference/22-mobile-settings-overview.png` 作为认可页面参考：页头左侧保留会话导航入口，中央只显示“设置”，右侧不增加操作；主体使用“账户 / 服务”两个短分组、开放式单列整行入口和细分隔线，不使用卡片或把桌面状态列压缩到手机。账户区直接显示“修改邮箱”和“修改密码”；服务区依次显示文本模型、图片模型和微信读书，当前状态以行尾单行次要文字配合细箭头表达，说明文案进入详情页。退出登录作为独立低频行置于服务列表之后。页面使用 `settings-paper` 中性纸白，不得套用更绿的 `bg`、`app-paper` 或浅青阅读预设；下部未被内容占用时可保留贴底、极低对比并向上消隐的远山与亭子，但不得上移、加深或填满留白。正常状态不放浮动桌宠或底部导航。

## 4. 通用组件

### 4.1 图标与操作

- 使用统一的成熟线性图标或本地 SVG，常规 `20px`，主导航 `22–24px`，描边约 `1.75–2px`。
- 不使用字符、Emoji、CSS 线框或圆点冒充正式图标；图标按钮必须有可访问名称。
- 按钮高度：桌面至少 `40px`，手机至少 `44px`；图标按钮触控区域至少 `44×44px`。
- 主按钮使用深绿实心和白字；次按钮使用白底、深色文字和细边框；破坏性操作使用错误色和明确文字。

### 4.2 表单与导航

- 输入框和选择器使用白底、8px 圆角和 1px 边框；手机高度至少 `44px`。
- 聚焦态使用 2px 强调色轮廓；错误信息靠近字段显示并保留原输入；占位符不能代替标签。
- 当前导航项同时改变背景或轮廓与图标颜色；不依赖悬停或单一颜色表达选中。
- 标签栏最小高度 `44px`；窄屏可横向滚动并自动显示当前项。
- 设置总览使用分组标题、整行入口和分隔线组织。Wide / Medium 的文本模型、图片模型与微信读书连接整行可点击，状态固定在中间列，行尾只使用一个无容器的细箭头表达进入详情，不再重复显示“修改配置”“配置”或“修改连接”；账户区使用一个“账户与登录方式”整行入口，再单独显示带退出图标的“退出登录”。Compact 按 `design-reference/22-mobile-settings-overview.png` 省略桌面说明列与汇总账户行，改为“修改邮箱 / 修改密码”和单行服务状态。所有整行入口必须支持键盘焦点和不小于 `44px` 的命中高度；Wide / Medium 悬停或聚焦时才显示 `accent-faint` 底色与焦点轮廓，Compact 必须提供按下反馈。总览不并列放置绑定、解绑、移除配置、断开连接或手动同步；只有进入对应流程后的保存、验证或确认等提交操作才使用实心主按钮。

### 4.3 列表、卡片与媒体

- 结构化列表优先使用行、分组标题和分隔线；卡片只用于独立选择、拖动、状态或预览对象。
- 选中卡片至少同时使用边框、浅背景和图标中的两种信号。
- 对话类列表行使用统一图标、标题和摘要，不预留固定封面位，也不因当前任务改变基础结构。必要状态和产物数量放在摘要或元信息位置。
- Compact 会话抽屉延续 `design-reference/11-mobile-conversation-drawer.png` 的无卡片列表、充足行间距和轻分隔节奏；当前会话仍使用统一会话图标，并以浅背景、左侧强调线或明确状态文字中的至少两种信号表达选中，不照搬图中的书签形标记或时间线圆点。
- 竖向封面优先保持 `5:7` 或原始比例，宽屏内容优先保持真实 `16:9`。
- 统一书架使用连续封面网格，不以来源拆分视觉分区。Compact 对照 `design-reference/14-mobile-reading-library.png` 使用双列封面，Wide / Medium 根据可用宽度增加列数；封面下方只保留一行书名，超出时省略并提供完整可访问名称，作者移入书籍详情。来源不使用常驻封面角标，默认在书名同一行末尾使用无底色的单色小图标并提供可访问名称；同名不同来源同时出现时才改用“微信”或“本地”短文字明确区分。阅读进度贴近封面底边呈现，不得遮挡封面主要文字或依赖颜色单独表达。
- 图片不得拉伸或放大失真；加载前保留稳定比例，避免布局跳动。
- 生成图片中的错字、伪 Logo 和不一致图标不得作为正式 UI 素材复用。

### 4.4 对话与异步运行态

- 当前会话的 AI 回答运行时，消息区在老己头像旁显示“老己正在思考…”或流式内容，发送按钮原位变为带可访问名称的“停止回答”控件；输入可保留草稿，但发送和附件提交不可用。
- 异步任务运行时，对话区使用一条稳定位置的原位状态，输入区附近显示可理解的锁定原因，发送按钮原位切换为明确的停止操作。
- 运行态不靠大面积置灰表达；状态文字、图标或形状与停止操作至少同时出现两种。
- “正在思考”使用低频的三点呼吸或小幅书页翻动反馈；减少动态效果时改为静态状态文字，不使用无限旋转的大型加载器。

### 4.5 对话内结构化选择

- 结构化选择控件直接附在对应消息下方，使问题、选项和结果保持同一上下文；不为每个简单选择弹出模态框。
- 待选择时，问题文案保留在老己消息气泡内，选项区在正文下方间隔 `12px` 直接展开；不再包一层外部重卡片，也不把选择器脱离问题单独放到页面其他位置。
- `2–6` 个清晰选项优先使用按钮组、单选或多选；短文案的 `2–3` 项可同行排列，`4–6` 项或较长文案使用两列或单列，手机统一改为单列。每组提供可理解的问题标题，必要时提供“其他”或直接输入出口，不把下拉框作为所有场景的默认形态。
- 单个选项使用白底、`1px` `border` 边框、`8px` 圆角和至少 `44px` 高度；选项内容左对齐，文案前可使用单选、复选或语义图标，不使用一排无差别胶囊。
- 需要确认或自由输入时，在原选项组下方显示紧凑主操作或行内输入，不另开模态框。
- 动态选择的可视状态遵循下表：

| 状态 | 视觉与反馈 |
| --- | --- |
| 默认 | 白底、`border` 边框、`text-primary` 文字，不用颜色预先暗示答案。 |
| 悬停 / 按下 | 底色切换为 `accent-faint`，边框使用 `accent-mid`；按下仅做轻微明度变化，不做明显缩放。 |
| 键盘聚焦 | 控件外显示 `2px` `accent` 焦点轮廓，不与选中状态混淆。 |
| 已选中 | `accent-soft` 底色、`accent` 边框和对勾或单选点同时出现，不只改文字颜色。 |
| 提交中 | 保留已选内容，禁止重复点击，原位显示“正在提交…”与低频动效；减少动态效果时只保留文字。 |
| 已确认 | 整组选项折叠为一行“已选择：…”，附对勾与“已确认”文字，不保留可点击的旧选项。 |
| 已更新 / 已失效 | 使用次要文字和“已更新”或“此选择已失效”明示，不再接受交互，也不仅靠置灰表达。 |

- 层级、多选、需要预览或较长说明的复杂选择进入当前任务工作区；手机优先使用全屏次级视图或底部面板，不强行把复杂内容塞进消息气泡。
- 工作区需要回看当前值时，使用标题、文本和值的轻量分组，不新增独立重卡片或重复边框。
- 选择控件必须支持键盘操作、可访问名称、清晰焦点和至少 `44×44px` 的触控目标。

### 4.6 PPT 阶段导航与范围工作区

- PPT 工作区顶部使用“范围与需求 / 大纲 / 模板 / 生成”四阶段水平步骤条。已完成阶段使用对勾与连线，当前阶段使用实心强调圆点和强调文字，未开始阶段使用中性描边；三种状态不得只靠颜色区分。
- Compact 模式不压缩完整步骤条，改为当前阶段名称与 `N / 4` 的紧凑进度头，并保留明确返回路径。
- “范围与需求”按轻量分组纵向排列：当前有效范围摘要置顶，`SPEC.md` 定义的固定字段置于其后；摘要不存在时不保留空容器，字段标签始终位于控件上方。
- 工作区底部使用稳定操作区：返回为次操作，推进当前阶段为唯一实心主操作；滚动内容需为操作区预留空间，不得遮挡最后一项。

### 4.7 层级大纲编辑器

- 大纲优先使用行式分层结构：每页为一级行，页标题直接编辑，要点在行内展开编辑；以细分隔线组织，不将每页做成独立重卡片。
- 页面之间在悬停或键盘聚焦时显示“插入一页”，列表末尾保留“新增一页”；展开页面后可添加要点。
- 结构操作的保存、失败和重试反馈使用原位置，避免打断编辑视线。
- 插入控件必须可键盘访问并具备可访问名称，不把悬停作为唯一入口。

### 4.8 模板选择

- 模板使用单列宽卡片展示，每项包含真实 `16:9` 预览、模板名称和一段简短风格说明；整项为同一选择目标，不拆成图片与文字两个点击区域。
- 选中项同时使用 `accent` 边框、`accent-faint` 底色和对勾；未选项保持白底细边框，不依赖预览图颜色表达选择状态。
- 模板列表可滚动，底部操作区保持稳定；图片模型提示放在操作区上方，以次要文字说明，不与模板卡片争夺层级。
- Compact 模式仍为单列，预览置于名称与说明上方；卡片、返回和开始生成操作均满足 `44×44px` 触控目标。

### 4.9 生成页面瀑布流

- 生成中、失败和完成态复用同一个单列大图瀑布流；页型内容保持真实比例，当前 PPT 页为 `16:9`，并尽量使用工作区可用宽度。
- 生成中只展示已经完成的完整页面与末尾一个同尺寸当前页骨架；尚未开始的页面不提前铺设空骨架，页数和当前进度固定在工作区顶部说明。
- 新完成页面原位替换当前页骨架，下一页骨架追加到瀑布流末尾，避免内容跳动。
- 失败提示覆盖或嵌入失败页的完整比例区域，已完成页面保持可见；恢复生成后从失败页原位继续，不清空或缩回为任务列表。
- 完成态连续展示全部大图页面，滚动即预览，不额外显示缩略图列表、轮播或分页器。
- 瀑布流背景使用 `surface` 或 `accent-faint` 与页面白底拉开层级；页码、生成状态和当前页轮廓使用深浅不同的绿色，不依赖阴影堆叠。

### 4.10 浮层与反馈

- 小范围操作使用定位弹层，集中输入使用模态，手机复杂任务使用全屏层。
- 底部面板必须有标题和明确关闭方式；拖拽指示不能成为唯一出口。
- Toast 只反馈短结果；需要阅读或操作的错误在原位置呈现。
- 进度、加载和失败占用稳定区域，已有内容不得因后续失败消失。

### 4.11 书籍详情、阅读与引用内容

- Wide / Medium 书籍详情顶部使用带真实封面的紧凑信息条。封面保持原始竖向比例，书名、作者和来源形成主次两层；简介和必要信息能在一至两行内完整展示时直接呈现，不显示“书籍信息”或收起入口。只有内容超过两行时才提供按需展开控件，且控件必须完整位于安全区域内、具备不小于 `44×44px` 的命中范围。信息条右侧始终保留一个轻量描边的“基于本书制作 PPT”入口；阅读标签内不在信息条重复显示全书进度。
- Compact 打开可提取正文的本地书籍时先显示书籍介绍首屏，并以 `design-reference/17-mobile-book-introduction.png` 作为认可页面参考：真实封面、书名、作者、来源、必要简介和一处轻量全书进度按同一灰绿纸白页面纵向组织，底部只使用低对比上滑指示和“上滑翻页阅读”说明，不出现实心或描边“继续阅读”按钮。介绍首屏与正文属于同一纵向分页阅读流；向上滑动后整张介绍页自然翻走并直接恢复全书上次位置，首次阅读从开头开始。正文以 `design-reference/15-mobile-reading-immersive.png` 作为默认沉浸态参考，一屏为一页，上滑前进、下滑返回，手势结束后吸附到完整页，避免停在跨页中间。正文不展示封面信息条，也不常驻“阅读 / 划线与想法 / 老己笔记 / PPT 作品”标签；正文默认占满安全区域，页头和底部工具栏均隐藏。轻点非链接、非选区的正文空白后，上下操作层以 `180–240ms` 淡入并轻微滑入，再次轻点、翻页或静置后收起。减少动态效果时只使用约 `140ms` 淡入淡出。
- Compact 操作层以 `design-reference/16-mobile-reading-controls.png` 作为认可页面参考：顶部只提供左侧返回、居中当前书名和右侧更多；底部阅读工具栏贴住安全区上沿，四个正式工具从左到右等距排列为目录、书籍内容、阅读设置、制作 PPT，使用成熟线性图标与简短标签，不增加“继续阅读”按钮，也不重复显示全书进度。“书籍内容”以移动端大圆角底部面板承载“划线与想法 / 老己笔记 / PPT 作品”三项切换及对应内容，三种状态分别以 `design-reference/18-mobile-book-content-highlights.png`、`19-mobile-book-content-notes.png`、`20-mobile-book-content-ppt-works.png` 为认可页面参考；面板顶部保留拖拽指示和明确关闭方式，内容区独立滚动且不覆盖固定底部工具栏。阅读设置使用同类底部面板统一承载五种背景、字号及相关可读性选项。

- 书籍详情和阅读页的正文复古感只来自宋体、冷调纸面背景与极低对比边缘纹理；应用左侧导航仍保留与完整视觉定稿一致的低对比、低饱和远山、树木与亭子，近景收在底部约三分之一，向上只延伸非常浅的远山和雾气。近景不得上移覆盖导航项，水墨场景也不得进入内容列、形成主画布大插画或与封面、正文争夺视觉焦点。

## 5. 状态、动效与无障碍

### 5.1 状态

所有数据区域区分初次加载、真实空数据、搜索或筛选为空、请求失败和正常内容，并保持相同内容骨架。加载和失败不得先闪现为空数据。

组件必须覆盖默认、悬停、聚焦、按下、选中、禁用、加载、成功和错误状态；手机不需要悬停，但必须有按下反馈。

### 5.2 动效

- 即时反馈 `120–180ms`，面板与视图切换 `180–240ms`。
- 推荐缓动：`cubic-bezier(.2,.8,.2,1)`。
- 动效只解释层级、来源和状态变化，不做持续装饰运动。
- 桌宠可以在同一固定槽位内低频切换站立、坐下、趴卧和躺下，每次只保持一种待机姿态，不按短周期机械循环。Compact 对话输入区默认使用趴卧持书的注意姿态；用户操作、任务运行、错误出现或空间不足时回到适合当前空间的注意姿态或召回入口。
- 姿态切换只使用轻微位移、缩放和交叉淡入淡出，不改变槽位尺寸；眨眼、呼吸、轻摆和点击回应保持低频。对话页不通过提示气泡宣称不存在的导航功能。
- Wide / Medium 关闭桌宠使用约 `220ms` 的收缩与曲线路径移入左上角头像，头像做一次轻微回应；Compact 对话页使用约 `180–220ms` 的纵向下沉与输入框裁切，只留下一个小发髻，召回均沿反向路径展开，不使用拖尾粒子。
- 尊重 `prefers-reduced-motion`；减少动态效果时取消位移、缩放、曲线路径和姿态位移，关闭与召回改为约 `140ms` 淡入淡出。

### 5.3 无障碍

- 正文和关键控件对比度至少 `4.5:1`，大号文字至少 `3:1`。
- 键盘焦点始终可见，焦点顺序与视觉顺序一致。
- 触控目标不小于 `44×44px`，状态不只靠颜色表达。
- 200% 文本缩放、长标题和系统字体放大时仍能完成主要操作。
- 不使用固定高度裁切动态文字；多栏内容在窄屏重新组织，而不是整体缩小。
