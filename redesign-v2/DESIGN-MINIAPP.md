# 老己微信小程序视觉规范

- 状态：v2 微信小程序当前视觉事实源
- 上位共享规则：[`DESIGN.md`](DESIGN.md)
- 产品行为：[`SPEC.md`](SPEC.md)

## 1. 范围与原则

本文只定义微信小程序的页面布局、触控交互、系统安全区、组件形态、页面参考和视觉验收。项目不再把移动网页作为 MVP 必交付端，也不使用断点术语代替“微信小程序”这一客户端名称。

- 一次只呈现一个主要任务；复杂内容使用全屏次级页、抽屉或底部面板。
- “单任务”不等于所有内容只能单列。封面、模板和 PPT 作品等视觉选择可按已确认规则使用双列网格。
- 操作适配触控、键盘弹出和系统安全区；不能把桌面侧栏、密集工具条或小圆角控件机械缩小后搬入小程序。

## 2. 页面基础

### 2.1 安全区与布局

- 页面内容覆盖当前小程序可用窗口并适配顶部状态区、右上系统区域、底部手势区和键盘；吸底操作必须位于安全区之上。
- 页面水平留白 `16–20px`；滚动内容为吸底按钮、工具栏和底部面板预留空间。
- 会话输入、阅读工具栏、PPT 主操作与其上方滚动内容共用“安全区之上稳定底边”关系；键盘只改变可用高度，不改变发送、主操作、桌宠可见锚点或工具栏的底边语义，也不得让内容滚动到吸底层之下。
- 小控件圆角 `10–12px`，主要操作面 `16–20px`，会话输入框 `24–28px`，抽屉与底部面板 `24–32px`。
- 主要操作可以使用饱满大圆角或胶囊轮廓；同一操作组只保留一个高强调按钮。
- 主操作默认使用深青瓷绿；允许使用克制的同色系明度渐变，但不得加入第二色相、霓虹光带或重阴影。
- 所有主要触控区域不小于 `44×44px`，按下状态必须可见。

### 2.2 页面背景与纸面

- 小程序以中性偏冷的纸白、极低饱和灰绿和大面积留白为主，不把桌面左侧导航背景铺满页面。
- 远山、树木与亭子只出现在未被内容占用的顶部、底部或空状态区域，并保持低对比、贴边和向内容区自然消隐。
- 抽屉、登录、设置与会话的山亭落款只能使用在参考索引中另行确认的微信小程序透明运行时资产；桌面山亭资产、参考截图裁片、CSS 山形、临时 SVG 或通用渐变均不能替代。
- 阅读正文可以全页使用极淡细密纸纹，中心区弱于边缘，不形成可辨认花纹。

### 2.3 页头与返回

- 页头使用左侧返回或会话菜单、居中单行标题和必要时的右侧单一操作，不放置含义重复的图标。
- PPT 流程中的返回箭头始终返回上一个阶段或上一个界面，并保留当前已保存内容；它不是“返回会话”。
- 需要关闭的底部面板同时提供明确关闭按钮；拖拽指示不能成为唯一出口。
- 尚未接入真实服务时，只在相关操作附近使用一条短说明“开发适配器 · 仅当前运行内存；真实能力尚未接入”；可用控件只能触发确定性本地状态，其他控件明确禁用或说明边界，不显示伪 AI、伪下载或伪成功结果。

## 3. 会话与导航

### 3.1 会话抽屉

- 会话抽屉从左侧覆盖主画布约 `84–88vw`，右上与右下使用 `28–32px` 大圆角，右侧保留少量被遮罩上下文。
- 顶部依次为紧凑品牌行、新建对话和搜索；最近会话以无卡片单列内容流滚动，读书与设置固定在独立底部导航区。
- 当前会话使用浅背景、左侧强调线或明确状态文字中的至少两种信号表达选中，不照搬书签标记或时间线圆点。
- 下部远山亭子贴底并向上消隐，不占用列表高度或进入可点击层。

### 3.2 会话主画面与输入区

- 通用会话外壳以 `design-reference/13-mobile-conversation-shell.png` 为准；底部半屏多选、确认后普通输入和图片附件输入分别以 `30-mobile-conversation-selection-sheet.png`、`31-mobile-conversation-confirmed-input.png`、`32-mobile-conversation-image-attachments.png` 为认可局部参考。局部状态与 13 冲突时以 30–32 为准，各图的采用点和不得照搬项只查参考索引。
- 页头中央只显示一行通用会话名称；书名、任务名、范围和阶段不作为固定页头内容。
- 普通对话不显示任务阶段；只有明确结构化任务才在相关消息上下文内显示阶段。
- 消息、结构化选择和吸底输入区保持清晰的单任务层级；多选不再直接铺在聊天消息中，也不把桌面复选卡片缩窄后塞进对话流。
- AI 提问后使用微信小程序底部半屏选择层承载多选。选择层从屏幕底部覆盖进入，不推动消息列表或输入框，不改变桌宠和输入框锚点；关闭时回到原会话位置。
- 选择层使用单一连续表面、约 `24px` 顶部圆角、轻量标题和开放式列表。选项为约 `56px` 高的整行触控目标，以留白和细分隔线组织；默认不使用整行色块、独立卡片、胶囊标签或圆形伪单选控件。
- 选中状态使用成熟复选图标与文字状态，不依赖整行背景色；底部安全区内仅保留一个大圆角“确认”主操作，无“已选 N 项”、无“继续”。没有勾选时确认不可用，拖动下滑或点击遮罩关闭时保留当前勾选。
- 确认后选择层关闭，对话中只回写一条简洁范围摘要；提问消息后的低强调“选择范围”入口用于再次打开，不把摘要继续做成可勾选卡片。
- 会话输入框初始视觉高度约 `56–64px`，内容增加后再向上扩展；不得以大块空白文本框长期挤占消息区域。
- 输入框左侧提供独立图片入口，图标视觉约 `20–24px`、完整触控目标不小于 `44×44px`；因为 MVP 仅支持图片附件，不使用含义过宽的文件回形针。点击后可从相册选择或直接拍摄，单条消息最多 `4` 张。
- 已选图片以 `56–64px` 方形缩略图在文字输入行上方排列，不在输入区显示 `2 / 4` 等容量计数；最多 `4` 张的限制由相册 / 拍摄选择器直接执行，达到上限时禁止继续选择并给出轻提示。
- 每张缩略图右上使用浅色半透明圆底和细线关闭图标，视觉尺寸约 `20–22px`、完整移除命中区不小于 `44×44px`；禁止黑色实心圆底、粗重叉号或把删除控件挤入图片之间，不提供拖动排序。
- 图片与文字共用原发送操作。存在附件时输入面只向上扩展，底边、安全区和发送按钮锚点保持不变；不得把整个输入框继续向下移动或裁掉桌宠。
- 输入框左上使用低存在感趴卧持书桌宠：微歪头、双臂趴靠上沿、双手扶小书，只露头部与少量上半身。
- 桌宠定位以透明 PNG 中“可见双臂 / 书本下缘”贴合输入框上边线为基准；透明画布边界和固定 `bottom` 值不得作为视觉锚点。输入增长、附件和键盘切换时，该可见锚点相对输入框的偏差保持在 `2px` 内。
- 键盘弹出或输入框向上扩展时，桌宠继续完整趴靠在输入框左上沿，不随附件条下移或被缩略图裁切；只有真实可用高度不足时才沿输入框后方下沉，并至少保留可召回的小发髻。透明命中区仍不小于 `44×44px`。
- 桌宠与输入面属于同一视觉组合并覆盖在输入边界上层；输入框不得保留第二条旧边界或让描边从角色身体下方穿过。桌宠不形成新的输入按钮，不遮挡消息、文字、图片入口、缩略图、移除操作、发送或键盘安全区。
- 图片选择、上传或发送失败时在输入面上方就近显示原因，保留文字和全部已选缩略图；当前文本模型不支持图片时，发送前提示并保持输入区可编辑。

### 3.3 免费体验与模型配置引导

- 符合领取条件的新账户只在登录后的对话首页内容流顶部显示一条轻量卡片条，不增加首次配置向导、独立领取卡、全屏领取页、底部弹窗、积分入口或会话抽屉常驻入口。
- 卡片条遵循页面 `16–20px` 水平留白，高约 `56–64px`，使用共享 `benefit-soft` 暖纸底、`benefit-accent` 细色边与小型成熟线性礼物图标、约 `12px` 圆角和极轻投影；“免费体验额度”使用中等字重，“领取”使用品牌墨绿实心按钮。不得放说明、金额、余额、进度、倒计时、插画或多枚状态标签。
- 点击“领取”后原位短暂显示“已领取”，随后整条提示移除且不保留空位；领取后不在输入区、PPT 阶段页头或其他页面常驻显示额度状态。
- 体验不可用或已完成后，用户触发新的 AI 操作且未配置文本模型时，在输入面上方或当前 PPT 阶段操作区就近显示“配置自己的 AI 模型后继续”和唯一主操作“配置 AI 模型”；不得在页面打开时主动弹窗。
- 点击“配置 AI 模型”进入全屏次级配置页，返回后恢复原输入、会话滚动位置和任务阶段。领取、重试或跳转失败均原位反馈，不清空输入或体验草稿。
- 全屏配置页的 `API Key` 使用带显隐操作的密文输入并适配键盘安全区，“检测并保存”是唯一吸底主操作。验证失败在字段下说明并保留输入；成功后返回原位置并显示“已配置，可继续”，但不自动发送原消息或启动原任务。

## 4. 登录、书架与设置

### 4.1 登录

- 登录页以 `design-reference/21-mobile-auth-login.png` 为认可页面参考，使用单列层级，不照搬桌面左右分区。
- 微信登录是唯一高强调操作；邮箱登录位于其下，使用无边框线性图标与文字入口。
- 趴卧老己只出现一次并依附微信按钮上沿；背景分为上方低对比山亭、中央大面积纸白和协议下方极淡远山。
- 登录页使用 `DESIGN.md` 规定的共享标语，不另设端侧文案；背景不得偏米黄、暖粉或红色。

### 4.2 统一书架

- 页头左侧为会话菜单，中央为“读书”，右侧为图标加“导入”的明确操作。
- 页头下只保留一个全宽大圆角搜索框，不增加来源筛选、同步时间或重复标题。
- 未连接微信读书时，在搜索框下、书籍网格前放置低强调服务行“连接微信读书”；连接成功后服务行消失。
- 微信读书与本地书籍在连续书籍封面网格中混排；`430px` 视口使用 3 列，单卡约 `120px`、列间距 `16px`，`360px` / `390px` 视口使用 2 列；封面底部显示阅读进度，封面下只保留一行书名和无底色来源小图标。所有本地导入书籍统一使用同一套 `5:7` 动态默认封面模板，不展示原文件封面；封面内显示书名和作者，作者缺失时显示“作者未知”。微信读书书籍继续使用同步得到的真实封面。
- 不设置最近阅读大卡片、来源分区、底部导航或浮动桌宠；远山亭子只可出现在空状态或滚动末端未占用空间。

### 4.3 设置总览

- 页头只保留会话菜单和“设置”；主体使用“账户 / 服务”两个短分组、开放式单列入口和细分隔线。
- 账户区直接显示“修改邮箱”和“修改密码”；服务区依次显示文本模型、图片模型和微信读书，状态以行尾单行次要文字配合细箭头表达。
- 说明进入详情页，不把桌面说明列压入小程序；退出登录作为独立低频行置于服务列表之后。
- 页面使用 `settings-paper`，正常状态不放浮动桌宠或底部导航；下部远山亭子保持极低对比与充足留白。

## 5. 微信小程序 PPT 流程

本流程以 `design-reference/23-mobile-ppt-range-requirements.png` 至 `29-mobile-ppt-complete.png` 为认可页面参考，依次覆盖范围与需求、大纲、编辑大纲、模板选择、生成中、生成失败和生成完成；各图的采用点、不得照搬项与 Figma 原稿链接只以 `design-reference/README.md` 为准。

### 5.1 阶段头与操作区

- 四个阶段分别显示为“范围与需求 · 1 / 4”“大纲 · 2 / 4”“选择模板 · 3 / 4”“生成 PPT · 4 / 4”。
- 阶段名称与进度保持同一紧凑页头，不显示桌面水平步骤条，也不挤压主要内容。
- 生成阶段在页头下方使用一行轻量状态“正在生成第 N / 总页数页”；不增加第二套进度条。
- 底部使用稳定吸底操作区；主操作使用小程序大圆角，滚动内容必须完整露出最后一项。
- “范围与需求”存在个性化范围时，内容区先显示“已确认范围”轻量摘要，再显示用途、受众、页数范围和补充要求；不在摘要前重复解释页面用途，也不保留范围来源或提交结果等辅助文案，底部主操作统一为“确认”。
- 通用需求采用字段标签在上、控件在下的轻量混合表单，不使用整张设置卡片、行分割线或设置项式右箭头。用途和受众使用带下拉指示的选择框并支持自定义，页数范围直接提供“6–8 页 / 8–10 页 / 10–12 页 / 自定义”四个并列选项，补充要求使用多行输入框。

### 5.2 大纲预览与编辑

- 大纲预览直接展示页面、一级要点和二级说明的分层结构，不要求用户看到格式工具栏。
- 点击“编辑大纲”后打开接近全屏的高位底部面板；面板标题为“编辑大纲”，提供明确关闭按钮。
- 编辑体验采用类似飞书文档的连续分层文本编辑：点击文字直接出现光标与键盘，页面、要点和说明由段落层级判定。
- 换行默认沿用当前层级；缩进进入子层级，退格在段首回退层级，删除空段落即删除对应结构；用户不需要手动选择字号、项目符号或格式模板。
- 编辑面板不显示页卡、页操作按钮或独立页面列表；不提供针对页面、要点或页面结构的独立操作按钮语义，也不显示格式工具栏或上下文工具条。
- 子段落失去所属页面层级时，在原段落位置提示“需要页面层级才能确认大纲”，并阻止确认；恢复层级后才可继续。
- 编辑内容以 `300–500ms` 防抖自动保存；状态只显示“保存中 / 已保存 / 保存失败 · 重试”。保存失败不得先关闭面板，必须保留文字、光标和当前滚动位置并在原位置重试。
- 完成编辑后返回大纲预览；推进按钮使用“确认大纲并选择模板”，不在同一操作组并列“复制”等非核心操作。

### 5.3 模板选择

- 模板使用双列网格，每项只显示真实 `16:9` 封面预览；模板名称直接作为封面标题，不在封面内或封面外再增加独立名称标签，也不显示可见风格说明。
- 整张封面与名称属于同一选择目标；选中项同时使用强调边框、浅强调底色和对勾。
- 模板列表独立滚动，底部“开始生成 PPT”保持稳定；页面不显示图片模型未配置说明。

### 5.4 生成中、失败与完成

- 生成中使用单列大图瀑布流；已完成页面按顺序显示，末尾只保留一个同尺寸当前页骨架，所有页面保持 `16:9`。
- 新页面完成后只在用户停留于末尾时自动跟随；用户向上查看时不得抢夺滚动位置。
- 失败页原位保留完整 `16:9` 区域和此前已完成页面；右上角低频菜单提供“删除任务”，二次确认后只清理当前失败任务及其临时已完成页面，不影响会话、书籍或历史作品，删除后不可重试；主要操作仍为“重新生成”和“修改大纲”。
- “重新生成”从失败页继续，不重复已完成页面、不创建重复任务；不在界面上拆分图片服务、模板视觉或内部重试策略。
- 完成态继续使用同一瀑布流；“下载 PPTX”是唯一主操作，更换模板和修改大纲使用次级操作。
- 更换模板或修改大纲后再次生成会创建独立作品，不覆盖当前作品。
- “下载 PPTX”保持唯一主操作；其附近只显示一行低强调说明“可在 PowerPoint 或 WPS 中继续编辑”，不增加下载前确认弹窗。

## 6. 本地阅读与书籍内容

### 6.1 介绍首屏与正文

- 可提取正文的本地书籍先显示 `design-reference/17-mobile-book-introduction.png` 所示介绍首屏：动态默认封面、书名、作者、来源、必要简介、轻量全书进度和“上滑开始阅读”。
- 介绍首屏按可用高度流式收紧封面、间距与简介长度，不只按宽度适配；常见短屏仍须在一屏内保留封面、书名、作者、来源、至少一句完整必要简介、轻量进度和预留的底部提示槽。更长简介紧接提示后的同一连续内容流自然展开，不得用分页、吸附、行数截断、省略号或 `overflow` 裁字换取单屏构图。
- 介绍首屏不设置“继续阅读”按钮；“上滑开始阅读”使用低对比向上动效，不是固定图片。首次有效上滑后提示淡出，并在当前阅读会话不再出现；减少动态效果时改为静态提示与快速淡出。介绍内容随后自然滚出并进入正文，正文恢复全书上次位置，首次从开头开始。
- 正文以 `design-reference/15-mobile-reading-immersive.png` 的排版和沉浸层级为默认状态，采用自然连续的纵向滚动，不按屏强制分页，也不做整页吸附；动态字号、章节长度和系统字体变化不得造成断页或跳位。
- 正文默认隐藏页头、工具栏、桌宠和气泡；轻点非交互区域后呼出操作层，再次轻点、继续滚动或静置后收起。

### 6.2 阅读操作层

- 顶部只显示返回、当前书名和更多；底部工具栏从左到右等距排列目录、书籍内容、阅读设置、制作 PPT。
- “书籍内容”使用大圆角底部面板承载“划线与想法 / 老己笔记 / PPT 作品”，对应参考图为 18、19、20。
- 面板底边位于包含安全区的底部工具栏实际占高之上，最大高度只使用扣除顶部系统区、顶部操作层和工具栏后的可用窗口；只有面板内容独立滚动，底部工具栏始终完整可见。面板提供标题、拖拽指示和明确关闭按钮。
- 工具栏右侧上沿显示小尺寸趴卧桌宠和约 `44px` 墨绿色圆形对话按钮，两者间距 `6–8px`，不占用四个工具位置。桌宠同样以透明素材的可见下缘贴合工具栏上边线为锚，浅 / 深背景、不同安全区和工具栏高度下不得改用透明画布边界定位。
- 阅读设置以同类底部面板提供浅色与暗色两种阅读背景；首次默认浅色，后续恢复用户最近一次选择。

### 6.3 内容组织

- 正文选中后的“划线 / 写想法 / 和老己聊聊”使用从 30 号参考的连续底部表面最小派生的紧凑操作层，不做临时悬浮气泡或独立卡片；三项均为至少 `44×44px` 的同级操作，操作层不得遮住所选正文，关闭或失败时保留选区与当前滚动位置。
- 划线与想法、老己笔记使用单列全宽内容流、充分留白和细分隔线，不为每条内容增加独立卡片。
- 老己笔记标签在内容流上方保留一个轻量“新建笔记”主操作；编辑器只从 25 号参考派生接近全屏的高位底部表面、明确关闭和安全区内保存操作，不继承 PPT 层级结构或格式工具栏。笔记正文没有标题字段，可选引用只读；保存失败保留正文、引用和滚动位置并原位重试。
- PPT 作品使用紧凑双列 `16:9` 网格；生成中与已完成项保持同一预览比例，下载为行尾独立图标操作。
- 书籍内容面板支持动态高度、内容滚动、系统安全区和五类数据状态，不按参考图固定裁切。

## 7. 动效与验收

- 页面与底部面板切换使用 `180–240ms` 淡入并轻微位移；减少动态效果时改为约 `140ms` 淡入淡出。
- 阅读滚动、抽屉、键盘和吸底操作不得造成内容跳动或遮挡当前焦点。
- 冻结候选至少覆盖 `320×568` 短屏、`360×640` Android、`390×844` iOS 与 `430×932` iOS，并检查短 / 常规 / 长高度、顶部系统区、右上胶囊、底部手势区、键盘打开 / 关闭、系统字体 `15 / 17 / 23 / 26` 和减少动态效果开 / 关。
- 检查无横向溢出、固定高度裁切、按钮遮挡、内容被底部操作覆盖和触控目标重叠。
- 检查书籍封面列数、双列模板和双列 PPT 作品在长名称下仍保持稳定；列数不改变“每次只完成一个主要任务”的页面层级。
- 微信小程序参考图只约束索引列出的布局、视觉节奏和采用点；图像模型生成的文字、头像、桌宠、图标和整张截图均不得直接作为运行时界面素材。
