# 老己 MVP 产品规格

> 本文只定义产品目标、功能、流程、状态与验收。视觉从 `DESIGN.md` 进入，并按客户端读取对应端侧规范。

## 1. 产品目标

老己是一个以对话为入口的个人书库与任务工具，帮助用户整理自己的阅读内容与笔记，并在同一会话中调用可持续扩展的任务能力。MVP 首个任务能力是基于一本书生成可编辑的成品 PPTX。

MVP 核心闭环：

`同步或导入书籍 → 阅读与记录 → 从对话或书籍发起 PPT → 确认范围、需求、大纲和模板 → 生成并下载 PPTX`

### 1.1 MVP 包含

- 统一账户、微信登录、邮箱备选登录与基础会话。
- 微信读书同步、本地书籍导入和统一书架。
- 查看可用书籍内容、个人同步内容与老己笔记。
- 从对话和书籍详情进入同一套 MVP 单书 PPT 流程。
- PPT 草稿恢复、内置风格选择、生成失败重试、作品查看与下载。
- 新账户无需配置文本模型即可领取一笔受限的免费体验额度。
- 桌面 Web 与微信小程序完成相同核心闭环。

### 1.2 暂不包含

- 头像、昵称、账号注销等通用资料管理；MVP 只提供修改邮箱、修改密码以及微信与邮箱登录方式的必要绑定管理。
- 会话重命名、书友笔记和公开观点。
- 多书或通用主题 PPT、PPT 以外的新增任务能力、协作、社交、付费。
- 本地书籍删除、回收站及复杂格式编辑能力。
- 老己内的逐页 PPT 编辑；内容大改时返回大纲并重新生成独立作品。

## 2. 核心对象与导航

| 对象 | 说明 |
| --- | --- |
| 账户 | 稳定的用户身份及其微信、邮箱登录方式、服务配置和同步状态。 |
| 会话 | 统一承载消息、输入草稿、上下文和任务记录；不因当前书籍、入口或任务类型形成不同会话类型。 |
| 任务 | 在会话中发起的阶段性工作，包含任务类型、资料来源集合、阶段、运行状态和产物；MVP 只实现 PPT 任务，后续可增加其他任务能力。 |
| 书籍 | 来源为微信读书或本地导入；同名不同来源不合并。 |
| 书籍内容 | 微信读书同步到的个人内容，或本地书籍可提取的内容；原文只读。 |
| 老己笔记 | 用户按书保存的笔记，可独立记录、引用原文或由老己根据对话整理生成。 |
| PPT 草稿 | PPT 任务最终提交前的范围、需求、大纲和模板，仅存在于发起会话。 |
| PPT 作品 | PPT 任务成功生成的独立产物，可在原会话和相关书籍中找回。 |

一级导航固定为：`对话 / 读书 / 设置`。PPT 不是独立一级入口。

通用任务是产品对象边界，不是要求 MVP 提前展示“任务中心”或空的通用入口；只有用户实际发起已支持的任务能力时，才出现对应工作区和状态。

## 3. 全局规则

- 文本模型、图片模型和微信读书连接相互独立；未配置某项时仍可使用不依赖它的功能。
- 刷新、切换页面或临时失败不得丢失已保存内容和关键输入。
- 重试不得重复创建任务，过期请求不得覆盖较新的状态。
- 数据区域必须区分加载、真实空、筛选空、失败和正常内容。
- 桌面 Web 与微信小程序共享业务规则；只有登录同一账户时才共享数据状态，具体布局遵循共享视觉规范和对应端侧规范。

## 4. 核心功能

### 4.1 账户与会话

- 桌面 Web 与微信小程序都以微信登录为主入口，同时保留邮箱注册、登录和找回密码；微信小程序首屏将邮箱登录作为低一层级的备选入口，不与微信登录并列争夺主操作。MVP 不提供手机号登录。
- 微信身份已经关联老己账户时直接进入该账户；尚未关联时，用户可以验证并绑定已有邮箱账户，也可以暂不绑定并使用微信创建独立账户，不得强制绑定。绑定仅允许发生在待关联的一侧为空时；两个已有账户均含数据时必须拒绝绑定，MVP 不提供自动或手动合并，用户只能保持独立账户。
- 绑定微信与邮箱后，两种登录方式进入同一账户，书籍、会话、任务、笔记和作品随该账户跨端同步；未绑定时，微信账户与邮箱账户彼此独立，不共享或自动复制数据。
- 用户登录后可在设置中修改邮箱与密码；修改邮箱必须验证新邮箱，修改密码必须验证当前账户身份。绑定已有邮箱账户仍必须重新验证该邮箱并明确确认，账户关系和数据归属在设置中可见。
- 邮箱注册成功或使用微信创建独立账户后直接进入产品，不设置首次配置向导。
- 新账户尚未领取时，只在登录后的对话首页提供一次性“免费体验额度 / 领取”入口；不扩展为独立领取中心、积分或券体系，也不展示金额、余额、进度、倒计时、过期时间或充值入口。具体视觉表现由 `DESIGN.md` 和目标端规范定义。
- 点击“领取”后短暂反馈“已领取”，整条提示随即消失；领取后不常驻展示剩余额度、使用状态或领取记录。
- 免费体验额度可用于 AI 对话或 PPT 生成，不绑定某一份 PPT。后台按账户累计平台模型与联网调用产生的实际成本，达到 `¥5` 硬上限后停止使用平台能力；桌面 Web 与微信小程序登录同一账户时共享领取与成本状态。
- 领取中断、平台能力暂不可用或全站预算限制触发时保留领取状态、输入、会话上下文和 PPT 草稿，并允许稍后重试。额度耗尽后，用户下一次发起需要文本模型的操作且仍未配置自己的模型时，才在当前输入或任务位置提示“配置自己的 AI 模型后继续”，并提供“配置 AI 模型”主操作。
- 支持新建、切换和删除会话；各会话独立保存输入、上下文、任务草稿和任务记录，但这些状态不形成不同会话类型。
- 会话列表统一使用会话图标、标题、最后消息摘要和必要的任务状态或产物数量，不使用书籍封面代表整个会话。
- 对话中识别到任务意图后沿用当前会话；MVP 识别 PPT 意图，资料来源不明确时先让用户选择。
- 微信小程序中的结构化多选使用独立确认界面，不把可编辑多选控件长期留在聊天历史中；确认后回写范围摘要，主动关闭时保留当前勾选并允许重新进入。具体界面形态由 `DESIGN-MINIAPP.md` 定义。
- 切换书籍、发起新的 PPT 或未来新增其他任务能力都不自动新建会话；是否新建会话只由用户主动决定。
- 同一会话内任一 AI 回答或任务正在运行时，不接受新的消息发送；用户可保留输入草稿，但必须先停止当前回答或任务才能发送。
- 任务互斥只作用于当前会话；用户切换到其他没有运行任务的会话后仍可正常发送消息。
- AI 回答或任务进度使用单条状态原位更新，不按内部进度高频追加重复消息；只有需要用户理解或确认的阶段结果才进入消息历史。
- AI 回答或任务完成、停止或失败后立即恢复当前会话发送；用户可在原会话继续提出任何后续请求。
- 除当前账户已领取且仍有可用免费体验额度外，发送 AI 对话前必须配置可用的文本模型；未配置或调用失败时保留输入和上下文。
- 会话消息支持文字与图片共同发送；单条消息最多附加 `4` 张图片，发送前可逐张移除，MVP 不提供附件排序或图片以外的文件类型。微信小程序同时支持从相册选择和直接拍摄；桌面 Web 使用本地图片选择。
- 含图片的消息由当前文本模型执行图片理解，不调用用于 PPT 配图的图片模型。当前文本模型不支持图片输入时，在发送前明确提示并保留文字与已选图片；图片选择、上传或发送失败时同样保留完整草稿，允许重试或移除失败图片。
- 删除会话会删除其中尚未提交的任务草稿，但不删除已启动任务和作品。
- 老己桌宠支持关闭和再次召回，不允许自由拖动；关闭时收回左上角老己头像，点击头像可再次召回。在对话页面只承担陪伴作用，不提供重复的对话入口，在读书、设置等非对话页面才可作为进入对话的快捷入口。

### 4.2 书籍与笔记

- 书架统一展示微信读书同步书籍和本地导入书籍，并支持搜索已有书籍。
- 两类来源在同一个连续书籍网格中混排，不按来源分区、分页或默认筛选；书籍来源必须可辨认，同名不同来源不得误合并。
- 尚未配置有效微信读书 API Key 时，桌面 Web 与微信小程序均在书架提供“连接微信读书”入口；连接成功后入口消失，正常自动同步状态不显示同步按钮或上次同步时间，连接修改统一进入设置。入口位置与视觉层级由目标端规范定义。
- 本地导入统一视为本地书籍；格式识别和解析差异只属于技术实现，不形成不同产品流程。
- 本地书籍的原始文件、解析结果、书籍信息、阅读进度、划线和老己笔记保存到用户账户，并在登录同一账户的桌面 Web 与微信小程序之间同步。
- 系统尽可能提取书名、作者、目录和正文；实际能力取决于可提取内容。本地导入书籍不使用原文件封面作为产品封面。
- 所有本地导入书籍统一使用同一套动态默认封面模板，封面内直接显示书名和作者；作者无法提取时显示“作者未知”。微信读书同步书籍继续使用同步得到的真实封面。
- 可提取正文时，提供统一的阅读、导航、进度恢复、复制、划线和笔记体验。
- 桌面 Web 书籍详情展示封面和必要书籍信息，同时保证阅读、划线、想法、老己笔记和作品内容可用；长简介的布局与展开方式由 `DESIGN-WEB.md` 定义。
- 微信小程序打开可提取正文的本地书籍时，先显示书籍介绍，再通过上滑进入纵向分页正文并恢复全书上次位置，首次阅读从开头开始；不增加“继续阅读”按钮。上下翻页、整页吸附和按需呼出阅读操作属于产品交互要求，具体手势提示、页头、工具栏与视觉状态由 `DESIGN-MINIAPP.md` 定义。
- 微信小程序本地阅读提供目录、书籍内容、阅读设置、基于本书制作 PPT 和进入当前会话的能力；“划线与想法”“老己笔记”和“PPT 作品”都能从当前书籍访问。微信读书没有完整正文，因此不进入本地沉浸式阅读流程，只展示已同步的个人划线与想法。工具排列、面板和桌宠关系由 `DESIGN-MINIAPP.md` 定义。
- 本地书籍进入阅读时自动恢复全书上次停留位置，首次阅读从开头开始；只维护全书连续阅读进度，不保存或展示每章独立进度，也不设置“继续阅读本章”等重复入口。
- 本地阅读默认不常驻展示目录；用户需要跨章节导航时可按需呼出目录，选择章节后返回正文并定位到对应位置。
- 本地阅读支持专注模式，进入后隐藏与阅读无关的应用外壳，但仍保留目录、阅读背景和清晰退出路径；提供浅色与暗色阅读背景并记住最近一次选择。背景覆盖范围与视觉表现由目标端规范定义。
- 用户选中正文后可直接划线、写想法或将所选原文作为引用带入当前会话与老己讨论；划线与选中状态的可辨认方式由视觉规范定义。
- 只能提取图片或页面时，仍可浏览并创建独立笔记；无法读取时明确失败原因。
- 微信读书仅展示已同步的个人划线和想法，不在老己内提供完整原文阅读。
- 微信读书和本地书籍的划线与想法都展示引用内容；存在可靠定位信息时才显示位置，无法识别时不显示空定位或虚构位置。本地书籍的可用定位可以返回原文，微信读书定位只展示同步信息且不可跳转；列表布局与操作呈现由目标端规范定义。
- 老己笔记按书归档，支持新建、编辑和删除；引用原文只读，保存失败保留输入。
- 老己笔记不设置独立标题字段，也不把正文第一行转换为标题式摘要。列表直接展示笔记正文；老己整理的笔记同样直接展示生成正文，不要求用户命名，也不额外调用模型总结标题。
- 用户明确要求老己将讨论内容整理为笔记时，完成后直接新增一篇老己笔记，不要求预览确认，也不提供待处理、覆盖或另存选择；AI 生成来源以轻量元信息说明。
- 用户可以直接编辑 AI 整理的笔记；只有用户明确引用一篇已有老己笔记并要求修改原笔记时，才更新该笔记，其他整理请求均新增笔记。
- 每本书都可发起 PPT，并查看该书生成中和已生成的作品。
- 最终生成前的 PPT 草稿只保留在原会话中，不进入作品列表。

### 4.3 设置与外部服务

- 设置仅包含账户与登录方式（含修改邮箱、修改密码与必要绑定管理）、文本模型、图片模型、微信读书连接与同步状态、退出登录。
- 微信小程序设置总览的账户区直接提供“修改邮箱”和“修改密码”两个入口，不使用“账户与登录方式”汇总行；绑定、验证和风险确认进入对应账户流程后再出现。
- 文本模型负责对话、书籍理解、大纲和逐页文案，是 AI 对话与 PPT 内容生成的必需能力。
- 新账户领取的免费体验额度由平台提供受限模型能力，不把平台凭证展示或下发给用户，也不改变设置中“用户自己的文本模型”配置状态。
- 图片模型只用于可选配图，不影响无配图 PPT 的生成；同一服务支持两类能力时可复用连接信息。
- 联网查找公开书籍资料是产品内置能力，不要求用户额外配置模型或搜索服务。
- 每类模型同时使用一个已验证的有效配置；新配置验证成功后才替换当前配置。
- 文本模型配置详情先从固定下拉列表选择 `DeepSeek / Kimi（月之暗面）/ GLM（智谱）/ 通义千问（阿里云百炼）`，再填写密文 `API Key`；选择千问时按当前官方接入要求补充业务空间 ID。MVP 不开放任意服务商、自定义 Base URL、模型名称或高级参数。用户可粘贴和修改，但失焦、返回或关闭不得自动保存、清空或检测。只有点击“检测并保存”才发起验证并在成功后持久化，验证失败时原位说明原因并保留当前输入。
- 从免 Key 体验结束后的上下文引导进入配置页时，验证成功后返回原输入或原 PPT 阶段并显示可继续状态，不自动重放尚未执行的 AI 请求；用户再次确认后才继续。
- 设置总览中，已配置模型只显示一个“修改配置”入口，未配置模型只显示一个配置入口；撤销凭证属于修改配置流程内的低频操作，不与修改入口并列。
- 撤销模型配置不影响书籍、笔记和历史作品。
- 微信读书通过腾讯官方微信读书 API Key（`wrk-...`）连接；保存并验证成功后立即自动同步，后续按自动同步策略更新，正常状态不要求用户手动触发同步。MVP 不使用 Cookie 抓取，也不把微信读书描述为可提供整本正文。
- 设置总览中，已连接微信读书只显示一个“修改连接”入口；新 API Key 验证成功后才替换当前连接，断开连接属于修改连接流程内的低频操作，不在总览并列展示。
- 断开连接只停止后续同步，已同步内容继续只读保留，老己笔记不受影响。
- 切换微信读书账号时不得静默合并不同账号的数据。

## 5. MVP PPT 生成流程

PPT 任务绑定资料来源集合，而不是永久绑定单个书籍字段。MVP 在产品交互和提交校验上将该集合限制为恰好一本书；后续跨书 PPT 可在同一任务中选择多本书，并继续复用任务、来源关联和作品模型。

### 5.1 双入口

```text
对话入口 → 选择或继承书籍 ┐
                         ├→ 范围与需求 → 大纲 → 模板 → 最终生成
书籍详情 → 带入当前书籍 ──┘
```

- 对话入口沿用当前会话，并在来源不明确时要求选择一本书。
- 书籍详情入口把当前书预选为本次 PPT 任务的资料来源，并进入用户当前会话；仅当账号尚无任何会话时创建初始会话，不得仅因书籍变化自动创建新会话。
- 两个入口只在书籍上下文来源上不同，后续流程、状态和结果一致。
- 用户可以返回发起入口，历史消息和已保存阶段保持不变。
- 同一会话可先后创建多个 PPT 任务和作品，且这些任务可以对应不同书籍；每个任务独立保存自己的资料来源和阶段。

### 5.2 范围与需求

- MVP 的资料来源选择为单选书籍；这是当前能力限制，不是任务或会话的永久单书约束。
- “范围与需求”工作区的固定表单只包含用途、受众、页数范围和补充要求等跨场景通用字段；用户已在对话中明确说明的值自动带入并允许修改。用途和受众提供常用选项并支持自定义，页数范围提供“6–8 页 / 8–10 页 / 10–12 页”预设和自定义，补充要求为自由文本。
- 任务来源上下文由发起入口和任务内部状态维护，“范围与需求”步骤不要求用户重复填写；需要补充或更换时再通过当前对话或选择能力处理。具体信息层级由目标端规范定义。
- 内容范围、资料选择和其他随任务语义变化的信息不作为固定表单字段。系统只在缺少生成所需信息时通过当前对话追问；用户已经表达清楚时不得重复询问。
- 简单且选项明确的问题直接附在老己消息下方提供结构化选择，并可用于选书以外的任何选择场景；层级、多选、需要预览或说明的复杂选择再进入任务工作区或适合当前视口的浮层，无法可靠结构化时允许用户直接输入。
- 低风险单选可在选中后直接作为新输入提交；多选、包含自由输入或会使已有内容失效的选择必须显式确认后才提交。
- 老己发出待用户回答的问题后，本轮 AI 回答即结束，选择控件和输入区恢复可用；用户提交选择后视为新的输入，并在系统继续处理期间重新遵循当前会话的任务互斥规则。
- 用户完成选择后，原选择控件折叠为只读历史结果并写入当前 PPT 草稿；已经失效的旧问题不得继续提交，也不得覆盖后来修改的范围。
- 存在个性化范围时，“范围与需求”步骤显示可修改的当前有效摘要；未产生个性化范围时不显示摘要。摘要的布局与层级由目标端规范定义。
- 对话历史记录当时的问答，工作区摘要记录当前有效值；用户后来修改时，旧结果标记为已更新，不能让两个位置看起来同时有效。
- 生成大纲前更换书籍时，保留用途、受众和页数等通用要求，清除并重新加载与旧书相关的范围和资料。
- 已生成或人工修改大纲后更换书籍时，必须说明旧大纲和来源关联将失效，并在用户确认后重新生成；正在生成 PPT 时必须先停止，再在当前会话中创建使用新资料来源的 PPT 草稿或任务，不覆盖旧任务结果。
- MVP 书籍场景可根据语义询问全书、可靠识别的章节或个人笔记，但这些只属于本次问题的候选答案，不形成永久的“内容范围”表单。
- 选择全书时，系统优先使用已提取正文；正文缺失或不完整时，自动结合个人划线、想法、老己笔记与联网查找到的公开资料补全。
- 公开资料优先采用出版社或作者信息、公开目录、作者访谈和可信书评，并保留来源关联；使用补充资料时向用户轻量说明。
- 通用需求包含用途、受众和页数范围，补充要求既可在工作区修改，也可通过对话补充。
- 公开资料不足以支持可靠内容时，不得假装掌握全书或编造分析；保留当前需求和已找到的资料，并引导用户补充内容或重试。
- 填写通用字段不依赖模型；识别缺失的个性化范围、继续对话或生成大纲前必须配置可用的文本模型，或由当前账户仍可用的免费体验额度覆盖。模型未配置、体验不可用或追问失败时保留当前草稿、已确认范围和用户输入。

### 5.3 大纲与模板

- 大纲改为类似飞书文档的连续分层文本编辑：页面、要点和说明由段落层级判定，一级页面段落自动计为一页，页数只由当前一级段落数量计算。
- 换行继承当前段落层级；缩进进入子层级，退格在段首回退层级；删除空段落即删除其对应的页面、要点或说明结构。
- 大纲以连续分层文本直接编辑，不提供另一套页卡或页面结构编辑模式；具体编辑控件由目标端规范定义。
- 子段落失去所属页面层级而无法组成有效大纲时，在对应段落原位提示“需要页面层级才能确认大纲”，并阻止确认；恢复层级后才可继续。
- 编辑和保存保留当前编辑位置与焦点，不迫使用户重新定位。
- 来源关联由系统维护，不作为用户需要编辑的字段。
- 用户明确确认大纲后才能选择模板和最终生成。
- 修改已确认大纲后重新生成时必须再次确认，避免误覆盖当前选择。
- 模板从带预览的内置风格中选择；未配置图片模型时也必须产出可直接展示的完整视觉结果，不得降级为无设计排版的白底黑字。
- 图片模型只按大纲中的视觉意图增强配图，不是模板选择、视觉质量或最终生成的前置条件。
- 桌面端进入任务流程时可在当前对话旁打开单个上下文任务工作区；MVP 由 PPT 流程使用该工作区，其阶段可调整宽度、收起并恢复，不形成固定多栏或通用自由分栏系统。

### 5.4 生成与作品

- 只有用户在模板阶段最终提交后才创建生成任务。
- PPT 生成期间遵循当前会话的通用任务锁定规则；输入区说明“停止生成后可修改要求”，停止后保留已完成页面和已确认配置，并根据新要求返回相应编辑阶段。
- 生成中在同一 PPT 工作区持续展示已完成页面、当前页面和总体进度，不另建任务列表或单页查看模式；具体瀑布流、骨架和比例由视觉规范定义。
- 新页完成后，只在用户仍停留于瀑布流末尾时自动跟随；用户已向上查看完成页时不得抢夺滚动位置。
- 离开页面不取消任务；返回后恢复到最新完成页面和当前生成位置。
- PPT 列表只展示生成中和已生成；排队、重试等内部状态合并为生成中。
- 生成失败不进入 PPT 列表；失败提示直接出现在对应大图页面位置，保留此前已完成页面以及范围、需求、大纲和模板，主要操作仍为“重新生成”和“修改大纲”。失败页右上角低频菜单提供“删除任务”，二次确认后只删除当前失败任务及该任务的临时已完成页面，不删除会话、书籍或历史作品；删除后不可重试。
- 成功后在同一瀑布流连续展示全部页面，滚动即预览，不再切换单页；作品支持下载可编辑 PPTX，可在 PowerPoint 或 WPS 中继续修改内容与版式。
- PPT 完成后不继续占用会话发送权；工作区可以继续打开供查看和下载，同时用户可在同一会话发送任意后续请求。
- 具体对象如何映射、不同客户端的兼容性以及修改后的布局表现，在技术设计和实现阶段通过真实导出验收确定；产品范围不预先限定为只有文字或简单形状可编辑。
- 再次生成会创建独立作品，不覆盖已有作品。

## 6. 状态与恢复

| 场景 | 必须保留或恢复 |
| --- | --- |
| 文本模型未配置、验证失败或调用失败 | 当前输入、会话上下文和已确认阶段；配置或重试后继续。 |
| 免费体验领取、调用或恢复失败 | 领取状态、原输入、会话上下文和 PPT 草稿；平台能力不可用时提供稍后重试，额度耗尽时提供配置自己的文本模型。 |
| 图片模型未配置或调用失败 | 可选择配置，或使用模板原生视觉继续生成，不影响文本内容。 |
| 联网补全失败或公开资料不足 | 保留范围、需求和已找到的资料，可重试或补充内容，不生成伪装成全书分析的结果。 |
| 微信读书自动同步失败 | 既有同步内容、失败原因和重试同步入口。 |
| 本地导入失败 | 已有书架数据、失败文件信息和可理解原因。 |
| 阅读或笔记保存失败 | 阅读位置、未保存内容和重试入口。 |
| 大纲生成或保存失败 | 范围、需求和当前可编辑大纲。 |
| 个性化范围识别、选择或保存失败 | 已确认范围、当前问题和用户输入；可重试、重新选择或直接输入，不回退到固定表单。 |
| AI 回答被停止 | 已发送问题、已输出内容和未发送输入草稿；当前会话立即恢复发送。 |
| 会话图片选择、上传或发送失败 | 未发送文字、已选图片和可理解原因；可重试或逐张移除，失败不得清空整条消息。 |
| PPT 生成被停止 | 已确认配置、已完成页面和未发送输入草稿；当前会话恢复发送，可修改要求后重新确认。 |
| PPT 生成失败 | 原会话保留已确认配置和重试入口；失败任务不进入 PPT 列表，删除任务需从失败页低频菜单二次确认，删除后不可重试。 |
| 刷新、跨页面或跨端继续 | 服务端已保存的本地书籍、全书阅读位置、阅读背景、划线、想法、老己笔记、会话、任务草稿、任务阶段和作品。 |

## 7. 跨端原则

- 桌面 Web 适合并行查看上下文与工作内容；微信小程序按单任务逐步推进。
- 两端均可完成账户、会话、书架、笔记和 PPT 核心闭环。
- 两端登录同一账户时共享已保存数据；未绑定的微信账户与邮箱账户保持独立，不得表现为同一账户暂时未同步。
- 关键阶段必须有清晰返回路径，返回后不丢失已保存状态。

## 8. MVP 验收

- 一级导航仅为对话、读书、设置，入口和返回路径可用。
- 桌面 Web 与微信小程序均可使用微信或邮箱进入产品；微信登录始终是首屏主入口，邮箱是清晰但低一层级的备选，手机号不是 MVP 登录方式。
- 微信身份尚未关联老己账户时，用户可选择绑定已有邮箱账户或创建独立账户；跳过绑定不阻塞使用，未绑定账户不共享数据，两个已有账户均含数据时不自动合并。
- 两类来源进入统一书架，同名不同来源不误合并。
- 本地书籍以统一产品模型工作，其文件、解析结果、阅读进度、划线和笔记可跨端同步。
- 本地阅读自动恢复全书上次位置，目录按需呼出，专注模式中仍可使用目录、阅读背景和退出；阅读背景选择会保存，产品只维护一处全书进度，不出现每章进度或重复的继续阅读操作。
- 选中正文后可直接划线、写想法或引用原文与老己讨论，已划线内容和选中文本操作均清晰可辨。
- 微信读书和本地书籍的划线与想法都能看到引用内容；可靠定位存在时才显示，无法识别时不留空占位；本地定位可返回原文，微信读书定位保持只读。
- 用户可查看自己的同步内容，并按书创建和维护老己笔记。
- 用户明确要求整理讨论内容时直接得到一篇新的老己笔记；只有明确要求修改某篇已有笔记时才更新原笔记，不增加预览确认或保存方式选择。
- 对话和书籍详情均能进入同一套 MVP 单书 PPT 流程；单书是当前提交限制，任务的资料来源模型不写死为永久单书。
- 会话不按书籍、入口或任务能力区分类型；切换书籍或任务不自动新建会话，同一会话可先后承载不同书籍的 PPT 任务以及未来新增的其他任务。
- 会话列表不显示书籍封面，只显示统一会话信息和必要的任务状态或产物数量。
- “范围与需求”固定表单只展示通用字段；个性化范围由语义识别后在对话中按需询问，简单选择使用消息内结构化选项，复杂选择进入任务工作区或浮层。
- 生成大纲前可在“范围与需求”顶部回看当前有效的轻量范围摘要；没有个性化范围时不显示摘要，历史选择失效后不能继续提交或覆盖新值。
- 选择全书时优先使用正文，正文不足则自动联网补全；公开资料不足时不编造全书分析。
- 新账户未领取时只在对话首页看到“免费体验额度 / 领取”；领取后提示消失，额度可用于 AI 对话或 PPT，前台不显示余额、金额、进度、倒计时或第二套券中心。
- 同一账户的平台实际调用成本达到 `¥5` 后停止免费能力；未配置文本模型且没有可用免费体验额度时，AI 对话和大纲生成会在当前操作位置引导配置且不丢输入，图片模型始终可选。
- 大纲以连续分层文本直接编辑，页面数由一级段落自动计算，模板可预览选择，最终提交才创建任务；失去页面层级的子段落会在原位提示并阻止确认。
- 桌面 PPT 工作区可调整宽度、收起和恢复；没有 PPT 上下文时不出现无关工作区。
- 当前会话的 AI 回答或任一任务运行时不能发送新消息；停止、完成或失败后立即恢复，同一时间其他空闲会话不受影响。
- 会话可发送纯文字、纯图片或图文消息；单条最多 `4` 张图片，微信小程序可从相册选择或直接拍摄，失败和模型不支持图片时均不丢失消息草稿。
- 两端设置均可直接进入修改邮箱、修改密码、四家固定文本模型配置和微信读书连接；已配置模型和已连接微信读书分别只有一个修改入口，微信读书 API Key 验证成功后自动同步。端侧标题与布局按对应视觉规范验收。
- 桌宠可关闭并收回左上角头像，点击头像可召回；对话页只陪伴，非对话页才可作为对话快捷入口。
- 未配置图片模型时，所有内置模板仍达到可直接展示的视觉质量。
- PPT 列表只出现生成中和已生成，失败在原会话恢复。
- PPT 失败页保留“重新生成”和“修改大纲”主路径；右上角低频菜单可二次确认删除当前失败任务及其临时已完成页面，不影响会话、书籍或历史作品，删除后不可重试。
- PPT 生成中、失败和完成在同一工作区连续呈现，并能保留此前已完成页面；具体布局按对应视觉规范验收。
- 成功作品可预览并下载可编辑 PPTX，可在 PowerPoint 或 WPS 中继续修改内容与版式；具体对象能力与兼容性在技术设计和真实导出验收中确认。
- 再次生成不覆盖历史作品。
- 桌面 Web 和微信小程序均跑通核心闭环，并覆盖关键数据状态。
