# Agent 长任务上下文治理与台账粒度

> 状态：已编译；最后核验：2026-08-28。本文是治理方法知识页，不是 SelfAlone 产品、视觉、技术或任务状态的权威事实源。项目执行仍以 `AGENTS.md`、当前权威事实源和 `TASK_LEDGER.md` 为准。

## 1. 五层分工与证据链

1. **当前上下文**：承载最新用户目标、当前状态、约束、本轮工具结果和下一步。
2. **Compact**：在上下文压缩或阶段切换时临时续接工作现场；至少保留最新目标、已完成/未完成、约束、证据、失败路径和下一步。它不是长期记忆，也不写入项目台账。
3. **LLM Wiki**：持续编译多份资料，形成索引、主题页、冲突记录和来源链接。Wiki 内部由 Raw Sources、Wiki 页面和组织 Schema 组成。
4. **长期记忆**：只保存稳定、可复用、可验证且带适用范围的偏好、事实、决策、坑点、流程和禁区。
5. **任务台账**：负责当前目标、任务拆分、状态、负责人、阻塞、下一步、验收和证据位置，支持中断恢复与目标回收。

**证据链不是第六层**，而是贯穿上述各层的完成判定机制。Raw Sources 也不是与五层并列的第六层，而是 LLM Wiki 的原始资料层。

## 2. Wiki 的编译循环

- **Ingest**：原文进入 Raw Sources，保留来源、版本、适用范围和哈希；摄取结果写日志。
- **Query**：先从索引进入 Wiki 综合页；摘要不足、存在冲突或需要引用时再回溯原文。
- **Lint**：检查矛盾、过期说法、孤岛页面、缺失来源、断裂链接和 Wiki 对权威事实源的越权复制。

Wiki 是知识编译层，不自动改变产品规则或任务状态。新资料不能只被切块检索，还应更新结构化页面和索引。

## 3. 台账粒度是控制策略

台账粒度表示 Agent 一次独立承担多大的不确定性，不是文档写得多详细。常见层级：

- **模块级**：连续性强、错误半径大；适合目标清晰、边界稳定、风险较低的工作。
- **功能级**：以可独立验收的功能闭环为单位；通常最适合建设阶段。
- **场景/验收级**：以业务行为和边界 Case 为单位；适合权限、资金、状态机、迁移、写回等高风险工作和最终收口。

决定粒度时综合五个变量：失败代价、需求清晰度、项目或资料质量、执行者熟悉度、人工校准成本。

## 4. 随阶段动态调整

- **探索阶段**：偏细，先查清未知问题、风险和决策门，不急于完整开发。
- **建设阶段**：按功能闭环推进，保持连续执行。
- **验收阶段**：重新拆到真实业务 Case，以证据收口。

出现大面积改文件、长时间无证据、频繁换方案、大规模返工或下一步不清楚时，应拆细。出现每做一点就停、人工确认成本过高、机械拆分没有独立验收价值或台账维护拖慢开发时，应合并。

## 5. 台账项字段

可执行项至少记录：任务目标、非目标/边界、依赖关系、预计涉及文件、当前状态、验收标准、验证方式、证据位置和下一步动作。高风险项再增加回滚方案、禁止动作和人工确认点；多 Agent 项还要明确唯一负责人和文件所有权。

字段按状态渐进展开：

- `PENDING`：保留 ID、目标、父项、依赖和释放条件。
- `READY`：补齐边界、文件、负责人、验收、验证和停止条件。
- `ACTIVE`：补齐工作区/分支/基线、当前检查点和下一动作。
- `VERIFY`：记录候选、实际 diff、测试和真实环境证据。
- `BLOCKED`：记录阻塞证据、已尝试路径、解除条件及不受影响的 READY 项。
- `DONE`：压缩为结果、主线提交、验收结论和证据链接；详细过程由 Git 与验收收据承载。

## 6. 对 SelfAlone 的直接约束

- `TASK_LEDGER.md` 保留拆分任务和必要字段，但活动项详细、远期待办适量、完成历史压缩；不能把台账变成会话流水、周报或第二份规格文档。
- 台账状态变化时及时回写；生成过台账但不维护，不能支持跨会话恢复。
- Compact 由当前运行时临时生成，恢复后先用仓库、台账和权威事实源校验；只有真实状态变化才进入台账。
- 当前 Goal 与活动工作包应位于控制面顶部；已有无依赖 `READY` 工作应在可用容量内推进，不能因整理文档而停掉开发。
- 用户新要求优先于旧 Compact、Wiki 和长期记忆；Wiki 的方法总结不能越权改变当前产品和视觉合同。
