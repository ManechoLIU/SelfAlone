## 1. 产品定义

### 1.1 一句话定义

老己是一个以聊天为主入口、以统一书架为内容入口的个人自我提升助理。MVP 聚焦一条闭环：

```text
微信读书同步 / 本地导入
        -> 阅读、划线、写老己笔记
        -> 在 PPT 对话中选择范围并生成大纲
        -> 用户确认
        -> 导出可编辑 PPTX
```

### 1.2 目标用户

需要持续学习、整理知识并形成输出的职场知识工作者。

### 1.3 MVP 目标

- 用户能在统一书架管理微信读书同步书和本地导入书。
- 用户能查找、阅读或查看书籍相关内容，并建立自己的私有笔记。
- 用户能从一本书的章节、划线和笔记生成 PPT 大纲。
- 用户确认大纲后，获得可预览、可再次打开、可下载的可编辑 PPTX。
- 所有核心流程在桌面和手机浏览器中可完成。

### 1.4 MVP 不包含

- 养生食谱、专注力管理等后续技能；
- 微信登录、手机号登录、邀请码；
- 多人协作、社区、公开分享、付费和订阅；
- 微信读书全文站内阅读；
- 微信读书全站书目搜索；
- 拼音搜索、全文搜索和笔记全文搜索；
- 跨书籍或跨来源混合生成 PPT；
- 通用的非读书 PPT 创作；
- 复杂阅读统计、社交排行和推荐系统。

## 2. 体验原则

1. **先使用，后配置**：注册后直接进入产品，不用配置卡阻塞用户。
2. **统一入口，能力真实**：两类书共用书架和工作区外壳，但只展示实际可用功能。
3. **熟悉但不复制**：借鉴微信读书的书架信息层级和封面网格，不复制品牌视觉、图标或资产。
4. **来源可追溯**：我的笔记、书友笔记和本地原文在界面中有明确来源。
5. **先确认，后生成**：PPT 必须经过大纲确认，不提供绕过确认的一键生成。
6. **安静、专注、工作导向**：不使用营销式首页、巨型口号或装饰性页面。
7. **错误可恢复**：连接、导入、同步和生成失败时保留上下文，并提供明确重试路径。

## 3. 信息架构

### 3.1 页面地图

```text
未登录
+-- AUTH-01 登录
+-- AUTH-02 注册
+-- AUTH-03 忘记密码 / 重置结果

已登录
+-- APP-01 对话
+-- BOOK-01 统一书架
|   +-- BOOK-02 统一书籍详情 · 微信读书内容变体
|   +-- BOOK-03 统一书籍详情 · 本地 EPUB 阅读变体
|   +-- BOOK-04 统一书籍详情 · 本地 PDF 阅读变体
|   +-- NOTE-01 老己笔记内容状态（嵌入书籍详情，不单独计页）
|   +-- PPT-01 对话式 PPT 需求
|   +-- PPT-02 大纲确认
|   +-- PPT-03 模板、预览与作品
+-- SET-01 AI 服务
+-- SET-02 微信读书连接
+-- SET-03 设置与账户安全
    +-- SET-04 个人资料
    +-- SET-05 登录邮箱
```

### 3.2 全局导航

```text
已登录一级入口
+-- 对话
+-- 读书
+-- 设置
```

- 默认登录后进入 `对话`。
- 桌面、平板和手机都必须让三个一级入口清晰、可发现且可到达；具体使用侧栏、顶部导航、底部导航或其他主流方式，由 Open Design 根据视口与可用性决定。
- 桌面“对话 / 读书 / 设置”复用同一全局导航轨、同一开合控件和跨页面持久化状态。切换一级模块只替换导航右侧的模块上下文与主工作区，不改变工作区起点、页头基线或页面高度；会话列表属于“对话”的二级上下文栏，不得与全局导航使用同一开合状态或相同图标语义。
- PPT 不作为顶层导航，从书籍工作区或书籍相关上下文进入。
- 设置在所有适用端都可从一级导航直接进入。

## 4. 核心用户流程

### F-01 注册与首次进入

```text
注册 -> 自动登录 -> 对话首页
                     |
                     +-- 顶部轻量提示“AI 未配置”
                     +-- 不展示配置向导或连接卡
```

### F-02 配置 AI 后返回原上下文

```text
用户触发 AI 操作
      -> 未配置提示
      -> 进入 AI 设置
      +-- 验证成功 -> 返回原页面和原操作上下文
      +-- 验证失败 -> 留在设置，可重试或取消
      +-- 取消配置 -> 返回原页面并保留原操作上下文
```

### F-03 连接微信读书

```text
书架 -> 同步微信读书
     -> 未连接状态
     -> 填写 Skill Key
     -> 验证并连接
     -> 同步中
     -> 书籍进入统一书架
```

### F-04 导入本地书

```text
书架 -> 导入书籍 -> 选择 EPUB / PDF
     -> 上传/解析中
     -> 成功：进入对应阅读器
     -> 不支持：说明原因并返回书架
```

### F-05 阅读和笔记

```text
本地正文 -> 选择原文 -> 选区旁浮动工具条：复制 / 划线 / 写笔记
         -> 书籍“老己笔记”汇总全书划线和老己笔记

微信读书内容 -> 激活一条同步原文 -> 复制 / 写引用型老己笔记
```

### F-06 书友观点加入 PPT

```text
PPT 专属会话 -> 选择范围
             -> 用户明确选择“加入书友观点”
             -> 明确显示作者/来源
             -> 进入本次 PPT 范围
```

书籍详情中的书友笔记保持只读浏览，不提供逐条“加入 PPT”按钮。

### F-07 PPT 生成

```text
书籍详情“制作 PPT” / 普通对话提出 PPT 制作意图
      -> 确定一本书并创建或绑定 PPT 专属会话
      -> 选择内容范围
      -> 确认用途/受众/页数需求卡
      -> 生成大纲
      -> 编辑并确认
      -> 选择具有真实封面预览的固定模板
      -> 点击“开始生成 PPT”
      -> 逐页生成并在瀑布流查看进度
      -> 完成作品 -> 预览 / 编辑大纲 / 更换模板 / 重新生成 / 下载 PPTX
```

范围、需求、大纲与模板选择属于会话草稿；只有点击“开始生成 PPT”后才创建生成任务并进入书籍“读书 PPT”列表。重新生成创建独立作品，不覆盖旧作品，也不提供版本切换界面。

### F-08 本地书保留

```text
本地书导入成功 -> 保留在书架
              -> 阅读 / 划线 / 写老己笔记 / 制作 PPT
```

MVP 不提供单书移除、回收站或恢复流程。

## 5. 页面原型说明

### 5.0 页面契约总表

页面详情中的原型、字段和状态与下表共同构成页面契约。UI 不得省略下表中的主要出口；开发不得在失败后丢失用户已输入内容或当前书籍上下文。

所有列表、标签页和数据工作区必须区分五类状态：初次加载、真实空数据、搜索/筛选为空、请求失败和正常数据。加载或失败不得短暂显示为空数据；每个空状态需要说明原因，并提供与当前状态直接相关的恢复动作。

| 页面 | 主要入口 | 页面完成结果 / 主要出口 | 页面级验收重点 |
| --- | --- | --- | --- |
| `AUTH-01` 登录 | 未登录访问、退出登录、注册页 | 登录成功进入 `APP-01`；可去注册或找回密码 | 凭证错误留在原页，邮箱不丢失 |
| `AUTH-02` 注册 | 登录页“注册” | 注册并自动登录后进入 `APP-01`；可返回登录 | 不出现邀请码、手机号、微信登录或配置向导 |
| `AUTH-03` 找回密码 | 登录页“忘记密码”、重置邮件 | 发送结果页或重置成功后返回 `AUTH-01` | 不泄露邮箱是否存在，失败可重试 |
| `APP-01` 对话 | 登录后默认页、主导航“对话”、新对话、书籍 PPT 入口 | 普通回复；切换会话；去 `BOOK-01`；从按钮或自然语言意图进入带单书上下文的 `PPT-01` | 每个会话独立保存输入、书籍上下文和任务；AI 未配置时保留输入和上下文 |
| `BOOK-01` 统一书架 | 主导航“读书”、对话中的“查看书架” | 打开 `BOOK-02/03/04`；去 `SET-02`；发起导入 | 区分加载、真实空书架、搜索无结果和失败；两类来源能力不混淆 |
| `BOOK-02` 统一书籍详情 · 微信读书内容变体 | 微信读书书籍卡片 | 去 `NOTE-01` 或 `PPT-01`；返回书架 | 与本地书共用详情外壳；只显示微信读书可用区域，不出现站内全文阅读 |
| `BOOK-03` 统一书籍详情 · 本地 EPUB 阅读变体 | 本地 EPUB 书籍卡片 | 阅读、保存位置、划线或笔记；去 `NOTE-01/PPT-01` | 与微信读书/PDF 共用详情页头和内容容器；划线重开后仍对应相同原文 |
| `BOOK-04` 统一书籍详情 · 本地 PDF 阅读变体 | 本地 PDF 书籍卡片 | 阅读、保存位置、跨页划线或笔记；去 `NOTE-01/PPT-01` | 与微信读书/EPUB 共用详情页头和内容容器；优先显示章节目录 |
| `NOTE-01` 老己笔记视图 | 本地书“老己笔记”、微信读书“老己笔记”、阅读器写笔记 | 汇总当前书籍可见的老己笔记内容；定位原文；新建、编辑或删除老己笔记 | 作为统一书籍详情的内容区域展示；本地包含划线和带原文笔记，微信读书只显示新增笔记 |
| `PPT-01` 对话式 PPT 需求 | 书籍工作区“制作 PPT”、书籍“读书 PPT”分区、对话中的 PPT 制作意图 | 在绑定书籍的会话中确认范围与需求后生成大纲 | 一次仅一本书，不逐条选择素材，失败保留原消息、范围和需求 |
| `PPT-02` 大纲确认 | `PPT-01` 生成完成 | 在同一 PPT 会话中展开大纲作品画布；确认后进入预览画布 | 至少保留一页；未明确确认不得进入最终生成 |
| `PPT-03` 模板、生成与作品 | 已确认的大纲、本书生成任务或完成作品 | 选择模板并启动逐页生成；实时查看瀑布流；预览、下载或基于旧作品重新创作 | 生成前草稿不进书籍列表；任务进度同源；失败保留已完成页；新作品不覆盖旧作品 |
| `SET-01` AI 服务 | 主导航“设置”、AI 未配置提示 | 验证并启用后返回原上下文或设置首页 | 全局仅一套生效供应商和 Key，可替换、撤销 |
| `SET-02` 微信读书连接 | 设置首页服务行、书架“同步微信读书” | 保存或测试 Key；测试成功后连接并同步；可清除凭证 | 未配置、已配置未测试、测试中、测试失败、已连接、失效、重试、撤销完整 |
| `SET-03` 设置与账户安全 | 主导航“设置” | 进入个人资料、登录邮箱、连接服务；修改密码、退出或删除账户 | 聚合页易于扫描；不出现本地书回收站；账户级破坏性操作有确认 |
| `SET-04` 个人资料 | 设置首页个人资料摘要 | 点击头像更换或恢复默认头像；显式保存昵称后返回设置 | 不显示登录邮箱；头像与昵称独立保存；失败保留当前输入 |
| `SET-05` 登录邮箱 | 设置首页“账户与安全”中的登录邮箱 | 查看当前邮箱；完成两步验证后更新邮箱 | 独立详情页承载安全任务；不得把邮箱修改塞回个人资料表单 |

## AUTH-01 登录

**目标**：已有用户使用邮箱和密码进入老己。

**入口**：未登录访问产品、退出登录后、注册页“已有账户”。

**桌面原型**：

```text
+----------------------------------------------------------------+
| 老己                                                           |
|                                                                |
|                    欢迎回来                                    |
|              +--------------------------+                      |
|              | 邮箱                     |                      |
|              +--------------------------+                      |
|              | 密码                 [眼] |                      |
|              +--------------------------+                      |
|              [ ] 保持登录    [忘记密码]                         |
|              +--------------------------+                      |
|              |          登录            |                      |
|              +--------------------------+                      |
|              还没有账户？[注册]                                 |
+----------------------------------------------------------------+
```

**手机原型**：

```text
+------------------------+
| 老己                   |
|                        |
| 欢迎回来               |
| [邮箱                 ] |
| [密码             眼  ] |
| [ ] 保持登录  忘记密码 |
| [      登录          ] |
| 还没有账户？注册       |
+------------------------+
```

**字段与操作**：

- 邮箱：必填，失焦后验证格式。
- 密码：必填，可显示/隐藏。
- 登录：字段合法后可点击；提交中按钮显示处理中并禁止重复提交。
- 登录成功：进入 `APP-01`。
- 登录失败：在表单内显示原因，不清空邮箱；密码错误时清空密码。

**状态**：初始、字段错误、提交中、凭证错误、网络错误、成功跳转。

**验收**：键盘可完成输入和提交；手机键盘弹出时登录按钮仍可到达；错误不使用只有颜色的提示。

## AUTH-02 注册

**目标**：通过邮箱和密码开放注册，不使用邀请码、手机号或微信登录。

**入口**：`AUTH-01` 的“注册”。

**桌面原型**：

```text
+----------------------------------------------------------------+
| 老己                                                           |
|                                                                |
|                    创建账户                                    |
|              [邮箱........................]                    |
|              [密码.................... 眼]                    |
|              [确认密码................ 眼]                    |
|              密码至少 8 个字符                                 |
|              [       注册并进入       ]                        |
|              已有账户？[登录]                                  |
+----------------------------------------------------------------+
```

**手机原型**：

```text
+------------------------+
| 老己                   |
|                        |
| 创建账户               |
| [邮箱................] |
| [密码............ 眼] |
| [确认密码........ 眼] |
| 密码至少 8 个字符      |
| [    注册并进入      ] |
| 已有账户？登录         |
+------------------------+
```

**规则**：

- 密码长度 8 至 64 个字符；确认密码必须一致。
- 注册提交中禁止重复操作。
- 注册成功后自动登录并进入 `APP-01`，不展示配置向导。
- 邮箱已注册时提供“去登录”和“忘记密码”。

**状态**：字段错误、邮箱已注册、注册中、网络错误、成功。

**出口与验收**：注册成功自动进入 `APP-01`；点击“登录”回到 `AUTH-01`。键盘可完成全表输入和提交，错误反馈不清空合法字段，页面不出现产品配置项。

## AUTH-03 忘记密码 / 重置结果

**目标**：用户通过邮箱恢复账户。

**入口**：`AUTH-01` 的“忘记密码”和重置邮件中的链接。

**桌面原型**：

```text
+----------------------------------------------------------------+
| 老己                                                           |
|                    重置密码                                    |
|              [邮箱........................]                    |
|              [       发送重置邮件       ]                      |
|              [返回登录]                                        |
|                                                                |
| 结果：如果账户存在，重置邮件已发送。 [重新发送]                 |
+----------------------------------------------------------------+
```

**手机原型**：

```text
+------------------------+
| < 返回登录             |
| 重置密码               |
| [邮箱................] |
| [  发送重置邮件      ] |
|                        |
| 如果账户存在，重置邮件 |
| 已发送。  [重新发送]   |
+------------------------+
```

- 结果文案不泄露邮箱是否已注册。
- 提供返回登录和重新发送入口。
- 重置成功后返回登录页，不自动展示其他配置。

**状态**：输入邮箱、字段错误、发送中、发送结果、网络错误、链接失效、重置中、重置成功。

**出口与验收**：发送结果页可返回 `AUTH-01` 或重新发送；重置链接失效时可重新申请。任何结果都不显示“邮箱不存在”，提交中禁止重复发送。

## APP-01 对话首页

**目标**：作为老己的默认入口，承载可创建和切换的普通对话与书籍 PPT 专属会话。

**桌面原型**：

```text
+------------------+--------------------------------------+----------------+
| 老己  [+ 新对话] | 原子习惯：读书 PPT        AI 未配置 | 当前书籍       |
| 今天             +--------------------------------------+                |
| 原子习惯：PPT    | 老己：先选择内容范围。              | 原子习惯 42%   |
| 最近的阅读想法   | 用户：[我的笔记 + 老己笔记]          |                |
| 昨天             |                                      | 最近任务       |
| 深度工作笔记     | [需求卡：用途 / 受众 / 页数]         | 生成第 8/12 页 |
| 对话 / 读书 / 设置|                                     |                |
|                  | 输入消息...                    [发送] |                |
+------------------+--------------------------------------+----------------+
```

**手机原型**：

```text
+------------------------+
| [会话] 原子习惯：PPT AI 未配置 |
+------------------------+
| 对话内容               |
|                        |
| [选择书籍并生成 PPT]   |
|                        |
+------------------------+
| 输入消息...       [>]  |
+------------------------+
| 对话 | 读书 | 设置    |
+------------------------+
```

**信息与操作**：

- 桌面、平板和手机都提供“新对话”和按时间排列的会话列表；会话标题由首条用户消息生成，可重命名。会话列表的入口、位置和展开方式由 Open Design 决定。
- 小屏幕的会话管理不能长期挤压消息阅读和输入区域；关闭后应返回原会话位置，具体采用抽屉、弹窗、独立视图或其他主流方式由 Open Design 决定。
- 新对话默认没有书籍上下文；用户可主动选择书籍。书籍“制作 PPT”入口自动创建绑定该书的专属会话。
- 用户在普通对话中提出制作 PPT、生成读书分享或把某本书整理成 PPT 等明确意图时，触发 `PPT-01`，不要求必须先点击书籍页面按钮。
- 当前会话已有唯一书籍上下文时，直接将当前会话绑定为该书的 PPT 会话并进入范围选择；没有书籍上下文或书名不明确时，在当前对话显示书籍选择，选择后继续。不能仅凭模糊相似书名自动绑定。
- PPT 从选书、范围、大纲、模板到生成/完成始终沿用同一会话身份和累计消息；跨页面或刷新不得重建会话、清空已完成阶段或丢失对话与作品滚动位置。
- 当前消息提到多本书或匹配到同名不同来源书籍时，要求用户选择一本；MVP 不进入多书 PPT。
- AI 状态使用轻量文字、图标或等效表达，并在主要页面保持可发现；不使用大面积配置卡，具体位置由 Open Design 决定。
- 有历史的新对话显示最近阅读、最近任务和可执行命令，不展示营销文案。
- 首次进入且没有对话、书籍、笔记或最近活动时，显示简短起步说明，主动作是“打开书架”，次动作是“导入书籍”；不出现 AI 或微信读书配置卡。
- “查看书架”进入 `BOOK-01`。
- “生成读书 PPT”无论来自快捷入口还是用户消息，都要求最终绑定一本书。来自普通对话时优先继续使用当前会话，来自书籍详情按钮时创建新的 `PPT-01` 专属会话。
- 用户触发 PPT 制作但书架为空时，进入 `BOOK-01` 的真实空书架状态并保留原消息与创建意图；添加第一本书成功后显示“继续制作 PPT”，由用户确认后返回原会话继续。
- 带书籍上下文的对话必须显示当前绑定书籍，并提供最近阅读和最近作品入口；不提供跨书籍最近笔记入口。当前书笔记从绑定书籍详情进入。
- AI 未配置时允许输入；点击发送后就地提示“配置 AI 后可使用对话”，提供“去配置”和“取消”。
- 配置成功、失败后取消或主动取消返回时，都保留未发送文字和当前书籍上下文；只有验证成功后 AI 操作才可继续。
- 删除会话会删除仍处于范围、要求、大纲或模板阶段的生成前草稿；已经开始最终逐页生成的任务和完成作品不随会话删除，并仍可从书籍“读书 PPT”找回。删除确认必须说明影响范围。
- 最近任务显示最终 PPT 的生成中、失败和已完成状态；“生成中”从用户确认模板并点击“开始生成 PPT”起算，大纲生成不得使用该状态名。点击任务进入对应作品状态，保证离开长任务页面后仍能找回。

**状态**：首次无任何数据、无当前会话但有最近内容、新对话、普通对话、识别到 PPT 意图、待选择书籍、同名/多书待确认、PPT 专属会话、回复生成中、回复失败、AI 未配置、Key 失效、书籍上下文、网络慢。

**验收**：对话只调度读书和 PPT；明确的 PPT 制作意图进入 `PPT-01`，书籍不明确时不误绑；其他未来技能不展示空入口；重复发送被阻止；失败消息可重试。

## BOOK-01 统一书架

**目标**：在一个入口查看和搜索微信读书同步书及本地导入书。

**桌面原型**：

```text
+------------+-------------------------------------------------------+
| 老己       | 读书        AI 未配置·去配置        [同步] [导入]|
|            +-------------------------------------------------------+
|   对话     | [搜索书名或作者.................................]       |
| > 读书     +-------------------------------------------------------+
|   设置     | [完整封面] [完整封面] [完整封面] [完整封面]           |
+------------+-------------------------------------------------------+
```

**手机原型**：

```text
+----------------------------+
| 读书             [同步][+] |
| [搜索书名或作者........]   |
+----------------------------+
| [完整封面]      [完整封面] |
| [完整封面]      [完整封面] |
+----------------------------+
| 对话 | 读书 | 设置        |
+----------------------------+
```

**书籍卡片**：

- 必须展示包含书名和作者的完整封面；封面下方不得重复书名、作者、文件类型、进度或操作。
- 书架封面不显示微信读书、本地导入、EPUB 或 PDF 来源角标。
- 同名不同来源显示为两张卡片，不自动合并。
- 封面缺失或源图清晰度不足时使用稳定比例的文字封面；任何来源图片都不拉伸或超出清晰度上限放大。
- 没有真实封面时使用稳定比例的文字封面完整承载书名和作者。书籍详情页显示作者、进度和当前位置，不显示来源或文件格式。

**搜索**：

- 搜索匹配书名或作者，输入后更新当前书架结果。
- 当前原型固定按最近访问排序，不显示单独的排序控件。

**主要操作**：

- 同步：未连接进入 `SET-02`；已连接开始同步并在当前页显示状态。
- 导入：打开文件选择，限制 EPUB/PDF；选择后显示上传/解析进度。
- 点击微信读书卡片进入 `BOOK-02`。
- 点击任意书籍都进入统一书籍详情外壳。微信读书使用 `BOOK-02` 内容变体；本地 EPUB/PDF 使用 `BOOK-03/04` 阅读内容变体，但页头、封面信息、标签样式和内容容器保持一致。
- MVP 不提供任何单书移除入口。

**状态**：初次加载、首次空书架、已连接但结果为空、仅微信读书、仅本地书、更新中、部分更新失败、导入中、导入失败、搜索无结果、加载更多、网络错误。

**缺省与失败状态**：

| 状态 | 界面说明 | 主要动作 | 次要动作 |
| --- | --- | --- | --- |
| 初次加载 | 使用稳定骨架，不显示“书架为空” | 等待 | 无 |
| 首次空书架且未连接 | 说明可以同步微信读书或导入本地书 | 导入书籍 | 连接微信读书 |
| 已连接但同步结果为空 | 说明当前账号尚未同步到书籍，不误报失败 | 重新同步 | 导入书籍 |
| 搜索无结果 | 显示当前搜索词，不发起外部搜索 | 清除搜索 | 导入书籍 |
| 网络错误且无缓存 | 说明书架暂时无法加载，不显示空书架文案 | 重试 | 无 |
| 网络错误但有缓存 | 保留已有书籍并显示非阻塞错误 | 重试 | 继续浏览 |

这些空状态只在用户进入书架后出现，不在注册成功后的对话首页提前展示连接卡。

## BOOK-02 统一书籍详情 · 微信读书内容变体

**目标**：在统一书籍详情外壳中查看微信读书同步的我的笔记、书友笔记、老己笔记和读书 PPT；不提供站内全文阅读。页头、封面信息、标签栏和内容容器与本地书详情使用同一组件。

**桌面原型**：

```text
+------------+-------------------------------------------------------+
| 读书       | [返回书架]  [封面] 原子习惯                           |
|            |          詹姆斯·克利尔  进度 42%   [同步] [制作 PPT] |
|            +-------------------------------------------------------+
|            | [我的笔记] [书友笔记] [老己笔记] [读书 PPT]            |
|            +-------------------------------------------------------+
|            | 我的划线 128 条                                      |
|            | “每个行动都是一次投票……”                              |
|            | “习惯是自我身份的复利……”                            |
|            | “让行动变得显而易见……”                              |
+------------+-------------------------------------------------------+
```

**手机原型**：

```text
+------------------------+
| < 原子习惯       [同步] [制作 PPT]|
| 进度 42%              |
| [我的笔记][书友笔记][老己笔记][读书 PPT]|
+------------------------+
| 原文条目 1             |
| 原文...                |
| 点击条目后在附近显示 [复制] [写笔记] |
| 原文条目 2             |
| 原文...                |
+------------------------+
```

**内容分区**：

- 我的笔记：我的划线和我的想法；同步内容只读，可新建引用型老己笔记。
- 书友笔记：最多展示 20 条热门划线和 20 条高赞评价；内容只读，可新建引用型老己笔记。标签始终保留；真实没有内容时显示空状态，确认有内容但获取失败时显示失败与重试。
- 老己笔记：使用 `NOTE-01` 结构统一展示用户记录；有原文引用时显示原文和来源，没有原文引用时只显示笔记正文。
- 读书 PPT：本书已经开始最终逐页生成的任务、可恢复的失败任务和已完成作品；范围、要求、大纲和模板阶段的草稿不进入该列表。主动作是“制作 PPT”。

**标签页缺省状态**：

| 标签页 | 空状态说明 | 主要动作 |
| --- | --- | --- |
| 我的笔记 | 暂无同步的个人划线或想法 | 立即同步 |
| 书友笔记 | 暂无可展示的书友笔记 | 返回我的笔记 |
| 书友笔记 | 确认有内容但本次获取失败 | 重试失败部分 |
| 老己笔记 | 还没有老己笔记 | 新建书籍笔记 |
| 读书 PPT | 还没有生成任务或完成作品 | 制作 PPT |

同步部分失败时，只在受影响的标签页显示失败范围和“重试失败部分”，其他已成功内容保持可用。

**原文条目操作**：

- 我的笔记和书友笔记都按多条独立内容项展示；每条保留原文、章节/位置、内容类型和作者信息（接口有值时）。
- 默认只显示内容，不在每条下方重复放置按钮。点击、轻触或键盘激活某一条后，在该条附近显示上下文工具条：`复制`、`写笔记`；一次只允许一个条目处于激活状态。
- `复制`只复制当前条目的正文，不附带界面标签；成功后显示短暂“已复制”反馈，不需要 AI 配置。
- `写笔记`创建引用当前条目的老己笔记，编辑器同时显示只读引用原文；同一条原文可以新增多条老己笔记。
- 点击条目外、按 `Esc` 或切换标签页时收起工具条。桌面端拖选文字时优先完成文本选择，不因按下鼠标立即触发工具条。

**明确限制**：不出现“开始阅读”“继续阅读”或正文翻页入口。可以显示进度，但不能暗示老己拥有全文。

**书友内容操作**：

- 书友观点默认不进入 PPT；只有在 PPT 专属会话中明确选择“加入书友观点”才可使用。
- 加入后在大纲和最终作品中显示作者、来源和“书友观点”。
- 不能编辑他人原文；可以另建私有引用型老己笔记。

**状态**：同步中、同步成功、部分内容失败、连接失效、无我的笔记、无书友笔记、书友笔记获取失败、网络错误。

## BOOK-03 统一书籍详情 · 本地 EPUB 阅读变体

**目标**：在与微信读书一致的书籍详情外壳中阅读 EPUB；“阅读”区域承载目录、正文和当前笔记，“老己笔记”区域承载本地全书划线与老己笔记汇总。

```text
+----------------+--------------------------------+------------------+
| 目录           | 书名 / 当前章节        进度 36%| 笔记             |
| 第一章         +--------------------------------+                  |
| > 第二章       | 正文正文正文正文正文正文       | 当前划线         |
| 第三章         |                                | “被选中的原文”   |
|                | 用户选中一段文本               |                  |
|                | [复制] [划线] [写笔记]           | 老己笔记       |
|                |                                | [保存]           |
+----------------+--------------------------------+------------------+
```

**手机原型**：

```text
+------------------------+
| [目录] 书名     [笔记] |
| [阅读][老己笔记][读书PPT]  |
+------------------------+
|                        |
| 正文主阅读区           |
```

**交互**：

- 详情页头与 `BOOK-02` 使用同一封面、书名、作者、进度元信息和标签栏组件；本地书只显示“阅读 / 老己笔记 / 读书 PPT”。
- 阅读器提供统一的“目录 / 缩小 / 标准 / 放大 / 阅读进度 / 专注阅读”控制。EPUB 内部调整字号，PDF 内部调整页面缩放，但用户不需要理解文件格式差异；两类阅读器的按钮名称、顺序、状态与反馈一致，不在公共控制中暴露页码或“适合宽度”等格式专属概念。
- 桌面和手机初始都收起阅读操作栏且不预留正文空间；点击正文空白处显示，再次点击、正文滚动或 3 秒无操作后收起。选择文字、操作划线、目录或控制栏本身时不得误切换显隐。专注阅读态沿用相同规则，并保留可发现的退出入口。
- 阅读器内的上下文笔记区域只显示当前选区或当前位置相关内容，全书内容从“老己笔记”进入 `NOTE-01`；区域位置和承载方式由 Open Design 决定。
- 选择原文后在选区附近显示浮动操作条：复制、划线、写笔记。工具条优先位于选区上方，空间不足时翻转到下方；不得固定在页面底部。
- MVP 使用一种默认划线样式，不提供颜色配置。
- 复制只复制当前选区并显示“已复制”；写笔记进入清晰、可返回的老己笔记编辑状态，并保留当前选区作为只读引用。编辑器采用侧栏、面板、弹窗或内联方式由 Open Design 决定。
- 点击或轻触已有划线时重新显示上下文工具条：复制、写笔记；取消划线放在次级菜单，避免误触。
- 章节切换和重新打开后恢复阅读位置与高亮。
- 目录和上下文笔记区域可收起或切换；关闭后正文获得更多空间且阅读位置不变。

**状态**：解析中、正文加载中、恢复进度、空章节、保存中、保存失败、重新定位失败。

## BOOK-04 统一书籍详情 · 本地 PDF 阅读变体

**目标**：在与微信读书和 EPUB 一致的书籍详情外壳中阅读 PDF；文件差异只影响内容渲染和定位能力，不改变详情页与公共阅读控制。

**桌面原型**：

```text
+--------------+--------------------------------------+---------------+
| [封面] 书名 / 作者 / 进度                                 [制作 PPT]   |
| [阅读] [老己笔记] [读书 PPT]                                         |
+--------------+--------------------------------------+---------------+
| 目录           | PDF 阅读内容                         | 笔记          |
| 第一章         +--------------------------------------+               |
| > 第二章       | 页面 12：选区从本页末尾开始          | 跨页划线      |
| 第三章         | ------------------------------------ | 第12-13页     |
|              | 页面 13：选区在本页继续并结束        | 老己笔记      |
|              | [复制] [划线] [写笔记]                | [保存]        |
+--------------+--------------------------------------+---------------+
```

**手机原型**：

```text
+------------------------+
| [目录] PDF 阅读内容     |
| [阅读][老己笔记][读书PPT]  |
+------------------------+
| 第 12 页               |
| 页面内容...            |
| 第 13 页               |
| 页面内容...            |
+------------------------+
| 选中文本后在选区附近显示 [复制][划线][写笔记] |
+------------------------+
```

**交互**：

- PDF 导入解析目录的顺序固定为：读取文件内置书签/大纲；没有可用大纲时，根据文本层中的标题字号、层级和位置自动提取章节标题；提取结果不可靠时不生成虚假章节。
- 目录面板默认展示章节层级并定位到对应页。只有未识别到可靠章节时，目录面板才显示“未识别到章节”，并提供页码列表/缩略页导航作为降级能力。
- 自动提取目录属于本地文档解析，不依赖用户配置 AI API Key；解析中显示“正在识别目录”，失败不阻塞 PDF 阅读。
- 允许选区从一页末尾跨到下一页或多页，并作为一条连续划线保存。
- 选区工具条与 EPUB 一致，包含复制、划线和写笔记；跟随选区出现并避让页码、浏览器边缘和手机安全区，不固定在页面底部。点击已有划线时提供复制和写笔记。
- 调整显示级别和阅读进度不改变已保存划线位置。
- 重新打开后恢复跨页高亮；若无法准确恢复，显示“需要重新定位”，不静默标到错误文字。

**不支持状态**：

| 文件情况 | 产品行为 |
| --- | --- |
| 扫描版 PDF | 允许查看可渲染页面；禁用精准划线并说明原因 |
| 无文本层/文本层损坏 | 允许查看；禁用精准划线 |
| 加密且无法读取 | 阻止导入，说明 MVP 暂不支持 |
| 文本顺序异常 | 提示精准划线不可用，不承诺错误结果 |

**验收**：跨页选区在缩放、刷新和重新打开后仍对应相同原文；所有不支持状态在用户开始大量阅读前可见。

**状态**：文件加载中、正在识别目录、内置目录可用、自动目录可用、未识别到章节、页面渲染中、正常阅读、跨页选区、保存中、保存失败、页面渲染失败、无可渲染页面、需要重新定位、不支持精准划线。

- 页面渲染失败保留书名、页码和返回书架入口，提供“重试加载”。
- 无可渲染页面不显示空白阅读区；说明文件无法显示，并提供“返回书架”。
- 扫描版或文本层异常属于“可阅读但不可精准划线”，不得与渲染失败或空文件混为同一状态。
- 未识别到章节不等于文件解析失败；用户仍可按页阅读、定位、划线和写笔记。

## NOTE-01 当前书老己笔记内容状态

**目标**：在统一书籍详情中展示当前来源可见的老己笔记。微信读书只显示用户新增的笔记；本地书同时显示全书划线和用户笔记。记录有原文引用时显示原文与笔记，没有原文引用时只显示笔记正文。阅读器内的笔记入口仍只承担当前上下文的快速查看和编辑。

`NOTE-01` 不是独立页面或全局管理入口。每本书只展示和管理自己的老己笔记；应用不提供跨书籍汇总、独立笔记页或“最近笔记”总入口。

**桌面原型（本地书变体）**：

```text
+--------------------------------------------------------------------+
| 老己笔记                                                [新建笔记] |
+--------------------------------------------------------------------+
| 第三章 · 位置 36%                                                   |
| “系统不会上升到目标的高度，而会下降到系统的水平。”                 |
|                                               [复制] [写笔记]     |
+--------------------------------------------------------------------+
| 第五章 · 老己笔记                                                   |
| 把目标拆成环境提示和最小动作。                    [编辑] [删除]   |
+--------------------------------------------------------------------+
```

**手机原型（本地书变体）**：

```text
+------------------------+
| 老己笔记             [+]|
+------------------------+
| 第三章                  |
| 原文...                |
| [删除] [编辑] [复制]   |
+------------------------+
```

**规则**：

- 本内容区嵌入统一书籍详情外壳，不另起一套页面头部。两类书都从“老己笔记”进入，但内容规则按来源自适应。
- 本地书和微信读书都直接平铺用户新增的老己笔记，不提供“全部 / 划线 / 笔记”筛选，也不显示“引用型 / 独立型”等类型名称。有关联原文时可在卡片内显示只读原文，没有关联原文时只显示笔记正文。
- 激活笔记卡片后显示删除、编辑和复制；这些操作不常驻挤压正文，也不通过“回到原文”或更多菜单再次分流。
- 本地老己笔记按最近更新时间展示；有原文引用时显示原文、来源、作者（如有）和位置，没有原文引用时只显示笔记正文。同一原文可以关联多条用户笔记。
- 微信读书只显示用户新增的老己笔记，不将同步的“我的笔记”或“书友笔记”混入；有原文引用时显示关联原文和来源，没有原文引用时只显示笔记正文。
- 点击“新建笔记”创建不带原文引用的独立老己笔记；编辑器不要求选择书籍级、章节级或划线级归属，保存后只显示用户输入的笔记正文。
- 微信读书与本地书中的每条用户创建笔记都提供编辑和删除；编辑复用笔记编辑器并保留只读引用原文，同一原文可关联多条用户笔记。
- 删除前明确提示“只会删除这条老己笔记”，确认后只移除当前用户笔记，不影响同步内容、关联原文、本地划线或书籍；删除失败时保留该条笔记并允许重试。
- 当前书笔记区不是 PPT 素材勾选器，不显示“加入 PPT”；制作 PPT 统一从“读书 PPT”、书籍主按钮或对话意图进入。

**状态**：初次加载、无老己笔记、编辑中、保存中、保存失败、删除确认、删除中、删除失败、引用来源已失效、网络错误。

- 真正无笔记时说明“还没有老己笔记”，主动作是“新建书籍笔记”，次动作是“返回阅读”。
- 初次加载和网络错误不得短暂显示“还没有笔记”。

## PPT-01 对话式 PPT 需求

**目标**：承接书籍“制作 PPT”、书籍“读书 PPT”分区或普通对话中的 PPT 制作意图，在绑定当前书籍的老己对话中集中确认生成范围和必要要求，不要求逐条选择素材。

**桌面/手机结构**：

```text
已选择《原子习惯》 · 制作读书 PPT

老己：先确认内容范围和分享方式。
+-------------------------------------------+
| 内容范围：[整本书] [指定章节] [已有老己笔记] |
| 用途：读书分享                              |
| 分享对象：同事                              |
| 页数：精简 / 标准 / 详细                    |
|                 [确认并生成大纲]             |
+-------------------------------------------+
```

**集中确认**：

- 从普通对话触发时，用户原消息保留为本次任务要求；书籍确定后在当前消息流追加选书确认与助手提示，桌面同时展开右侧确认工作区，手机进入同一会话的全屏作品层。不得跳转到新的页面或创建新会话。
- 桌面 PPT 会话使用可折叠的连续工作台：沿用全局紧凑导航轨，会话列表作为“对话”的二级上下文栏按空间固定或作为临时抽屉，作品区可收起；收起后当前阶段任务卡是唯一恢复入口。一级模块切换不改变全局导航状态，工作台布局变化不改变会话身份、累计消息或草稿事实源。
- 确认工作区集中显示内容范围、用途、分享对象和页数，只保留可见文案“生成大纲”一个主操作；按钮的无障碍名称明确为“确认范围并生成大纲”。补充要求继续使用当前会话输入器，不在工作区重复增加大文本框。手机全屏范围作品层不重复显示书籍封面、书名和作者身份条，页头后直接进入内容范围；桌面工作台保留书籍身份条。
- 内容范围中，本地书提供整本书、指定章节、已有老己笔记；微信读书根据可用内容提供整本书、指定章节、已有老己笔记。指定范围按章节和内容类型筛选，不逐条勾选笔记。
- 微信读书只有在同步数据提供可靠章节元数据时才显示“选择章节”；没有章节元数据时隐藏该选项，并引导使用“我的笔记 + 老己笔记”。
- 书友观点默认不使用；用户在微信读书范围中明确选择“加入书友观点”后才纳入，并在大纲中保留来源。
- 用途提供读书分享、知识讲解、内部培训和个人复盘；分享对象提供同事、读书会、学生和其他；页数使用精简、标准和详细三档，并在界面中显示对应约 5、8、12 页。
- 书籍由入口预选，MVP 不允许添加第二本书。后续多书合并不属于本次范围。
- 用户可以在对话中补充要求；需求卡与消息共同写入同一份草稿。

**按钮与状态规则**：

- AI 未配置时，用户可先完成范围和需求；点击“生成大纲”后就地提示配置 AI，成功后返回同一专属会话并保留草稿。
- 微信读书所选章节没有可用同步内容时，阻止生成并提供“选择其他章节”和“改用全部笔记”；如果没有可靠章节元数据，则不显示章节选择，不把空范围交给模型。
- 本地书整本或章节解析失败、范围加载失败和 AI 生成失败都保留需求卡与当前范围，并提供重试。
- 状态包括：识别到 PPT 意图、待选择书籍、书籍歧义、范围选择中、需求待确认、AI 未配置、内容不足、加载失败、大纲生成中、大纲生成失败和重复提交阻止。此阶段不得显示“PPT 生成中”。

## PPT-02 可编辑大纲确认

**目标**：用户在生成 PPTX 前检查和修改页面结构、文案和来源。

大纲作品画布必须保留在当前 PPT 专属会话中。桌面会话与画布并列；手机从会话中的大纲作品卡展开全屏编辑层，返回后恢复原消息位置与输入草稿。

**桌面原型**：

```text
+----------------------+--------------------------------+-------------+
| 页面列表             | 当前页面                       | 来源        |
| 01 封面              | 标题 [让好习惯自然发生......] | 第一章      |
| 02 核心观点          | 要点                            | 我的划线 #3|
| >03 行动系统         | [1. 缩小行动.................] | 我的笔记 #2|
| 04 案例              | [2. 设计环境.................] |             |
| 05 总结              | 配图意图 [环境提示示意图....] |             |
| [+ 添加页面]         |                                |             |
+----------------------+--------------------------------+-------------+
| [返回] [重新生成大纲]           [确认大纲并继续]       |
+--------------------------------------------------------------------+
```

**手机原型**：手机使用单列连续文档。页标题、副标题、内容要点、来源和配图意图通过字号、字重、缩进、项目符号和留白表达；点击文字直接编辑，不切换到逐项填写表单。底部只保留“确认大纲并选择模板”主操作。

**可编辑能力**：

- 修改页标题、要点、正文和配图意图；也可在专属对话中要求老己重排、合并或改写。两种修改写入同一份大纲。
- 添加、删除和调整页面顺序。
- 查看每个观点的来源；书友观点显示作者和来源元信息。
- 返回进入位置时保留当前大纲草稿、范围和需求卡；从会话进入返回原消息位置，从书籍列表进入返回书籍“读书 PPT”。
- 重新生成大纲或任意人工修改都会使旧确认失效；已有人工修改时重新生成必须先确认覆盖当前生成前草稿，但不创建或展示大纲版本历史。
- 大纲编辑自动保存草稿，并显示保存中、已保存或保存失败；保存成功后离开页面不弹确认。
- 至少保留一个页面；只剩最后一页时禁用删除并说明原因。大纲为空或保存失败时不能确认继续。
- 保存失败后离开页面需要确认，用户可继续编辑、重试保存或放弃未保存修改。

**强制规则**：未点击“确认大纲并继续”不能进入最终 PPT 生成。

**状态**：大纲生成中、大纲生成失败、待确认、自动保存中、已保存、保存失败、来源失效、重新生成确认、页面数超出建议。

## PPT-03 模板、逐页生成与作品

**目标**：选择固定模板，启动最终逐页生成，预览、下载和重新打开本书的生成任务与完成作品。

模板选择与生成沿用大纲相同的会话壳层，不使用独立功能后台。用户确认模板并点击“开始生成 PPT”后才创建生成任务。用户离开生成页面后，会话任务卡与书籍“读书 PPT”卡继续显示同一页进度；再次打开时恢复已完成页、当前页、等待页和滚动位置。

**桌面原型**：

```text
+----------------------+----------------------------------------------+
| 模板                 | 预览                                         |
| [简洁商务 缩略预览]  | +------------------------------------------+ |
| [知识卡片 缩略预览]  | | 第 3 页                                  | |
| [图文叙事 缩略预览]  | | 标题、正文、配图                         | |
|                      | +------------------------------------------+ |
| 配图按大纲意图补充   | [纵向瀑布流：01 / 02 / 03 / ...]            |
|                      |                                              |
| [返回编辑大纲]       | [开始生成 PPT] / [下载 PPTX]                |
+----------------------+----------------------------------------------+
```

**手机原型**：模板选择使用真实 16:9 封面双列浏览，底部唯一主操作为“开始生成 PPT”。开始生成后进入全屏纵向瀑布流：已完成页显示真实页面，当前页显示骨架和“第 N 页生成中”，后续页显示标题与“等待生成”；不设置“上一页 / 下一页”主按钮。

模板比较栏只属于生成前草稿。点击“开始生成 PPT”后，桌面生成中、正在完成文件、失败和完成作品都移除该栏，作品区扩展为单列纵向瀑布流；顶栏按状态显示“正在生成 PPT”“正在完成文件”“生成失败”或“PPT 已完成”。完成作品保留“更换模板”入口，它从该作品的大纲快照创建新的生成前草稿，旧作品保持不变。

**MVP 模板**：

- 简洁商务：默认，适合内部分享和培训。
- 知识卡片：强调观点、引用和行动项。
- 图文叙事：强调章节脉络和配图。
- 模板卡必须提供真实页面密度的预览；不以渐变色块或抽象装饰代替版式预览。

**生成状态**：

```text
生成前草稿 -> 点击“开始生成 PPT” -> 生成中（第 N / 总页数） -> 正在完成文件 -> 完成作品
                                                 -> 失败 -> 从失败页继续 / 删除任务
```

- “生成中”只指确认模板并启动最终 PPT 页面生成后的状态；大纲生成、编辑大纲和选择模板都不计入。
- 生成中明确显示“正在生成第 N / 总页数页”，不承诺精确剩余时间；整张任务卡可进入实时瀑布流生成页面。
- 失败保留大纲、模板和已完成页，不要求重新选素材；书籍列表保留失败任务，提供简洁的“继续”和低频“删除”。
- 从完成作品编辑大纲、更换模板或重新生成时，先创建新的生成前草稿；再次点击“开始生成 PPT”后创建新的生成任务，成功后形成另一份独立作品，不覆盖旧作品，也不显示版本号。
- 本书“读书 PPT”分区只展示生成中任务、可恢复的失败任务和已完成作品。生成前草稿只从创作会话继续。列表作为作品索引，手机和桌面均使用单列横向记录，整张记录可进入任务或作品；完成作品不在列表重复提供下载，下载保留在作品页。
- 从会话进入作品层时返回原会话；从书籍列表进入时返回“读书 PPT”。列表和作品页不提供固定“返回会话”按钮。
- 删除会话不影响已经开始生成的任务或完成作品；删除完成作品只作用于所选作品。
- 本书没有生成任务或完成作品时显示“还没有读书 PPT”和“制作 PPT”；加载中或加载失败不得使用空作品文案。

## SET-03 设置与账户安全

**目标**：聚合个人资料、AI 与微信读书服务、登录邮箱、登录状态和账户删除。

**结构**：

```text
设置首页
+-- 个人资料
+   +-- 头像 / 昵称
+-- 已连接的服务
|   +-- AI 服务                 [状态] [管理]
|   +-- 微信读书                [状态] [管理]
+-- 账户与安全
    +-- 登录邮箱                [当前邮箱] [进入]
    +-- 修改密码 / 退出登录
    +-- 删除账户

```

**规则**：

- 删除账户是独立高风险操作，需密码确认并说明会删除账户数据和作品。
- 个人资料只包含头像与昵称；登录邮箱从“账户与安全”进入独立 `SET-05`，修改前需要两步验证。
- MVP 不提供本地书移除、回收站、恢复或永久删除；设置页不得为这些未来能力预留入口或说明。
- “微信读书”服务行的“管理”进入 `SET-02`；书架的“同步微信读书”在未连接或连接失效时也进入同一页面。

## SET-04 个人资料

**目标**：在独立设置详情页管理公开头像与昵称，不混入账户安全信息。

**规则**：

- 点击头像本身打开系统文件选择器，不提供额外“选择图片”按钮，也不常驻显示格式说明。仅接受 JPG、PNG 或 WebP，最大 2MB；不合规时在头像附近显示具体错误。
- 头像使用正式相机图标角标表达可编辑性；选择有效图片后独立保存并跨已登录页面同步，不依赖昵称提交。
- “恢复默认头像”是低强调文字操作，只恢复头像，不修改昵称、邮箱或其他资料。
- 昵称为 2–24 个字符。用户修改后点击“保存昵称”才提交；未修改或校验失败时按钮不可用，失焦不自动保存。
- 保存中禁止重复提交；成功显示“已保存”，失败保留当前输入并提供重试。
- 页面直接打开或刷新仍可完整使用；默认返回设置首页。从允许的业务来源进入时，返回原来源并保留上下文。

**状态**：初次加载、头像选择、头像保存中、头像格式/大小错误、头像保存失败、昵称未修改、昵称已修改、昵称校验失败、昵称保存中、昵称已保存、昵称保存失败。

## SET-05 登录邮箱

**目标**：在账户与安全下查看和修改登录邮箱；个人资料页不显示邮箱或邮箱验证组件。

**规则**：

- 页面先以只读方式显示当前登录邮箱和“修改邮箱”操作，不把邮箱直接做成可编辑资料字段。
- 修改必须完成两步验证：先验证当前邮箱，再填写并验证新邮箱。每步显示当前位置、发送验证码、重发状态、字段错误和返回/取消。
- 当前邮箱验证成功前不能进入新邮箱确认；新邮箱格式无效、验证码错误或已被占用时保留合法输入并说明可操作原因。
- 验证码发送与最终提交都防止重复操作；安全结果不泄露其他账户信息，不显示第三方原始错误码。
- 修改成功后刷新账户邮箱摘要并显示“登录邮箱已更新”；失败留在当前步骤，可重试或取消返回。

**状态**：初次加载、当前邮箱验证码发送中/已发送/失败、当前邮箱验证失败、新邮箱填写、新邮箱验证码发送中/已发送/失败、新邮箱验证失败、提交中、修改成功、修改失败。

### 重复操作规则

- 所有提交型按钮在处理中禁用，反馈切换不得造成主要操作区明显跳动。
- 重试复用原任务和用户输入，不创建不可区分的重复记录。
- 用户离开长任务页面后，任务继续显示在对应书籍的状态区域，并同步出现在 `APP-01` 最近任务中；任务完成、失败或被删除后两处状态保持一致。

## 7. 响应式规则

### 7.1 覆盖范围

- 桌面、平板和手机浏览器都必须完成核心流程；断点、导航承载、分栏数量和内容重排方式由 UI 设计规范与 Open Design 根据真实视口验证。
- 大屏应支持高效扫描和并行查看相关信息；小屏应优先当前任务，并让次级内容可发现、可切换、可返回。

### 7.2 共同行为

- 手机端不依赖悬停；图标按钮有可见标签或辅助说明。
- 触控目标满足可用性与可访问性要求；操作条和工具栏在状态切换时保持稳定。
- 书架在各视口都优先保证快速扫描、封面清晰和书名可识别；列数、卡片宽度、标题行数与间距由 Open Design 通过真实内容验证，不能放大低清封面填满空间。
- 小屏阅读时，目录、上下文笔记和正文不得互相遮挡；具体切换与承载方式由 Open Design 决定。
- 所有导航和浮层避开系统安全区，不遮挡当前任务；选中态清晰且不只依赖颜色。
- 微信读书原文条目激活后和本地阅读文本选中后，操作条贴近当前内容并自动上下避让；它不得成为脱离当前内容的常驻工具栏。
- PPT 大纲在小屏上必须支持查看、编辑、调整顺序、查看来源和确认；具体采用逐页、列表、面板或其他主流方式由 Open Design 决定。
- 书名、作者和进度等信息在各视口都可辨认，长文本不会覆盖其他信息；截断与换行方式由 Open Design 决定。
- 键盘弹出时，当前输入和主要提交按钮可滚动到可见区域。
- 同一任务一次只呈现一个主要浮层层级，避免弹窗、抽屉或面板相互嵌套。

## 9. UI 设计输入

### 9.1 视觉方向

- 已接受方向为“青瓷书斋”：清新、安静、有书卷气，以现代工作台为骨架，以克制的国风细节建立识别。
- 国风元素使用“己”字题签、活字印刷字模暗纹、青瓷色和阅读排版；不使用大面积水墨、仿古纸纹或无功能含义的装饰性分组标题。
- 书架以完整封面作为唯一卡片内容；书名和作者由封面自身承载，封面下不重复元信息。
- 书架与书籍详情不显示微信读书、本地导入或文件格式角标，也不提供来源筛选；来源关系由系统数据保留。
- 所有已登录主页面提供可发现但不抢占主任务的 AI 配置弱提示，显示未配置、当前供应商或凭证失效状态；点击进入 `SET-01` 并保留当前上下文，具体位置由 Open Design 决定。
- 阅读区优先保证文本宽度、行距和选区清晰度。
- AI 状态和配置提示保持轻量，不做大卡片或强制向导。
- 卡片仅用于书籍、笔记、作品等重复实体；页面区块不包装成多层卡片。

上述方向的色值、字体、封面尺寸、网格密度和组件状态以 `../ui/laoji-mvp-ui-design-spec.md` 为唯一事实源，本文不复制具体参数。

### 9.2 UI 需输出的页面状态

UI 设计稿至少覆盖：

- 16 个页面的桌面主状态和手机主状态；独立老己笔记页已取消，个人资料与登录邮箱分别使用独立详情页；
- 统一书架的空、正常、搜索无结果、同步中；
- 微信读书未连接、连接失效；
- AI 未配置和配置失败；
- EPUB 正文选区；
- PDF 跨页选区和不支持精准划线；
- 微信读书我的笔记/书友笔记多条列表、单条激活工具条，以及本地书已有划线激活工具条；
- 老己笔记编辑和书友观点选中；
- 对话新建与切换、对话式 PPT 范围选择、需求卡、大纲生成与编辑、最终 PPT 生成中、失败和完成；
- 账户级破坏性操作确认。
- 首次无任何数据、更新结果为空、无我的笔记、书友笔记获取失败、无老己笔记和无读书 PPT。

### 9.3 设计参考边界

微信读书和 Alice APP 只作为交互习惯和信息层级参考。外部参考图仅用于确认“激活一条原文后，在内容附近显示上下文工具条”的交互关系；不照搬其黑色工具条、字号、颜色或品牌视觉。本 PRD 与 UI 规范中的文字规则可以独立完成高保真设计。

## 12. 原型冻结规则

- UI 可以调整视觉层级、排版和组件表现，但不能改变页面职责、来源能力和已接受流程。
- UI 发现内容溢出或移动端不可用时，优先调整布局，不删除产品状态。
- 开发发现技术不可行时，先回到对应阶段 0 验证结论，不在实现中静默降级产品承诺。
- 新增功能必须先判断是否属于 MVP；不在范围内的内容进入后续版本清单，不直接塞进当前页面。
