# ADR-0008: 将来源内容与用户笔记分层保存

- 状态：已接受
- 日期：2026-07-31；2026-08-09 同步阅读器笔记入口的设计自由度
- 范围：阅读划线、微信读书同步、老己笔记、书友笔记、PPT 范围

## 背景

老己同时处理三种内容：微信读书同步的我的笔记、微信读书书友笔记、本地 EPUB/PDF 中的用户划线。它们的来源、可编辑性和归属不同，不能都存成一个可直接修改的文本字段。

用户还需要在来源内容上添加自己的思考和 PPT 备注，而这些内容不应回写微信读书或改变本地原始文件。

## 决策

笔记由两个逻辑层组成：

1. **来源内容层**：保存微信读书同步内容、本地书原文、来源类型、来源标识、作者、位置、同步时间和必要的引用信息；原始内容只读。
2. **老己笔记层**：保存用户的老己笔记正文和更新时间；内容私有且可编辑、可删除，可选保留来源引用和原文快照。用户不需要选择或管理书籍级、章节级、划线级分类；编辑只修改笔记正文，删除只移除当前用户笔记，不影响来源内容、本地划线或书籍记录。
3. 微信读书的我的笔记与书友笔记按独立来源项展示；用户激活某一条后可复制或创建引用型老己笔记。同一来源项允许关联多条老己笔记。
4. 本地书文本选区和已有划线使用同一引用机制；写笔记时保存选区/划线锚点与原文快照，不将操作按钮常驻在阅读器底部。
5. 本地书工作区的“老己笔记”直接平铺用户笔记，不提供“全部 / 划线 / 笔记”分类，也不显示“引用型 / 独立型”等类型名称；有关联原文时可在卡片内展示原文，没有关联原文时只显示笔记正文。阅读器内的上下文笔记入口只显示当前选区或当前位置相关内容，具体位置和承载方式由 UI 设计决定。
6. 本地划线是用户创建的阅读标记，不属于不可变的来源原文；用户可以取消划线。取消只移除阅读高亮，不删除关联的老己笔记，引用型笔记继续保留原文快照和位置。

## 来源行为

| 来源 | 原文/划线 | 用户补充 | PPT 使用 |
| --- | --- | --- | --- |
| 微信读书我的笔记 | 同步后只读 | 可添加和编辑老己笔记 | 通过 PPT 对话范围选择可用 |
| 本地 EPUB/PDF 划线 | 用户创建，可取消；本地原文只读 | 可添加、编辑和删除老己笔记 | 通过 PPT 对话范围选择可用 |
| 微信读书书友笔记 | 原文、作者、来源只读 | 不修改书友原文；可另建私有老己笔记 | 默认不可用，仅在 PPT 专属会话明确加入书友观点后作为带来源参考 |

所有用户补充都是老己私有内容，可由用户编辑或删除；这些操作不回写微信读书，不修改本地原始文件、原始划线或书籍记录。

## 笔记挂载层级

系统内部可保留书籍、章节和划线位置等关联元数据，用于回到原文、排序和 PPT 来源追溯；这些关联不作为用户可见的笔记分类或填写项。

没有全文阅读能力的微信读书同步书，也可以基于同步的我的笔记、书友笔记或书籍/章节信息添加老己笔记。

## 2026-08-09 界面归属补充

- 老己笔记没有跨书籍汇总或独立管理页面；每条笔记必须从当前书籍详情进入、编辑和删除。
- 本地书与微信读书都在当前书“老己笔记”内容区平铺用户新增笔记；来源和引用关系由系统保存，不要求用户分类管理。
- 对话首页不提供“最近笔记”总入口。需要继续处理笔记时，先进入对应书籍，再打开该书的“老己笔记”。
- 这一界面收敛不改变底层引用元数据，仍需保存书籍、章节、页码或划线锚点用于回到原文和 PPT 来源追溯。

## PPT 素材行为

- PPT 不维护逐条“加入 PPT”标记；制作时在专属对话中选择书籍范围、章节或老己笔记。
- 微信读书的书友观点默认排除，仅在专属对话中明确加入后使用。
- 进入 PPT 大纲时保留书籍、章节、引用原文、作者和来源信息，供页面引用和最终作品追溯。
- PPT 生成不得把书友内容渲染成用户原创观点。

## 示意

```text
来源内容（只读）
  原文 / 划线 / 来源 / 作者 / 位置
          |
          v
老己笔记（私有、可编辑、可删除）
  内容 / 引用信息
```

## 后果

### 正面

- 保护微信读书同步数据和本地原始文件不被误修改。
- 让 WeRead 和本地导入共享笔记、PPT 和引用能力，同时保留来源差异。
- 为后续来源追溯、内容搜索、引用和撤销提供清晰边界。

### 代价

- 笔记列表需要区分来源内容与老己笔记；PPT 对话范围需要保留来源引用。
- 数据模型需要保存位置锚点和来源引用，不能只存一段文本。
