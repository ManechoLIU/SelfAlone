# 老己移动设置导航系统设计规范

日期：2026-08-12  
状态：方案 A 已获批准，进入实施  
适用范围：`SET-01 AI 服务`、`SET-02 微信读书连接`、`SET-03 个人资料与账户安全` 的移动端承载；桌面端既有能力保持不变

## 1. 背景与结论

当前设置首页已经使用移动端分组列表，但三个下钻入口仍不一致：

- 个人资料被作为 `laoji-settings.html` 内部的固定定位面板，并嵌在桌面内容容器中；父级布局与整屏横向位移叠加后，可能只显示视口右侧内容。
- AI 服务和微信读书各自仍使用桌面 `card + form-grid` 结构，小屏只发生宽度压缩，没有形成移动端的导航、信息层级和操作节奏。
- 三个入口缺少统一页面协议。继续逐页覆盖 CSS 会让后续新增同步服务、模型供应商、隐私或通知设置时重复产生同类问题。

采用方案 A：建立可复用的“设置首页 → 独立设置详情页”移动导航系统。个人资料、AI 服务、微信读书均使用独立 URL 和同一详情页壳；业务表单、连接状态与危险操作作为详情页内部内容插槽，不再复制页面骨架。

### 1.1 方案取舍记录

| 方案 | 收益 | 代价 | 结论 |
| --- | --- | --- | --- |
| A. 独立详情页 + 共享设置壳 | 深链、刷新、返回和扩展边界清楚；移动/桌面共用业务表单 | 需要一次性拆出个人资料页面并建立共享契约 | 已批准 |
| B. 只修个人资料内部面板 | 改动最少 | AI、微信读书继续桌面压缩；下一入口继续复制补丁 | 不采用 |
| C. 所有设置塞进单页状态机 | 页面切换集中 | 单页职责过重，业务表单与 URL/返回状态耦合 | 不采用 |

方案 A 的最强反方意见是：当前只是静态原型，多一个独立 HTML 页面和共享契约会增加初期文件数量。仍选择 A，因为文件数量是显性且可管理的成本，而嵌套面板、重复媒体查询和返回状态耦合会持续放大，并直接导致当前的截断与桌面组件压缩问题。

## 2. 设计目标

1. 消除个人资料页面截断、横向溢出和父容器耦合。
2. 所有设置入口在手机上遵循同一套返回、标题、滚动、状态和安全区规则。
3. 让表单看起来是为触控操作设计的设置页面，而不是缩窄的桌面卡片。
4. 保留 AI、微信读书、个人资料、邮箱验证和账户安全的现有业务行为与恢复路径。
5. 为后续增加设置详情页提供稳定契约，新页面不需要重新设计移动壳。
6. 768px 及以上继续使用桌面侧栏与宽屏内容组织，不因移动重构而退化。

## 3. 非目标

- 不新增供应商、同步服务、账户能力或设置项。
- 不改变 AI Key 与微信读书 Key 相互独立的产品边界。
- 不把所有设置内容合并为一个巨型单页，也不复制业务表单维护两套状态。
- 不使用自绘线框占位图标；本轮返回、状态和危险操作只使用成熟图标体系或清晰文字。
- 不冻结具体像素、圆角或动效曲线为产品行为；这些属于实现可调整参数。

## 4. 信息架构

### 4.1 页面关系

```text
设置首页 laoji-settings.html
├── 个人资料 laoji-profile-settings.html
│   ├── 头像
│   ├── 昵称
│   └── 登录邮箱 → 邮箱验证流程
├── AI 服务 laoji-ai-setup.html
│   ├── 服务商
│   ├── 密钥
│   └── 未配置 / 验证中 / 已连接 / 失效 / 重试 / 断开
├── 微信读书 laoji-weread-setup.html
│   ├── 密钥
│   ├── 同步状态与最近同步
│   └── 未配置 / 验证中 / 已连接 / 失效 / 重试 / 清除
└── 账户与安全
    ├── 修改密码
    ├── 退出登录
    └── 删除账户
```

个人资料从设置首页内部浮层迁移为独立页面。这样页面尺寸、滚动和焦点不再依赖设置首页 DOM，深链、浏览器返回和未来路由迁移也更自然。

### 4.2 层级规则

- 设置首页是唯一聚合页，只展示身份摘要、服务状态和账户入口。
- 设置详情页一次只处理一个主题，不重复一级设置分组。
- 详情页在手机上隐藏全局底部导航，避免用户在未完成编辑时误切换一级模块；顶部返回始终回到真实来源。
- 详情页在桌面上继续显示全局侧栏，并保留“设置”选中态。
- 破坏性确认属于当前详情页的模态层或底部确认层，不再创建第三层普通设置页面。

## 5. 可扩展页面架构

### 5.1 共享详情页契约

每个独立设置详情页使用同一组语义标记：

```html
<body class="settings-detail-page" data-settings-page="profile">
  <div class="app-shell settings-detail-shell">
    <header class="settings-detail-header" data-settings-detail-header>…</header>
    <main class="settings-detail-main">
      <div class="settings-detail-content">…业务内容…</div>
    </main>
  </div>
</body>
```

共享壳只负责：

- 移动端完整视口宽度、自然纵向滚动和安全区；
- 返回入口、居中标题和可选状态槽；
- 统一内容列、表单行、就地反馈和底部主操作；
- 桌面侧栏、页头和内容宽度的兼容；
- 键盘弹出、焦点可见、减少动效和减少透明度偏好。

业务页面只负责：字段、文案、校验、业务状态和提交动作。共享壳不得读取或重写密钥、头像、邮箱等业务数据。

当前原型仍采用静态 HTML，因此每页保留最小、可访问的 header 语义标记；视觉布局、响应式、返回解析和状态槽行为由共享层提供。未来迁移到组件或路由框架时，可以直接把这段最小标记替换为共享组件，不改变页面业务接口。

### 5.2 页面登记规则

新增设置详情页时只需要登记以下元数据：

| 字段 | 作用 | 示例 |
| --- | --- | --- |
| `data-settings-page` | 稳定页面标识 | `profile` |
| 页面标题 | 顶部导航标题 | `个人资料` |
| 默认返回目标 | 无来源参数时的安全回退 | `laoji-settings.html` |
| 状态槽 | 可选，显示连接或保存状态 | `已连接` |
| 内容类型 | `profile`、`connection`、`account` 或未来类型 | `connection` |

视觉和导航不依据页面文件名做大量特例。除确有业务差异外，新页面应通过共享类、数据属性和内容类型复用规则。

### 5.3 CSS 边界

- 共享设置详情规则集中在 `assets/laoji.css` 的明确设置作用域中，不能继续散落为每个 HTML 页面的重复媒体查询。
- 页面级 CSS 只描述业务特有内容，例如头像预览或连接历史，不重定义详情页宽度、页头和底部操作。
- 移动规则必须以 `.settings-detail-page` 或 `[data-settings-page]` 为根，避免影响阅读器、PPT、认证页和普通卡片。
- 所有内容容器使用 `min-width: 0`，字段和按钮使用 `max-width: 100%`，长邮箱、错误文案和供应商名称允许换行。
- 不使用 `transform: translateX(100%)` 把详情页藏在设置首页父容器内；独立页面本身就是导航目标。

### 5.4 JavaScript 边界

- 共享导航初始化只负责解析安全返回目标、设置返回链接和处理页面级焦点，不接管业务表单。
- 现有头像、昵称、邮箱、连接验证、撤销和重试逻辑继续按业务模块初始化。
- 返回参数继续使用允许列表内的相对 HTML 文件名。非法、跨域或路径穿越目标一律回退到 `laoji-settings.html`。
- 设置详情页不得通过复制表单实现桌面/移动两套状态；同一表单在不同断点下重新排版。
- 后续若迁移到前端路由框架，`data-settings-page`、标题、返回目标和内容插槽可直接映射为路由元数据，不依赖当前 DOM 嵌套。

## 6. 移动端页面设计

### 6.1 共享页面壳

- 顶部是轻量、粘性的次级导航栏：左侧返回，中央标题，右侧只放有价值的状态或提交结果。
- 页面内容从顶部栏下方自然滚动，不能出现横向滚动，也不能被固定底栏遮挡。
- 普通内容使用雾白背景与青瓷分隔；输入区域以分组行和留白建立层级，不使用卡片套卡片。
- 主要触控目标不小于 44px。正文与帮助文本保持可读行高，用户增大系统字号后仍可换行。
- 输入法弹出时，当前字段和错误提示保持可见；底部主操作不能盖住字段。
- 详情页不显示“对话 / 读书 / 设置”底部一级导航；返回设置首页后恢复一级导航。

### 6.2 个人资料

- 顶部标题为“个人资料”，返回文案为“设置”。
- 页面只管理公开资料：头像与昵称。登录邮箱不属于个人资料，迁移至“账户与安全”。
- 头像本身是上传入口：点击头像打开系统文件选择器；使用正式相机图标角标表达可编辑性，不显示“选择图片”按钮或格式说明。文件不合规时才在头像附近显示具体错误。
- “恢复默认头像”保留为低强调文字操作，不与上传入口争夺主次。
- 昵称使用原生单行设置字段与显式“保存昵称”按钮；只有昵称发生变化时按钮可用，提交时校验 2–24 个字符，并显示“正在保存 / 已保存 / 保存失败”。失焦不自动保存。
- 页面采用自然文档流，不使用固定定位的整页内部面板，从根源上消除当前截断。

### 6.3 AI 服务

- 顶部标题为“AI 服务”，状态槽显示“未配置 / 已连接 / 需重新连接”。
- 未配置态先说明用途与隐私边界，再显示服务商和密钥字段；主动作是“连接 AI 服务”。
- 服务商选择使用适合少量选项的列表或选择控件，不能把桌面下拉框和多个按钮横向挤压。
- 已连接态优先显示当前供应商和连接结果；“更换密钥”是普通操作，“断开连接”进入危险确认。
- 验证中锁定重复提交但保留输入；失败在字段或状态区给出原因和重试，不用短暂 toast 代替错误。

### 6.4 微信读书

- 顶部标题为“微信读书”，状态槽显示连接状态。
- 未配置态包括用途说明、密钥字段和“连接微信读书”主动作。
- 已连接态显示最近同步、连接身份或可验证的同步摘要；提供重新同步、更换密钥和清除凭证。
- 同步失败、部分成功和凭证失效使用稳定状态区，保留已有书架快照并提供对应恢复动作。
- 密钥管理与同步操作分组表达，不能因为都属于微信读书而堆进同一张大卡片。

### 6.5 账户与危险操作

- “登录邮箱”位于设置首页的“账户与安全”分组，摘要显示当前邮箱，点击进入独立 `account-email` 设置详情页。
- 登录邮箱详情页使用共享设置详情壳，展示当前邮箱并承载两步验证任务；个人资料页和资料表单不包含邮箱入口或邮箱验证 DOM。
- 修改密码属于普通安全任务，使用独立任务步骤或跳转到既有密码恢复流程。
- 退出登录使用轻量确认，确认后进入登录页。
- 删除账户保持最高危险等级，必须输入当前密码；确认按钮在条件不满足时不可用。
- 手机确认层使用底部确认层或适配移动端的模态内容，操作按钮纵向排布并避开安全区；桌面对话框可保持现有承载。

## 7. 导航与返回上下文

### 7.1 默认进入

- 从设置首页进入详情页，返回目标为 `laoji-settings.html`。
- 直接打开或刷新详情页时仍能正常呈现，返回目标回退到设置首页。
- 浏览器返回与顶部返回在常规进入路径中指向同一来源，不制造两套层级。

### 7.2 从业务流程进入

AI 服务和微信读书可能从 PPT、书架或同步入口进入。详情页通过安全的 `?return=<file.html>` 保留来源：

- 连接成功后返回来源并恢复原任务上下文。
- 取消配置返回来源，不清除原输入、范围或阅读位置。
- 验证失败留在详情页，用户可重试或主动返回。
- 来源参数只接受允许列表内的本地 HTML 文件名；其他值回退设置首页。

## 8. 状态模型

连接型详情页共享状态名称，但业务模块各自拥有状态数据：

| 状态 | 页面表现 | 可用动作 |
| --- | --- | --- |
| `unconfigured` | 说明 + 配置字段 | 连接 |
| `validating` | 保留字段，稳定进度反馈 | 禁止重复提交 |
| `connected` | 当前服务与有效状态 | 更换、同步或断开 |
| `invalid` | 明确失效原因 | 重新连接 |
| `partial` | 保留成功内容与失败摘要 | 重试失败部分 |
| `error` | 就地错误，不丢输入 | 重试或返回 |
| `revoking` | 保留当前信息，防止重复撤销 | 等待 |

个人资料昵称共享保存状态：`idle / dirty / saving / saved / error`。头像选择成功后独立保存，不依赖昵称按钮；这些状态用于按钮可用性、文案、可访问性和测试，不要求所有页面使用同一种视觉组件。

## 9. 动效与空间连续性

- 独立页面导航优先使用浏览器/应用路由带来的空间关系，不再用嵌套面板伪造整页导航。
- 若实现移动转场，进入与返回必须沿同一路径，时间短、可打断；不为普通设置切换添加弹跳。
- `prefers-reduced-motion: reduce` 下取消位移，只保留即时状态切换或轻微淡化。
- 粘性顶部栏使用克制的半透明材质；`prefers-reduced-transparency: reduce` 下改为实色。
- 触摸按下立即提供颜色或轻微缩放反馈，提交结果通过状态文字同步表达。

## 10. 可访问性与响应式验收

- 360px、390px、430px 宽度下无横向溢出、裁切或只显示半屏。
- 页面在 200% 文本缩放、长邮箱和长错误文案下仍能阅读和操作。
- 顶部返回、表单字段、显示/隐藏密钥、主操作和危险操作均可键盘聚焦并有可见焦点。
- 状态不只依赖颜色；验证、保存和错误区域使用适当的 `aria-live`。
- 打开确认层后焦点进入确认层，关闭后回到触发器；`Escape` 只关闭当前层级。
- 手机底部安全区、顶部安全区和键盘高度不得遮挡内容或主操作。
- 768px、1024px 与桌面宽度下不出现移动返回栏和重复标题；桌面业务功能与返回上下文保持可用。

## 11. 扩展规则

以后新增“通知”“隐私”“模型偏好”“导出”“其他阅读服务”等设置时，先判断内容类型：

1. 简单开关或状态行留在设置首页分组中，不创建空洞详情页。
2. 有说明、字段、验证、异步状态或危险操作的任务，创建独立详情页并使用共享壳。
3. 第三方连接复用连接状态模型，但凭证、权限和恢复逻辑保持模块隔离。
4. 一个详情页只处理一个清晰主题；不得因为共享壳存在就把无关设置塞在一起。
5. 新页面必须同时提供默认返回、直接访问、错误恢复、键盘和移动安全区验收。

## 12. 实施边界与文档影响

实施预计涉及：

- 新建 `prototype/laoji-profile-settings.html`；
- 重组 `prototype/laoji-settings.html`、`prototype/laoji-ai-setup.html`、`prototype/laoji-weread-setup.html`；
- 在 `prototype/assets/laoji.css` 增加共享设置详情页作用域；
- 在 `prototype/assets/laoji.js` 增加安全返回和共享详情页初始化，保留现有业务初始化；
- 新建移动设置详情系统回归测试，并更新个人资料/连接现有测试；
- 将获批体验边界同步到 `docs/ui/laoji-mvp-ui-design-spec.md`。PRD 的页面能力与状态没有变化，实施前只需核对页面映射，不新增产品能力。
- 更新 `prototype/README.md` 中的页面文件映射；对 PRD、ADR、架构、词汇表和项目 README 做影响扫描，无行为变化的文件明确记录为无需修改。

## 13. 验收标准

1. 设置首页进入个人资料后完整占满手机视口，左右内容均可见，滚动到底不被导航遮挡。
2. 个人资料、AI 服务、微信读书具有一致的移动返回栏、标题层级、内容宽度和安全区处理。
3. 三页不再使用桌面卡片套表单的移动缩窄形态；头像、字段、状态和操作按移动任务自然分组。
4. AI 与微信读书现有连接、验证、失败、重试、撤销及返回上下文行为全部保留。
