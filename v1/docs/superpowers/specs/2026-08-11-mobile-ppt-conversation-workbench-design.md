# 老己移动端 PPT 对话工作台设计规范

状态：已确认  
日期：2026-08-11  
范围：`prototype/laoji-ppt-materials.html`、`prototype/laoji-ppt-outline.html`、`prototype/laoji-ppt-preview.html` 及其共享移动端样式与交互

> 状态补充：PPT 生命周期、文档式大纲、模板启动生成和书籍任务列表规则已被 `2026-08-12-ppt-workbench-and-book-ppt-lifecycle-design.md` 替代。本文仅保留移动全屏作品层、返回位置恢复和基础响应式约束。

## 1. 背景与目标

现有移动端 PPT 制作流程沿用了桌面双栏结构：对话与作品画布通过固定定位切换，模板区、顶部操作和预览区仍按桌面横排。这导致 360–430px 宽度下出现横向溢出、操作含义不清、卡片层层嵌套和组件堆砌感。

本次设计以 `open-design-ui-reference/laoji-ppt-desktop-mobile.png` 的 Image 2 参考方向为视觉基准，并以 `image-10.png` 暴露的真实溢出问题为修复证据。目标是让移动端 PPT 制作呈现为一条连贯的对话任务流，同时保留完整的作品编辑能力。

## 2. 已锁定约束

- 不增加新功能、步骤、数据或生成能力。
- 保留现有内容选择、大纲编辑、模板选择、逐页预览、生成、失败重试和下载流程。
- 对话是主界面；大纲与预览使用全屏第二层工作台。
- 视觉向 Image 2 参考图靠近，但不得照搬其中不适合真机的桌面式横排。
- 360、390、430px 宽度不得产生页面级横向滚动。
- 所有可点击目标至少 44px，键盘焦点清晰，减少动态偏好继续生效。
- 不使用手绘 CSS 占位图标；无必要的操作优先使用明确文字标签。

## 3. 方案选择

### 方案 A：对话主流程 + 全屏作品工作台（采用）

聊天中只呈现作品摘要和进入入口；点击后进入覆盖全屏的移动工作台。工作台拥有自己的标题栏、内容滚动区和底部操作栏。

优势：保留对话式产品特色，为复杂编辑提供完整宽度，状态边界清楚。  
代价：需要在对话与作品之间切换，但返回路径始终可见。

### 方案 B：作品直接嵌入聊天（不采用）

优势：上下文连续。  
问题：大纲表单、模板和逐页预览空间不足，会形成更严重的嵌套卡片与长页面。

### 方案 C：独立分步向导（不采用）

优势：步骤明确、实现稳定。  
问题：削弱“在对话中制作 PPT”的核心体验，并改变现有交互心智。

## 4. 视觉系统

### 背景

- 页面继续使用现有青瓷灰绿 `--bg`。
- 对话消息与作品编辑面使用 `--surface` 和白色画布区分层级。
- 分层依靠留白、细边界和少量阴影，不叠加多层圆角卡片。

### 字体

- 界面、按钮和表单使用现有无衬线 `--ui`。
- PPT 页面标题和作品预览使用现有阅读衬线 `--reading`，强化“内容作品”属性。
- 状态、页码和版本信息使用 `--data`，避免与正文争夺层级。

### 布局原则

- 主内容宽度始终为 `100%`，子项使用 `min-width: 0`。
- 手机内边距为 16px；紧凑区域可使用 12px，但不得贴边。
- 同一视口只出现一个实心主操作。
- 模板、页面列表等横向集合允许局部滚动，但不得推动页面整体变宽。

### 标志性元素

作品工作台采用“青瓷框中的白纸”作为唯一视觉特征：编辑内容保持安静，PPT 预览像一张置于青瓷工作台上的纸面。其余区域不添加额外装饰。

## 5. 信息架构与流程

```text
PPT 专属对话
  ├─ 内容范围与要求
  ├─ 大纲作品摘要 ──> 全屏大纲工作台
  │                    └─ 确认并预览
  └─ PPT 作品摘要 ───> 全屏预览工作台
                       ├─ 选择模板
                       ├─ 逐页预览
                       └─ 生成 / 重试 / 下载
```

`data-mobile-view="chat|artifact"` 继续作为视图状态来源，不新建路由或数据模型。进入工作台时锁定背景滚动；返回时恢复原来的对话位置。

## 6. 页面设计

### 6.1 内容范围页

- 手机端隐藏桌面会话列表，只保留当前 PPT 专属对话。
- 绑定书籍缩成单行摘要：封面、书名、内容来源和“更换书籍”文字操作。
- 内容范围选项保持可点击，但从多枚独立组件整理成一个连续选择区。
- 输入框固定在安全区上方，发送按钮保持唯一主操作。

### 6.2 大纲工作台

- 顶栏：返回对话、标题“编辑大纲”、保存状态；不显示多枚并排图标按钮。
- 页面列表改为横向滚动标签，显示页码和短标题；选中项有明确底色与边界。
- 当前页编辑表单单列排列：标题、要点与正文、配图意图。
- 上一页、下一页属于编辑区内的次级导航。
- 底部固定操作栏只保留一个实心“确认并预览”，其他操作为文字或描边按钮。

### 6.3 预览与生成工作台

- 顶栏：返回对话、标题“预览与生成”、生成状态。
- “自动生成配图”单独占一行，不与章节标题或模板标题横向争抢空间。
- 模板以横向滚动卡片呈现，每张卡片宽度约为视口的 76–82%，使用滚动吸附；卡片内部不再嵌套额外面板。
- PPT 页面预览始终保持 16:9，并使用 `width: 100%`、`aspect-ratio: 16 / 9` 和 `overflow: hidden`。
- 页码与上一页/下一页位于预览下方的紧凑工具行。
- 底部固定操作栏包含次级“修改大纲”和唯一主操作“生成 PPT”。

## 7. 状态与反馈

- `ready`：显示模板、预览和生成操作。
- `generating`：保留当前模板与预览，底部主操作替换为进度状态；允许返回对话并继续生成。
- `error`：明确说明已保留大纲、模板和完成页面；主操作为“重试未完成部分”。
- `complete`：主操作为“下载 PPTX”，返回修改大纲为次级操作。
- 状态切换不得改变工作台宽度或造成内容跳出视口。

## 8. 动效

- 对话进入作品工作台：220ms 横向推入，使用标准缓动。
- 返回对话：相同路径反向退出，支持中途响应点击。
- 模板选中只改变边界、背景与轻微位移，不缩放整个卡片。
- `prefers-reduced-motion: reduce` 时取消位移动画，直接切换可见性。

## 9. 响应式与完整性要求

- 在 360、390、430、600、768px 检查无页面级横向滚动。
- `.ppt-artifact-canvas`、`.artifact-topbar`、`.section-head`、`.template-list`、`.preview-stage` 和底部操作栏都必须设置可收缩宽度。
- 顶栏标题允许截断，但返回和主操作不得被挤出视口。
- 键盘弹出时输入区仍保持可见；工作台内容可以独立纵向滚动。
- 手机底部导航在作品工作台打开时隐藏，返回对话后恢复。

## 10. 验收标准

1. 现有 PPT 制作功能与页面顺序保持不变。
2. `image-10.png` 中模板标题、自动配图控件和页面预览右侧被裁切的问题消失。
3. 三个 PPT 页面在 360、390、430px 均无页面级横向滚动。
4. 大纲和预览均可从对话进入并明确返回。
5. 每个视口最多一个实心主操作。
6. 模板选择、页面切换、生成、失败重试和下载状态仍可操作。
7. 桌面端双栏布局不因移动端重构而退化。
