# 老己移动端设置首页原生化设计规范

状态：已被 `2026-08-12-mobile-settings-navigation-system-design.md` 替代  
日期：2026-08-12  
范围：`prototype/laoji-settings.html`、设置页专属移动样式与移动视图切换

> 历史说明：本规范记录了第一阶段的设置首页原生化方案。个人资料内嵌全屏层已在后续获批方案中升级为独立详情页，实施与验收以替代规范为准。

## 1. 目标

当前设置页在手机上只是把桌面的头像编辑器、表单、服务卡片和账户操作压成单列，首屏信息密度失衡，页面像桌面组件纵向堆叠。本次改造建立真正的移动信息架构：设置首页用于浏览状态和进入任务，个人资料编辑进入独立全屏层。

所有现有功能必须保留：头像上传与恢复默认、昵称自动保存、登录邮箱两步验证、AI 服务与微信读书连接入口、修改密码、退出登录和永久删除账户。

## 2. 方案比较

### A. 摘要首页 + 全屏个人资料层（采用）

首页只显示账户摘要、连接服务和账户安全。点击账户摘要进入全屏个人资料编辑层。

- 优点：符合手机“浏览设置 → 进入具体任务”的心智；首屏清楚；复杂表单拥有完整宽度。
- 代价：个人资料编辑多一步进入，但返回路径始终可见。

### B. 单页紧凑长列表（不采用）

把现有表单压缩后继续放在首页。实现简单，但头像上传、昵称、邮箱与服务状态仍争夺同一滚动页面，不能解决组件堆砌问题。

### C. 当前页折叠分组（不采用）

使用手风琴展开资料与服务。减少首屏高度，但展开后页面位置跳动，邮箱验证和危险操作的层级不够稳定。

## 3. 移动信息架构

```text
设置首页
├─ 账户摘要：头像 / 昵称 / 登录邮箱 ──> 全屏个人资料层
├─ 连接服务
│  ├─ AI 服务 ──> 现有独立配置页
│  └─ 微信读书 ──> 现有独立配置页
├─ 账户与安全
│  ├─ 修改密码
│  └─ 退出登录
└─ 危险操作
   └─ 删除账户 ──> 现有确认对话框
```

桌面端继续显示现有资料编辑卡和分组列表，不改变宽屏布局。

## 4. 视觉与布局

- 背景继续使用老己现有青瓷灰绿 `--bg`；内容行使用白色与浅表面色，不引入新的全局颜色。
- 移动顶栏高度 64px，标题居中或按现有产品左对齐规则稳定展示，不出现桌面副标题。
- 页面左右内边距 16px；组间距 24px；列表行最小高度 56px；所有触控目标至少 44px。
- 账户摘要是首页唯一强调区域：56px 圆形头像、昵称、登录邮箱和明确的进入箭头。它是身份入口，不设计成营销卡片。
- 设置分组采用原生列表语法：组标题、连续行、状态文字、箭头。连接状态使用文字，不使用装饰性图标或线框占位符。
- “删除账户”与普通账户操作视觉分离，使用危险色文字和独立边界；不使用大面积红色背景。
- 全屏个人资料层使用白纸式内容面：固定顶部返回栏、头像编辑区、昵称与邮箱分区。避免卡片套卡片。

## 5. 交互

- 设置首页根节点以 `data-mobile-settings-view="home|profile"` 作为唯一移动视图状态。
- 点击账户摘要进入个人资料层；返回按钮和 `Escape` 返回首页。
- 打开个人资料层时锁定背景滚动；返回时恢复首页原滚动位置。
- 昵称仍在失焦时自动保存；头像上传、格式/大小校验和恢复默认逻辑不变。
- 修改邮箱继续使用现有两步验证对话框；成功后首页摘要和资料层邮箱同步更新。
- AI 服务、微信读书、修改密码、退出和删除账户继续沿用现有目标与确认流程。

## 6. 响应式与可访问性

- 仅在 `max-width: 767px` 启用移动首页与全屏资料层；768px 及以上保持当前桌面结构。
- 360、390、430px 宽度不得产生页面级横向滚动。
- 全屏层标题可截断，但返回按钮不得被挤出视口。
- 打开入口维护 `aria-expanded`；全屏层使用明确 `aria-label`；返回后焦点回到账户摘要入口。
- `prefers-reduced-motion: reduce` 下取消全屏层位移动画。

## 7. 验收标准

1. 手机设置首页不直接显示头像上传按钮、昵称输入框或登录邮箱修改按钮。
2. 账户摘要能进入全屏个人资料层，并能通过返回按钮和 `Escape` 退出。
3. 首页只显示状态与入口，个人资料层只承载资料编辑任务。
4. 删除账户与普通账户操作视觉分离。
5. 所有既有设置功能和桌面设置布局保持可用。
6. 360、390、430px 无页面级横向滚动，触控目标不小于 44px。
7. 设置、导航、链接与全量原型回归测试通过。
